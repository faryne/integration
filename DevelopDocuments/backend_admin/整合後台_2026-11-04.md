# 整合後台（faryne.dev/backend_admin）規格

- 狀態：已實作（2026-11-04），branch 已併入 main、未 push；前端部署後生效，後端只刪了重複路由
- Branch：`feat/backend-admin`
- Mockup：[`mockup/index.html`](mockup/index.html)

## 目標

把散在各網域的管理介面集中到 `faryne.dev/backend_admin`，同一個入口登入、同一套版面操作，不用再切網域。

## 範圍

| 收進來 | 現在的位置 | 後端 API（不變） |
|---|---|---|
| galgame 管理（頻道／影片／待審頻道／待審影片／影片關鍵字） | `galgame.tv/admin`、`faryne.dev/galgame/admin` | `/admin/galgame/*` |
| AV 女優管理（上稿審核／女優主題） | `faryne.dev/av/actress/admin/*` | `/admin/av/*` |

**不收進來**
- **SteamLoom 檢舉後台**：SteamLoom 使用獨立 Firebase 專案與平台 RBAC（`service/storyteller/admin_auth.go`），跟主站 `users.is_admin` 是兩套刻意脫鉤的帳號系統。側欄只放外連到 steamloom.works 的後台。
- API 網域整合（`/api-integration` → 各網域 `/api`）是另一案，這次不動。

## 權限與登入

- 一律使用主站登入（`BrandMain`，Firebase `faryne-integration`），判斷 `users.is_admin`。
- **真正的防線在後端**：`/admin/galgame/*` 與 `/admin/av/*` 都掛了 `authsession.New(BrandMain)`，service 層也都會呼叫 `authService.RequireAdmin`（`service/eroge/catalog.go`、`service/av/*`）。前端閘門只負責 UX。
- 首頁 `/backend_admin` 依登入狀態顯示：
  - **未登入**：全頁登入卡（Google 登入）。
  - **已登入但不是管理者**：403，附「切換帳號」（登出後重新登入），避免登錯帳號後卡住。
  - **管理者**：總覽。
- 子頁未登入時也顯示同一張登入卡，登入成功後留在原網址。
- 防搜尋引擎收錄：`/backend_admin` 不進 `prerender.mjs`、sitemap 和 `navigation.ts` 的公開導覽；頁面加 `<meta name="robots" content="noindex,nofollow">`，`robots.txt` 加 `Disallow: /backend_admin`。

| 路徑 | 內容 |
|---|---|
| `/backend_admin` | 登入卡／總覽 |
| `/backend_admin/galgame/brands?tab=all\|paused\|deleted` | 頻道管理 |
| `/backend_admin/galgame/videos?tab=all\|deleted` | 影片管理 |
| `/backend_admin/galgame/brand-submissions` | 待審頻道 |
| `/backend_admin/galgame/video-submissions` | 待審影片 |
| `/backend_admin/galgame/title-keywords` | 影片關鍵字 |

子分頁（全部／暫停／已刪除）改用 query string `tab`，重新整理或分享網址時可以停在同一個分頁。原本是 component state。

## 版面

獨立的 `BackendAdminLayout`，**不套主站 SiteLayout**（後台不需要公開站的頁首、頁尾與導覽）：

- **頂部列**：「faryne.dev 後台」（連回後台首頁）、右側帳號選單（回到網站／登出）。
- **左側導覽**：依模組分組，組內是功能頁；待審項目顯示紅色數字。最後一組「其他後台」放 SteamLoom 外連（↗）。
- **內容區上方放麵包屑**：`後台 / Galgame / 頻道管理`，動態頁沿用 `useBreadcrumbTail`。
- **手機（< md）**：側欄收進漢堡選單的 Drawer。
- **色彩模式**：沿用主站 `faryne-color-mode`。

**總覽頁**：每個模組一張卡，列出待處理數字（AV 待審上稿、galgame 待審頻道、待審影片），點了進對應頁。不加說明文字。

待處理數字**不新增 API**：AV 沿用 `usePendingActressSubmissionCount`；galgame 用既有的 `useAdminGalgameBrands("pending")`、`useAdminGalgameVideoSubmissions("pending")` 取 `total`。

## 文案與 i18n

- 後台外框（頂部列、側欄、總覽、登入卡）只有站長使用，比照現有 AV 後台寫死 zh-TW。
- galgame 管理頁原本就用 `galgame.admin.*` i18n key，屬於同一個功能，搬過來繼續沿用，不改 key。

## 舊入口處理

| 舊網址 | 處理 |
|---|---|
| `faryne.dev/av/actress/admin/*` | 前端 redirect 到 `/backend_admin/av/*`（保留 id） |
| `faryne.dev/galgame/admin` | redirect 到 `/backend_admin/galgame/brands` |
| `galgame.tv/admin` | `window.location.replace("https://faryne.dev/backend_admin/galgame/brands")` |
| 帳號選單的「AV 女優管理後台」、galgame 選單的「管理」 | 合併成一個「後台管理」，`adminOnly`；在 galgame.tv 點擊時開外部連結 |

galgame.tv 和 faryne.dev 的登入狀態存在各自 origin 的 localStorage，從 galgame.tv 跳過來第一次要重新登入一次，屬預期行為。

## User Stories

1. 站長打開 `faryne.dev/backend_admin`，看到登入卡，用 Google 登入後進總覽，一眼看到 AV 有 3 筆待審、galgame 有 2 個待審頻道。
2. 站長在側欄點「Galgame / 待審頻道」，核准一個頻道後，側欄的待審數字跟著減 1。
3. 站長用手機打開後台，點漢堡選單切到「女優上稿審核」，審完一筆回到列表。
4. 站長點了舊書籤 `galgame.tv/admin`，被導到 `faryne.dev/backend_admin/galgame/brands`，登入一次後正常操作。
5. 路人猜到 `/backend_admin`，看到登入卡；用自己的 Google 帳號登入後只看到 403，任何 `/admin/*` API 也一律被後端拒絕。

## 常見失敗與應對

| 情境 | 應對 |
|---|---|
| 操作途中 session 過期，API 回 401 | 沿用 `apis/auth/httpInterceptors.ts`：先用 Firebase ID token 靜默換新 key 再重送；換不到時 `clearSession()`，畫面回到登入卡並跳 SNACK，重新登入後留在原頁 |
| API 失敗（4xx／5xx） | SNACK 顯示錯誤，列表保持原狀，不做樂觀更新 |
| 刪除頻道／影片／關鍵字、刪除女優主題 | 沿用既有的 confirm 對話框 |
| 待審數字的 API 失敗 | badge 不顯示，不擋其他功能 |
| 登錯帳號（非管理者） | 403 頁的「切換帳號」登出後重新登入 |
| 直接打不存在的子路由 | 後台內 404，側欄仍在，可以點回去 |
