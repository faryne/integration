# Storyteller AI 助理 No-Drawer 提案（實作收斂版）

- 日期：2026-09-11
- 目前實作 branch：`codex/storyteller-ai-inline-anchor`
- 狀態：P0 inline anchor bug 已修復；另完成 AI composer 鍵盤事件隔離與 `/` 指令選單整理，等待 Claude 再次 review

## Review baseline

這一輪已經把「完全拋棄 Drawer」收斂成可實際操作的第一版：

- AI 助理直接插在故事／設定集編輯區的目標段落後方。
- 畫面同時只存在一個 AI 工作區，不會每個段落各長出一個 Agent thread。
- AI UI 透過 ProseMirror decoration + React portal 呈現，不寫進文件內容、Markdown 或 undo history。
- 選字浮動選單、右鍵選單與 `/` 選單都只提供一個「問 AI」入口。
- 對話、單輪 skill、提案與既有歷史能力仍沿用 `StorytellerAgenticPanel`，這輪沒有重做後端資料模型。
- AI composer 已改為接近 ChatGPT 的單一輸入面，常用操作與設定收進底部 icon/control 群組。
- `/`、右鍵與選字三種入口依操作情境採不同版型，但共用同一套 command、icon、名稱與功能順序。

本目錄的 `index.html` 是最初用來探索 No-Drawer 方向的互動概念稿，仍包含多 thread、thread pin、Review mode 等未實作構想。**本輪 code review 請以這份文件的「目前定案行為」與實際 branch 為準，不以 mockup HTML 作為逐像素驗收標準。**

## 需求演進紀錄

### 1. 完全放棄 Drawer

最初方向是不再用右側 Drawer 或 mobile bottom sheet 裝完整聊天室，而是讓 AI 回到編輯上下文中。

實作後採用：

- AI 工作區錨定在目前段落後方。
- 工作區仍保留完整對話與 composer，不採用最初 mockup 的「送出後 command bar 立即消失」。
- 工作區的展開不改變文章欄寬，避免文章重新換行。

### 2. 不在編輯區建立大量 thread

本輪沒有實作「每個 anchor 一個獨立 inline thread」。目前規則是：

- 整份文件同時只展開一個 AI 工作區。
- 再次從另一段觸發「問 AI」時，移動同一個工作區到新 anchor。
- 對話歷史仍是目前故事／設定集既有的 chat history，不因段落建立新的 thread 容器。
- 不建立 gutter pin、thread badge 或 thread navigator。

這個決定避免長篇文件被大量 AI 卡片撐高，也控制本輪不必修改 chat schema。

### 3. `/` 選單只保留「問 AI」

既有 slash command menu 增加／保留單一 AI command：

```text
✦ 問 AI
```

- 有 selection 時使用選取文字。
- 只有 caret 時使用目前 paragraph／block。
- 不把 `/ai` 寫進故事內容。
- `/rewrite`、`/expand` 等 skill 指令仍可直接在 AI composer 輸入，但不在 editor slash menu 展開多個 AI action。

### 4. 選字與右鍵選單只留「問 AI」

原本分散的 `改寫`、`擴寫`、`翻譯` 等 AI action 已統一成「問 AI」。

- BubbleMenu：只新增一顆「問 AI」按鈕。
- Context menu：只保留「問 AI」。
- 具體的改寫／擴寫／縮短／調整語氣移到 composer 底部 quick action icons。

### 5. AI 工作區必須真的出現在編輯內容中

第一版實作曾把 AI panel 放在編輯器下方，看起來仍像另一個固定區塊，與 mockup 的「錨定原文」差距太大。

修正後：

- 透過 paragraph `markerId` 找到目標 block 尾端。
- ProseMirror plugin 建立 widget decoration host。
- React 使用 portal 把 `StorytellerAgenticPanel` 掛進該 host。
- anchor 改變時移動同一個 host，不新增第二個 panel。
- marker 找不到時降級到文件末端，不讓 AI 工作區消失。

### 6. 移除沒有資訊價值的 scope 顯示

已移除 header 上方的「選取文字／目前段落／整篇內容」Chip。

原因：

- 工作區所在位置已經提供段落上下文。
- 有實際選取文字時，下方會顯示完整 selection target banner。
- 沒有選取文字時，不顯示「目前段落：（空白）」等冗餘 banner。

目前只有 `selectedText.trim()` 非空白時才呈現選取內容提示。

### 7. Composer 簡化為單一操作面

原本 composer 下半部同時顯示 quick action buttons、輸入框、Provider、Model、Markdown 說明與指令說明，資訊密度過高。

目前改為一個 `Paper` composer：

- 中央：multiline prompt input。
- 左下：quick actions、Agent、Provider／Model、Markdown、指令／引用說明。
- 右下：送出按鈕。
- 非必要說明不常駐顯示，改用 Tooltip 或 Drawer。
- prompt 錯誤才顯示 helper text。

Quick actions：

| Icon 行為 | 寫入 prompt |
| --- | --- |
| 改寫內容 | `/rewrite ` |
| 擴寫內容 | `/expand ` |
| 縮短內容 | `/rewrite 請縮短內容，保留必要資訊。` |
| 調整語氣 | `/rewrite 請調整語氣：` |

icon 均有 Tooltip 與 `aria-label`。

### 8. Agent 人設移入 composer

Agent 選單不再放在 panel header，改成 composer icon/control 群組的一部分。

- control 常駐顯示「無人設」或本次 prompt 使用的 Agent 名稱。
- 人設只影響本次訊息，以 `/<Agent 名稱>` prompt prefix 表示。
- 選「無人設」會清除既有 Agent prefix，但保留後面的 instruction。
- 選單不再包含「單輪指令」區塊；單輪 skill 已由 quick action icons 與直接輸入 `/` 負責。
- 沒有建立任何 Agent 時，control 顯示「尚無 Agent」並 disabled。

### 9. Provider／Model 合併成單一設定入口

Provider 與 Model 有連動關係，不再拆成兩顆只顯示 icon 的按鈕。

目前 control：

- 常駐顯示 `Provider · Model`，不需要點開才知道目前設定。
- Tooltip 額外顯示目前 API Key。
- 點擊後開啟雙欄 Popover：左欄 Provider／API Key，右欄該 Provider 的 Model。
- 切換左欄 Provider／API Key 時，右欄 Model 目錄即時更新，Popover 不關閉。
- 選定 Model 後才關閉 Popover。
- Model 欄固定高度並有獨立、可見的 scrollbar。
- 非 `self_hosted` 且有 model catalog 時，顯示即時 filter input。
- filter 同時比對 model label 與實際 name，切換 Provider 或關閉 Popover 時清空。
- `self_hosted` 繼續使用 `SelfHostedModelPicker`，不顯示一般 catalog filter。
- 允許 custom model、但沒有 catalog 的其他 Provider，保留自訂 model name input。

### 10. Header 只保留識別與關閉

目前 header 只保留：

- AI 協作標題與 icon。
- 貼齊最右側的 `×` 關閉按鈕。

關閉按鈕有「關閉 AI 協作」Tooltip 與一致的 `aria-label`。

### 11. Selection lifecycle 修正

實際操作發現：選取文字後按 BubbleMenu 的「問 AI」，BubbleMenu 沒消失，而且 AI panel 取不到 selection。

原因與修正：

- 點擊後若 selection 仍保持非空，BubbleMenu 會繼續顯示。
- child panel 原本在 mount effect 立即通知父層清除 pending trigger；React Strict Mode 重跑 mount 時，第二次 mount 已拿不到 trigger，selection 內容因此遺失。
- 現在改成在點擊當下先 snapshot 完整 selected text、scope 與 markerId，再收合 editor selection 並 blur。
- pending selection trigger 改由 Story／Lore editor 保留到 AI 工作區關閉，不在 child mount effect 立即消費。
- AI panel 只用短預覽呈現 selection banner，真正送給 skill 的 `selected_content` 保留完整原文。

### 12. Inline anchor 在段落編輯後失聯（Claude code review 發現，待修）

實際操作發現：在某段落觸發「問 AI」，工作區正確掛在段落後方後，若接著編輯／合併掉那個段落（例如游標放在段落開頭按 Backspace 跟前一段合併），AI 工作區會整個「消失」——但不是乾淨關閉：

驗證方式與現象：

- 在第二段觸發「問 AI」，確認 `[data-storyteller-ai-inline-anchor="true"]` host 正確掛在該段落後、`innerHTML` 有內容。
- 游標放到第二段開頭，dispatch 一次 Backspace，讓它跟第一段合併（第二段的 markerId 因此消失）。
- 合併後檢查：host 的 DOM node **還在**（`getBoundingClientRect()` 顯示位置與高度都正常、佔滿 600px），但 `innerHTML` 變成空字串——React portal 掛載的 `StorytellerAgenticPanel` 整個不見了，畫面上留下一塊空白區域，沒有任何內容、也沒有關閉按鈕。
- React state（`sidePanel === "agentic"`）仍認為工作區是開啟的，只是視覺上完全空白。
- **不是永久卡死**：使用者若在任何其他還存在的段落再次觸發「問 AI」，工作區會正確移動過去、內容恢復正常顯示（`hostCount` 全程維持 1，不會殘留孤兒 host）。但在使用者發現並重新觸發之前，會有一段「編輯區莫名多一塊 600px 空白、AI 卻消失」的破圖體驗。

根因分析：

- `inlineAssistantAnchor.ts` 的 plugin `apply()` 只在 `transaction.mapping.mapResult(current.pos, 1).deleted === true` 時才把 `pos` 設回 `null`（觸發「降級到文件末端」的重新解析）。這次合併操作沒有讓 mapping 判定成 deleted——position 被映射到一個新的、有效的位置，decoration host 因此繼續存在。
- 但 `StorytellerWysiwygEditor.tsx` 的 `useLayoutEffect`（負責 `resolveHost()` 抓 DOM node 存進 `inlineAssistantHost` state）只在依賴陣列（`editor`／`inlineAssistantAnchorMarkerId`／`inlineAssistantOpen`／`hasInlineAssistant`）改變時才重新執行。使用者編輯段落不會改變這幾個值，所以 effect 不會重新抓取 host，`inlineAssistantHost` 繼續指向舊的 DOM node 參照。
- ProseMirror 在這次 transaction 裡實際上**重建**了 widget 的 DOM（新的空 `<div>`），儘管 decoration 設了固定 `key`。React 的 `createPortal(inlineAssistant, inlineAssistantHost, ...)` 掛的是舊 node，內容因此渲染到一個使用者看不到的孤兒節點裡（或乾脆對不上新 host），畫面上只剩下新 host 的空殼。

修復方向建議（給 Codex 判斷實際可行的寫法）：

- `useLayoutEffect` 不能只在 marker/open 狀態改變時重新抓 host，還要能感知「當前 anchor 位置對應的 DOM host 是否還是原來那個」。可以考慮：在 `editorState`／`useEditorState` 裡額外訂閱 plugin state 的 `pos`（或整個 decoration 是否重建），只要偵測到 host 元素引用改變（例如用 `MutationObserver` 監看 ProseMirror DOM，或每次 transaction 後都重新 `resolveHost()` 並比較是否為同一個 node），就重新指定 `inlineAssistantHost`。
- 或者更簡單：不依賴「這個 host 是否還是同一個 DOM node」，改成每次 editor transaction dispatch 後都無條件重新查一次 `resolveHost()`（例如掛在 `editor.on("transaction", ...)`），確保 `inlineAssistantHost` 永遠對齊當下實際存在的 host，不管 ProseMirror 底層是重用還是重建了這個節點。
- 需要涵蓋的情境不只「合併段落」：段落被整個刪除（觸發現有的「降級到文件末端」邏輯）、段落被拆成兩段、undo/redo 回到編輯前的狀態，都要驗證 AI 工作區要嘛正確跟著移動、要嘛正確關閉，不能出現「host 還在但內容消失」這種中間態。

#### 修復實作（2026-09-12）

- `inlineAssistantAnchor.ts` 改為每個 plugin instance 只建立一次 decoration host；即使 ProseMirror 重建 widget view，`toDOM` 仍回傳同一個 DOM element，因此 `StorytellerWysiwygEditor.tsx` 既有的 `inlineAssistantHost` state 與 React portal 不會指到孤兒節點，也不需要等待下一次 React render 才搬移內容。
- plugin state 同時保留目標 `markerId`；每次 `docChanged` transaction 都從新文件重新解析 marker 位置，不再只信任 mapping。marker 消失時位置降級到文件末端，但仍保留 markerId，讓 undo 復原段落時可以自動跟回。
- `inlineAssistantAnchor.test.ts` 新增回歸測試：目標段落向前合併後沿用原 host 且 portal child 不消失；目標段落整段刪除後跟到文件末端；段落拆分後跟著保留原 markerId 的前半段；合併後依序 undo／redo／undo 時，host identity 與位置皆正確。

### 13. AI composer 的 Backspace 誤關閉工作區

實際操作發現：AI 工作區開啟後，composer 已帶入 `/custom`，在輸入框按 Backspace 想刪除文字時，整個 AI 工作區會直接消失。

原因與修正：

- AI 工作區雖然透過 React portal 呈現，但 DOM host 位於 ProseMirror decoration widget 內。
- widget 原本沒有攔截互動事件，因此輸入框的 `keydown` 會繼續交給 ProseMirror，Backspace 可能誤觸 editor command 並影響承載工作區的 anchor。
- decoration widget 現在設定 `stopEvent: () => true`，由 portal 內的 React controls 自行處理鍵盤、滑鼠與 IME 事件，不再冒泡給正文 editor。
- 新增回歸測試，確認在 host 內 textarea 對 `/custom` dispatch Backspace 時，ProseMirror `handleKeyDown` 不會收到事件，host 也不會消失。

這項隔離不只處理 Backspace，也避免 Enter、IME composition 或 composer 內其他快捷操作誤觸正文指令。

### 14. `/` 指令選單重新整理

原本 `/` 選單是窄版單欄清單，標題 1～6 佔去大部分首屏高度，使用者通常必須向下捲動才能看到區塊、插入或 AI 功能。

目前調整為分組 command palette：

- 順序比照「沒有選取文字」時的右鍵選單：`段落樣式 → 對齊 → 區塊 → 插入 → AI 協作`。
- 各組改用三欄 grid，桌面寬度上可在同一畫面看到全部 18 個 command；600px 以下降為兩欄。
- 選單寬度上限為 540px，高度上限為 440px／viewport 可用高度；內容超出時仍保留整體 scrollbar。
- 內文與標題 1～6 改用可辨識層級的獨立 icon，不再全部共用同一個標題 icon。
- 保留鍵盤上下選取、Enter 執行、目前項目自動捲入可視範圍，以及 query filter。
- 「問 AI」固定置於最後的 `AI 協作` 群組，不再搶占最上方位置。

三種入口刻意不統一成完全相同的版型：

| 入口 | 版型 | 理由 |
| --- | --- | --- |
| `/` 指令 | 分組、多欄 command palette | 適合鍵盤搜尋、快速瀏覽完整功能集合 |
| 無選取文字的右鍵選單 | 窄版垂直選單＋submenu | 就近操作、減少遮蔽正文 |
| 選取文字的浮動選單 | 精簡 icon toolbar | 只呈現可立即套用於 selection 的高頻操作 |

三者雖然外型不同，但應持續共用 command registry，並維持相同的功能名稱、icon、分類順序與執行結果；差異只存在於各情境所需的資訊密度與版面。

## 目前定案行為

### 入口與 scope

| 入口 | scope | 顯示位置 |
| --- | --- | --- |
| 選取文字後 BubbleMenu「問 AI」 | selection | selection 結尾所在段落後方 |
| 右鍵選單「問 AI」 | selection 或目前 block | 對應段落後方 |
| editor `/` 選單「問 AI」 | selection 或目前 block | 對應段落後方 |
| 文件工具列 AI 按鈕 | document | caret 所在段落後方作為 UI anchor |

`document` 的 anchor 只決定 UI 顯示位置，不會把 scope 降級成目前段落。

### AI panel 結構

```text
┌ AI 協作                                             × ┐
├──────────────────────────────────────────────────────┤
│ 對話歷史／空狀態／工具軌跡／提案                     │
├──────────────────────────────────────────────────────┤
│ [選取內容提示：只有 selectedText 非空白時顯示]       │
│                                                      │
│ 問 AI，或輸入 / 使用指令...                          │
│                                                      │
│ quick actions | Agent | Provider · Model | 說明   ↑  │
└──────────────────────────────────────────────────────┘
```

### 單一 panel 規則

- `StorytellerWysiwygEditor` 只建立一個 inline assistant decoration。
- panel 關閉時清除 decoration host 與 pending selection trigger。
- 新 trigger 只會改變 anchor 與 panel context。
- decoration 位置會跟著 ProseMirror transaction mapping 移動。
- decoration host 設為 `contentEditable="false"` 與 `ignoreSelection`，避免干擾正文編輯。

### Composer 顯示規則

- quick actions 只有 workspace presentation 顯示。
- Agent control 顯示本次 prompt 的人設，不是全域持久選項。
- Provider／API Key 與 Model 是跨 project 的操作偏好，沿用 localStorage。
- Markdown 與「指令／引用說明」以 icon + Tooltip 開啟既有 Drawer。
- send disabled 條件仍包含：沒有 API Key、prompt 空白、target 未儲存、Agent fallback 不可用、payload error 或 request pending。

## 技術設計

### ProseMirror inline anchor

新增 `InlineAssistantAnchor` extension：

- plugin state 保存 `pos: number | null` 與目標 `markerId`。
- `setInlineAssistantAnchor()` 依 markerId 尋找 block 尾端。
- 每次 `docChanged` 都從新文件重新解析 marker；marker 消失時降級到文件末端，undo 復原 marker 後可自動跟回。
- 每個 plugin instance 只建立一次 decoration host，ProseMirror 重建 widget view 時仍回傳同一個 DOM element，避免 React portal 指向孤兒節點。
- decoration widget 使用固定 key、`contentEditable="false"`、`ignoreSelection` 與 `stopEvent`；portal 內事件不交給正文 editor。

### React portal

`StorytellerWysiwygEditor`：

- `useLayoutEffect` 在 open／anchor 改變時 dispatch anchor transaction。
- 從 editor DOM 找到 decoration host。
- 使用 `createPortal()` 掛載現有 `StorytellerAgenticPanel`。
- host 出現後 scroll into view。
- 關閉時清除 anchor 與 portal host state。

### Story／Lore 共用

Story 與 Lore editor 使用相同的：

- selection trigger contract。
- inline anchor extension。
- `StorytellerAgenticPanel` workspace presentation。
- pending trigger lifecycle。

兩者只保留各自的 API、目前內容、提案套用與 snackbar 行為。

## Claude code review checklist

### P0：資料與編輯器安全

- decoration host 是否永遠不會被序列化進 ProseMirror document／Markdown。
- 開關或移動 AI panel 是否會污染 undo history。
- `contentEditable="false"` 的 portal 是否會破壞 selection、IME、copy/paste 或 editor keyboard shortcuts。
- composer 內 Backspace、Enter、IME 與滑鼠事件是否都被 widget `stopEvent` 隔離，不會觸發正文 command 或移除 anchor。
- marker 不存在、段落刪除／合併、文件內容重新載入時 anchor fallback 是否安全。
- Story 與 Lore 是否都不會因 panel 開關造成未預期的內容變更或 autosave。

### P1：Selection lifecycle

- BubbleMenu 點擊時是否保證先 snapshot `selectedText`／markerId，再收合 selection。
- React Strict Mode 下 pending trigger 是否仍能穩定帶入 panel。
- 關閉 panel 後 pending trigger 是否確實清除；重新開啟 document scope 時不應殘留舊 selection。
- 空白 paragraph 不應顯示「目前段落：（空白）」banner。
- skill request 的 `selected_content` 應是完整原文，不是 UI 的截斷預覽。

### P1：單一 host 與移動

- 任一時間 editor DOM 內是否只有一個 `[data-storyteller-ai-inline-anchor="true"]`。
- trigger 新段落時是否移動同一個 panel，而不是殘留孤兒 portal。
- close 後 host 是否確實消失。
- decoration mapping 與 marker lookup 是否有 off-by-one 或插在錯誤 paragraph 內的問題。

### P1：Composer 行為

- quick action 是否只預填 prompt，不會直接送出。
- Agent prefix 的新增、替換、清除是否保留 instruction。
- `/Agent 名稱` 與 `/rewrite` 等保留 skill command 的解析優先序是否正確。
- control 顯示的人設是否與實際送出的 prompt prefix 一致。
- Provider／API Key 切換後 Model catalog、fallback model 與 localStorage 是否同步。
- `self_hosted`、custom model provider、固定 catalog provider 三條路徑是否都可操作。
- Model filter 是否只在適用時顯示，能搜尋 label/name，並於切換 Provider／關閉時清空。
- Model 很多時右欄是否可獨立捲動，手機寬度下是否仍可操作。

### P2：UI／Accessibility

- header close button 是否在桌面與手機都固定於最右側。
- 所有只顯示 icon 的 action 是否有 Tooltip 與 `aria-label`。
- composer icon 列在窄寬度時是否可水平捲動，send button 是否維持可見。
- Popover focus、Escape、click-away 與鍵盤選取是否符合預期。
- AI panel scroll 與 editor page scroll 是否互相搶滾輪。
- `/` command palette 的分組名稱、順序、icon 與右鍵選單是否一致。
- `/` 選單在桌面三欄、窄螢幕兩欄及內容超出高度時是否仍可完整操作。
- query filter 後若只剩部分群組，group heading、鍵盤高亮與自動捲動是否正確。
