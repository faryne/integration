審查筆記（不屬於產品 UI）

  1. 自己的內容不出現「檢舉」：作品／故事／設定的擁有者、動態與留言本人都看不到這一項（上面「我自己」那則就沒有）。
  2. 作品首頁、創作者頁原本沒有 ⋯，這次新增。閱讀頁、設定頁統一放閱讀工具列：比照討論按鈕走插槽（reportButton），元件放獨立檔，Reader.tsx 只多一行串接。工具列空間有限，用 icon-only 旗子＋tooltip「檢舉」。
  3. 留言沿用行內文字動作，不另加 ⋯，跟現在「回覆／編輯／刪除／封鎖」一致。
  4. 作者對自己作品底下的留言／討論串可以檢舉（作者能刪，但也可能想交給站方處理帳號）。

審查筆記（不屬於產品 UI）

  1. 原因用下拉選單，不條列 radio，dialog 高度固定。選項依對象過濾：「限制級內容未標示」只出現在作品／故事／設定；「冒充他人」只出現在創作者。切換上方「檢舉對象」看差異。
  2. 選「其他」時補充說明變必填，沒填「送出檢舉」維持 disabled；其他理由補充說明可留空。
  3. 未登入：按「檢舉」直接導去登入頁，不開 dialog（切到「未登入」再按一次看 snack 示意）。
  4. 重複檢舉：同一目標還在處理中時，後端回成功、前端一樣顯示「已收到檢舉」，不提示「你已經檢舉過」。
  5. 手機版：dialog 改成底部 sheet。

審查筆記（不屬於產品 UI）

  1. 使用者自己刪的（delete_reason 為空）維持原文字不變；只有內部刪除才補原因。
  2. 內部刪除改寫成「已由站方移除，原因：……」，原因部分顏色深一階、不斜體；本人刪除仍是「此留言已刪除」，兩者一眼分得出來。
  3. 「↪ 回覆 已刪除的留言」不補原因：那只是指向，原因看上面的佔位就好，避免同一個原因重複出現。
  4. 原本 404 的（作品、故事、設定、創作者、討論串整串）維持 404，這裡不畫。
