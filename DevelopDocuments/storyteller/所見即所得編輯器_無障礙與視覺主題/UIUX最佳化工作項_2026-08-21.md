## Phase 1：低風險、範圍明確，直接修

- [x] **1. 新故事建立時預設狀態改成「草稿」，不是「公開中」**
  - What：`StoryEditor.tsx` 新建故事（`story` 為 undefined）時，`storyStatus` 的預設值從 `"completed"`（公開中）改成 `"draft"`（草稿）。
  - Why：一個完全空白、什麼都還沒寫的新故事一建立就是公開狀態，跟 Google Docs／Notion「新文件預設私有」的直覺相反，容易讓人沒注意就把空白/未完成內容曝光出去。
  - Where：`static_site/src/pages/storyteller/StoryEditor.tsx:312-314`（初始 state）、`584`（`story` 資料到位後重設一次）。
  - How：兩處的 `story?.status ?? "completed"` 改成 `story?.status ?? "draft"`。已存在的故事（`story` 有值）不受影響，只改「全新建立」這個情境的預設值。
  - ✅ 已修（2026-08-22）：`LoreEditor.tsx` 查證過沒有對應的公開狀態欄位（設定集本來就沒有 draft/completed 概念），不需要一併改。已用 dev-only 假登入實測：新建故事的「狀態」欄位顯示「未公開」，列表也顯示「草稿」標籤。

- [x] **2. 工具列「插入資產／AI Agent／編輯歷史」圖示按鈕補 `aria-label`**
  - What：三個 icon-only 按鈕目前只靠 `Tooltip` 的 `title`，`IconButton`／`ToggleButton` 本身沒有 `aria-label`，螢幕報讀器讀不出功能。
  - Why：跟這次 Phase E 對 slash/bubble/右鍵選單做的事一樣——icon-only 互動元件一定要有語意層級的名字，不能只靠滑鼠 hover 才看得到的 tooltip。
  - Where：`StoryEditor.tsx:1592-1601`、`LoreEditor.tsx:1254-1262`（插入資產）；`StorytellerEditorSideTabs.tsx:28-37`（AI Agent／編輯歷史）。
  - How：比照 Tooltip 的文字內容，各自補上對應的 `aria-label`（例如 `aria-label="插入資產"`）。
  - ✅ 已修（2026-08-22）：三處都補上 `aria-label`，已用瀏覽器 DOM 檢查確認 `getAttribute('aria-label')` 分別回傳「插入資產」「AI Agent」「編輯歷史」。

- [x] **3. 專案卡片可見度圖示（鎖頭/雙人/地球）補 `aria-label`**
  - What：`HomeCards.tsx` 的 `ToggleButtonGroup` 三個 `ToggleButton`（`private`/`unlisted`/`public`）只靠 `Tooltip` 包住圖示，`ToggleButton` 本身沒有 `aria-label`。
  - Why：同上，純圖示又沒有語意標籤，screen reader 使用者猜不到意思。
  - Where：`static_site/src/pages/storyteller/HomeCards.tsx:108-132`。
  - How：三個 `ToggleButton` 各自補上 `aria-label="私人"`／`aria-label="好友可見"`／`aria-label="公開"`（實際文案跟 Tooltip title 對齊）。
  - ✅ 已修（2026-08-22）：文案跟既有 Tooltip title 對齊（「完全不公開」「與親友分享」「已公開」），DOM 檢查確認三個 `aria-label` 都正確掛上。

- [x] **4. 插入資產 Dialog 沒有可用資產時，補上直接前往上傳的捷徑**
  - What：`StorytellerAssetPickerDialog.tsx` 空狀態只顯示「沒有可用資產，請先在資產集上傳圖片」文字，沒有任何連結/按鈕。
  - Why：使用者要自己回頭摸索側邊欄的「資產集」在哪，操作動線中斷。
  - Where：`static_site/src/pages/storyteller/StorytellerAssetPickerDialog.tsx:71-76`。
  - How：`CustomEmptyState` 補一個 action（按鈕或連結），導向對應專案的資產集頁面（`/storyteller/my/workspace/:id/assets` 之類，實際路徑需要對照 `App.tsx` 路由確認）。Dialog 本身可能需要判斷要不要順便關閉自己（跳轉後使用者應該還要回來插入圖片，這裡要想清楚體驗：是開新分頁，還是關閉 dialog 導頁）。
  - ✅ 已修（2026-08-22）：`CustomEmptyState` 補了 `action?: ReactNode` prop（其他呼叫端不受影響，預設不傳就沒有變化）；空狀態按鈕連到 `/storyteller/my/workspace/:id/assets`，用 `target="_blank"` 開新分頁，避免使用者跳走後遺失原本正在編輯的插入流程。實測：空狀態下按鈕出現、`href` 正確指向對應專案的資產集頁面。

- [x] **5. 故事／設定集列表標題被截斷時補完整 Tooltip**
  - What：`ProjectWorkspacePreviewRows.tsx` 的 `StoryRow`／`LoreRow` 標題用 `noWrap` 截斷成「...」，`StoryRow` 現有的 `Tooltip` 內容其實是「可拖曳調整順序」提示（跟標題文字無關，不可拖曳時是空字串），`LoreRow` 更是完全沒有 Tooltip。
  - Why：標題被截斷後使用者看不到完整標題，尤其手機版欄寬更窄、更常截斷。
  - Where：`static_site/src/pages/storyteller/ProjectWorkspacePreviewRows.tsx:100`（`StoryRow` 現有 Tooltip）、`137-139`（`StoryRow` 標題）、`193-230`（`LoreRow` 整體）、`213-216`（`LoreRow` 標題）。
  - How：`StoryRow` 現有的「可拖曳調整順序」Tooltip 需要跟「完整標題」兩個提示分開處理（不能互相覆蓋掉），例如標題本身包一層獨立的 `Tooltip title={story.title}`；`LoreRow` 標題比照補上同樣的 Tooltip。
  - ✅ 已修（2026-08-22）：標題各自包一層獨立 `Tooltip title={story.title}`／`title={lore.title}`，跟原本外層「可拖曳調整順序」的 Tooltip 是兩層獨立的 MUI Tooltip，互不覆蓋。屬於標準 MUI 用法、風險低，未逐一用滑鼠 hover 複測，程式碼審查信心足夠。

- [x] **6. 工作台嵌入模式的標題／摘要輸入框補鍵盤 focus 樣式**
  - What：`WorkspaceEditableTitle`／`WorkspaceEditableSummary`（`Box component="input"/"textarea"`）明確設了 `outline: 0`，沒有補任何 `:focus-visible` 替代樣式，鍵盤使用者 Tab 過去後完全看不到目前焦點在哪。
  - Why：拿掉瀏覽器預設 focus 外框是合理的視覺選擇（跟其他輸入框風格一致），但拿掉後沒有補一個看得見的替代方案，違反「focus 不能被拿掉，只能換色」這個 Phase E 已經在別處遵守的原則（見 `MuiButtonBase` 的 `focusRing` token 用法）。
  - Where：`static_site/src/pages/storyteller/ProjectWorkspaceEditorControls.tsx:43-113`。
  - How：補 `&:focus-visible` 樣式，用跟其他地方一致的 `var(--storyteller-focus-ring)` token（例如 `outline: 2px solid var(--storyteller-focus-ring); outline-offset: 2px`），不要用瀏覽器預設藍色。
  - ✅ 已修（2026-08-22）：兩處都補上 `&:focus-visible`，直接寫 `var(--storyteller-focus-ring)`（原生 `input`/`textarea` 不吃 `storytellerComponentOverrides.ts` 的 `v()` helper，改用同一個 CSS 變數字面值）。實測：聚焦摘要欄位後 `getComputedStyle(document.activeElement).outlineWidth` 為 `2px`、顏色為品牌色 `rgb(230, 189, 118)`。

- [x] **7. 觸控目標放大：故事/設定集/資產列的操作按鈕**
  - What：故事列表每一行的編輯/更多/刪除等 `IconButton` 目前是 `size="small"`（約 30×30px）且間距只有 4px/2px。
  - Why：WCAG 2.5.5（AAA，但業界慣例常視為最低建議）建議觸控目標至少 44×44 CSS px；就算不追求滿足 AAA，30×30px 且互相緊貼在手機上很容易誤觸（例如誤刪成誤編輯），這是這次獨立評測明確指出的問題。
  - Where：`static_site/src/pages/storyteller/ProjectWorkspacePreviewActions.tsx`（`renderStoryActions` 643-688、`renderLoreActions` 690-723、`renderAssetActions` 725-740+）。
  - How：只在手機斷點（`xs`）加大 `IconButton` 的 padding（`p: { xs: 1.25, sm: 0.625 } `）跟 `Stack` 間距（`spacing: { xs: 1, sm: 原值 }`），桌面滑鼠操作維持原尺寸不變。
  - ✅ 已修（2026-08-22）：實測 375px 寬（mobile 模擬）下，故事列的編輯／更多／刪除按鈕從原本 ~30×30px（padding 5px）放大到 40×40px（padding 10px），桌面寬度（1280px）下維持原尺寸不變。**側邊欄收合鈕（`ProjectWorkspacePreview.tsx:541-551`）查證後排除**：該按鈕只在 `!isMobile` 時渲染（`ProjectWorkspacePreview.tsx:507`），手機版走的是完全不同的 `WorkspaceMobileNav` 元件，不會顯示這顆按鈕，不需要跟著放大。

## 已查證、確認不是問題

- **右鍵選單對「已存在註解」的判斷（游標未選取時右鍵）**：程式碼邏輯查證過是對的——`annotationCommands` 的 filter 用 `hasSelection || command.isActive(editor)`，`comment` 的 `isActive` 在游標（collapsed selection）落在既有註解文字內時本來就會回傳 `true`，右鍵收合選取也不影響這個判斷。獨立評測報告裡「單純右鍵沒有註解選項、一定要先選取」這個現象，比較可能是自動化測試工具操作 DOM 的方式跟真實滑鼠右鍵行為有落差（例如測試工具的「右鍵」沒有先讓 ProseMirror 真的把游標移到點擊位置），不是程式碼問題。**不需要改程式碼**，但建議 Faryne 之後自己用真實滑鼠測一次這個情境，如果真的重現得出來再回頭查。

## 待複測／不確定是否為真問題（不列入本輪工作項）

- **建立專案表單滑鼠滾輪失效**：這次寫 Phase 1 工作項時我自己也在建立測試專案時撞到同樣的症狀（`computer` 工具的 `scroll` 動作直接逾時、頁面沒有任何反應），一開始懷疑真的是產品問題，但用 JS 檢查發現頁面裡確實有一個 `overflow-y: auto` 的可捲動容器（`scrollHeight 824 / clientHeight 599`），只是我後續改用 `resize_window` 加高視窗高度後就能正常看到並點擊到「建立專案」按鈕，過程中沒有再遇到卡死。無法排除是這次工具環境本身間歇性不穩定（同一個 session 裡點擊/滾動操作也各自逾時過幾次，跟頁面內容無關），也無法完全排除真的是這個表單的滾動容器在某些情況下有 bug。**先不當成確定的 bug 處理**，麻煩 Faryne 之後自己在真實瀏覽器測一次建立專案頁面的滾動是否正常，如果真人也重現得出來再回頭查。
- **Slash 選單在非空段落結尾打 `/` 沒有任何提示**：查證過現況是設計上的既有限制（`isTextOnlySlashQuery` 只允許段落開頭），不是 bug，但確實沒有任何提示/回饋。要不要補提示、補什麼樣的提示（例如短暫的文字色變化、tooltip），還是乾脆讓非空段落結尾也能觸發 slash 選單（比較大的改動），這是產品行為決策，先不列入本輪，需要另外討論方向。
- **沒有「所有註解列表」或側邊標記**：這是功能請求等級（類似 Google Docs 側邊留言泡泡），不是既有功能的 bug，工程量也明顯比其他項目大，列為之後的功能請求，不放進這次的 UI/UX 修正範圍。
- **手機版觸控長按選字、格式列/註解編輯路徑**：獨立評測報告自己也承認測試工具無法模擬真正的觸控長按手勢，這部分的疑慮沒辦法用自動化驗證，需要 Faryne 用真實觸控裝置複測。
