# SteamLoom 全站視覺風格提案：光織工房

## 結論

這次不把「更 fancy」理解成加入更多齒輪、銅色邊框、陰影或裝飾，而是把 SteamLoom 從目前較一致但偏厚重的 steampunk UI，推向一個更像成熟創作產品的 **editorial sci-fantasy** 風格：

- 保留「工房、織物、機械」的品牌記憶。
- 以字體層級、版面留白、線性織紋、局部光澤建立辨識度。
- 探索頁可以有戲劇性；工作台維持效率；閱讀頁維持沉浸。三種情境共享語言，但不硬套相同密度。
- 本 branch 已確定直接以三種 appearance 取代現有 palette × light/dark，不保留第二套 classic UI。

Mockup 上方可切換「探索／工作台／閱讀」三個代表頁，也可以切換「夜織／紙本／稜光」觀察同一套構圖在不同調性下的表現。

## 核心方向

### 1. 從齒輪轉向「織造」

目前 SteamLoom 的機械感大量依靠褐金色、粗框、鉚釘與齒輪符號。這套語言容易辨識，但套用到所有 surface 後，資訊密度會顯得偏重。

新方向以更抽象的品牌元素取代重複裝飾：

- 經緯線、套色標記、編號、細網格與局部光絲。
- 機械意象保留在結構與微互動，不讓每張 card 都長得像控制面板。
- 邊框減量，改用對齊、留白和背景層次區隔內容。

### 2. Fancy 來自構圖，而不是元件膨脹

首頁與探索頁使用較大字級、非對稱編排、帶編號的策展卡，讓內容像雜誌封面與展覽目錄。工作台則收斂為高密度清單與清楚的導航欄；閱讀頁讓紙面成為唯一主角，控制列固定在底端。

這樣不需要為了新風格大量增加 UI 元件，主要成本會落在 tokens、shared shell 與共用 card 的視覺重整。

### 3. 一套結構，三種強度

- **探索頁：高表現力。** 品牌 hero、策展編號、較明顯的動態線條。
- **工作台：中度表現力。** 保留品牌字體與線條，操作面維持安靜、易掃描。
- **閱讀頁：低干擾。** 以紙張、字體與閱讀節奏為主，品牌效果退到頁面外圍。

因此這不是把首頁樣式整批複製到每一頁，而是共享 design tokens 與視覺文法。

## Grid / List 的呈現策略

### 首頁作品：固定使用 Grid

首頁是探索情境，讀者先靠題材、作品名與視覺氣氛做選擇，因此維持三欄 editorial grid，不在首頁再放 grid / list 切換：

- Desktop 三欄、tablet 兩欄、mobile 單欄。
- 圖像／抽象 cover 約占 card 上方三分之一，接著才是作品名、簡介、篇數、字數與分級。
- tag 只保留兩至三個，管理按鈕不出現在公開版本。
- 首頁、探索、追蹤頁仍共用 Project Card anatomy；只有 CTA、follow state、owner actions 用 variant 決定。
- 搜尋結果或個人書架若資料量高，可以改用 compact list variant，但不是首頁的顯示選項。

### 工作台：故事預設 List；設定／資產預設 Grid

三者需要的掃描方式不同，不應為了「統一」強迫使用相同 layout：

- **故事：預設 List。** 順序、長標題、字數、公開狀態與更新時間更重要，也較適合排序和批次操作。仍可切 Grid，方便用章節氣氛或插圖瀏覽。
- **設定：預設 Grid。** 角色、地點、組織需要靠類型、簡介與引用關係辨識；card 顯示「被哪些故事引用」比更新時間更有價值。
- **資產：預設 Grid。** 預覽圖是第一辨識資訊，接著才是格式、尺寸、檔案大小與使用狀態。切成 List 時適合大量整理與批次管理。

三種內容共用 `CollectionItem` 骨架與同一組 grid / list layout primitives，但透過 content variant 決定 visual、metadata 與 actions。顯示偏好應分別記錄，例如故事切成 Grid 不會連帶把設定也切成 List。行動版不硬塞多欄 grid，統一收成單欄 compact card。

內容類型不在標題旁重複放一組「故事／設定／資產」切換。Desktop 直接使用既有 sidebar，Mobile 則使用導覽 drawer，兩者才是內容結構的單一入口；標題旁只保留目前頁面需要的 Grid / List 切換。

## 首頁亂數文案

首頁 Hero 使用亂數內容，但採用「人工策展的標題＋說明配對」，不能把標題和文案各自亂抽，否則語氣與意思容易不連貫。Mockup 與正式頁面每次載入會抽一組，不提供額外的「換一句」操作。

正式文案集中在 `storytellerPublicHomeCopy.ts` 的單一常數中，直接增刪完整配對即可。SSR／crawler 先取得第一組內容，client 掛載後再抽選，並用 sessionStorage 避免連續兩次載入抽到同一組。

## 色彩策略：收斂為三種 Appearance

我贊成直接棄用現有 11 組 palette。原本 palette × light/dark 的組合雖然自由，但調校、contrast、component overrides 與 regression 成本太高，也會稀釋 SteamLoom 自己的品牌色彩。

- **夜織（預設）**：深藍黑底、暖紙色文字、青藍光絲。品牌感最明確，也最能和現有褐金 steampunk 拉開距離。
- **紙本**：適合閱讀與日間使用，用暖灰紙色與深墨色維持 editorial 質感。
- **稜光**：暗紫底、青綠與粉紫 accent，提供高彩度但仍受控的選擇。

三者本身就是完整 appearance，不再另外疊一層 light / dark toggle。Header 裡原本的明暗與 palette 控制合併成單一三選一選單，localStorage 只保存一個 `storyteller-appearance`。

既有偏好的 migration 只看原本的 mode：舊設定是 light 就映射為「紙本」，dark 就映射為「夜織」；「稜光」保留給使用者主動選擇。這比嘗試把 11 種 hue 逐一猜測到三種 appearance 更可預期。Reader 的字體、字級、行距和頁寬仍是獨立 reading preferences；背景沿用全站 appearance，避免兩套色彩互相衝突。

## 三個代表頁的設計意圖

### 探索／首頁

- Hero 從傳統大卡片改為 editorial spread，降低「每個區塊都是 panel」的感覺。
- 專案卡仍是同一類共用元件，但以 variant 控制 CTA、狀態與管理功能。
- 內容 metadata 直接排版，不堆疊大量 chip。
- 首頁 header 的資訊架構不需要改；只調整 chrome、品牌標誌、間距與狀態呈現。

### 工作台

- 沿用目前已定案的 desktop sidebar / mobile drawer 行為，不重新推翻資訊架構。
- 故事以清單優先；設定與資產以 grid 優先，並允許各自記住使用者選過的 layout。
- project identity、冊／設定集／資產集繼續待在 navigator；手機仍由單一入口開啟。
- Fancy 元素只放在背景、標題、序號和 active state，不干擾排序、公開狀態、更多操作等功能。

### 閱讀頁

- Hero Card / Well Card 進一步轉成章節封面與紙面，而不是兩張有厚重 chrome 的 panel。
- 完整篇章標題還看得到時不重複顯示 context；捲過標題後才把專案、目前篇章與單行截斷摘要淡入既有網站 Header 的中央空間，不再另外增加第二層 fixed bar。這一列只負責定位，不混入操作。
- 已定案的 fixed bottom toolbar、閱讀進度數字、章節切換、目錄／書籤與閱讀設定都保留。
- 所有閱讀操作（包含編輯歷史）收進同一條底部工具列：desktop 顯示短標籤並以向上 Popover 展開歷史，mobile 以 icon、tooltip 與可獨立捲動的 bottom sheet 維持可用空間。
- 內文區不使用光暈或高彩裝飾；閱讀設定仍掌管字體、字級、行距與閱讀表面。

## 需求變更與最終定案

這個 branch 從純視覺提案進入正式實作後，依實際操作結果做過以下收斂；此處記錄的是目前程式碼應維持的最終行為，不是仍待選擇的備案。

### 全站外觀與 Header

- 原有十多套 palette、獨立 light / dark 與節慶外觀全部退場，只保留「夜織／紙本／稜光」三種完整 Appearance。
- Appearance 使用同一個 Header 選單與同一個 localStorage key；舊 light / dark 設定分別遷移到紙本／夜織，舊 palette 與 seasonal key 會清除。
- Header / Footer 的資訊架構不因 fancy redesign 重寫，避免首頁、工作台、閱讀頁互相影響；視覺只改 semantic color、字體、線條與 surface。
- 品牌 mark 從具象齒輪改成經緯線織框，favicon 同步更新。
- 閱讀中的篇章 context 透過共用 `StorytellerHeaderContext` 注入真正的網站 Header，不在 Header 下方再疊第二列。完整標題仍在畫面內時不顯示；捲離後 desktop 依可用寬度顯示「專案／篇章／摘要」，tablet 逐步縮成篇章，mobile 則以篇章名稱暫時取代品牌文字與次要操作。

### 首頁與共用 Project Card

- 首頁不提供「換一句」按鈕；每次載入從人工配對的標題／強調句／說明中抽一整組，並避免 session 內連續抽到同一組。
- 正式文案集中在 `storytellerPublicHomeCopy.ts`，修改常數即可增刪或替換文案，不把內容散在 component 裡。
- 首頁作品固定使用 responsive editorial grid，不增加 grid / list 切換。
- Project Card 的資訊骨架由首頁、探索、追蹤、作者頁與工作台共用；公開 CTA、追蹤狀態、visibility、owner menu 等差異由呼叫端注入，不複製另一張卡。

### 工作台

- Desktop 保留 sidebar，mobile 只顯示單一「導覽」入口並用 drawer 承載完整樹狀結構，側欄不再佔據行動版頁面開頭。
- 冊／設定集／資產集的展開、收合、排序與專案操作仍留在 navigator；內容標題旁不再重複一組「故事／設定／資產」切換。
- 故事預設 List，設定與資產預設 Grid；三種內容可以各自切換，偏好以 `storyteller-workspace-view-modes` 儲存並跨專案沿用。
- Grid / List 共用資料列元件，只依內容類型切換 visual、metadata 與 actions；mobile grid 收成單欄，管理動作收進 menu 以減少占位。
- 點首頁專案卡後的等待分成兩層處理：首頁穩定後及卡片 hover / focus 時預載工作台 route chunk；單一專案 detail query 先使用既有專案列表 cache 畫出 shell，再在背景換成完整資料。

### 閱讀頁

- 移除重複且占高的大型專案 Hero；頁首保留 breadcrumb，紙面內保留唯一一份完整篇章標題、摘要、作者與更新時間。
- 完整篇章標題捲離後，才在既有 Header 顯示 compact context；摘要一律單行截斷，不增加 Header 高度。
- 所有閱讀操作統一放在 fixed bottom dock：上一篇、目錄／書籤索引、閱讀進度條與百分比、作品資訊、編輯歷史、段落書籤、閱讀設定、下一篇。
- Desktop 使用短標籤與向上 Popover；mobile 使用 icon、tooltip 與 bottom sheet。320px 寬度下仍保留閱讀進度數字，不以水平捲動解決工具列空間。
- 文字故事才顯示編輯歷史；圖片作品沒有版本歷史，因此不留空 icon。版本過多時只在 Popover / bottom sheet 內捲動，不重新撐高正文。
- 原本放在正文標頭的版本歷史 icon 與 inline 展開區塊已移除，確保操作入口只有底部工具列一處。
- 閱讀字體、字級、行距與頁寬偏好仍獨立保存並跨專案沿用；閱讀背景直接跟隨全站 Appearance，不再建立第二套容易衝突的背景 palette。

## 對現有程式架構的衝擊

現有主題架構已有 `storytellerTheme.ts`、`storytellerSemanticTheme.ts`、`storytellerComponentOverrides.ts`，而 shared shell、project card、top bar 也已有共用層。正式實作直接收斂這些共用層，沒有逐頁複製一套 CSS。

| 衝擊 | 範圍                                                                                      | 說明                                                                                                                  |
| ---- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 低   | semantic tokens、CSS variables、背景、字體層級、reduced motion                            | 可在既有主題管線擴充，不改資料流或 API。                                                                              |
| 中   | `StorytellerLayout`、`StorytellerShell`、AppBar、shared project/work cards、panel top bar | 共用元件的外觀會一起受影響，需要明確 variant，避免首頁、追蹤頁、工作台互相誤傷。                                      |
| 中   | 11 palettes × light/dark migration                                                        | 刪除舊 token 前先讓 localStorage 舊值轉成「紙本／夜織」，並清掉 palette ring 與 mode toggle 的殘留入口。              |
| 高   | Editor、Reader、fixed dock、popover / drawer / selection menu                             | z-index、scroll container、mobile viewport、safe-area 與 keyboard interaction 容易出現跨頁 regression，應分階段處理。 |

### 不應該做的事

- 不為了視覺更新重寫 API、route、project data model 或 reading preferences。
- 不直接覆寫所有 MUI 元件，使非 Storyteller 頁面也被迫跟著改。
- 不在第一階段把每一張舊 card 個別重畫；先收斂 shared variants。
- 不讓 animated glow、blur 或背景網格進入長文閱讀區與 editor content area。
- 不在正式程式內長期維護 classic 與 atelier 兩套樣式；需要退回舊版時以 Git commit 回退。

## 本次採用的實作順序

1. **Appearance 與 migration**：新增三種 appearance tokens，將舊 light / dark 偏好映射到紙本／夜織。
2. **全站 shell**：header、頁面背景、breadcrumb、shared panel primitives；不碰頁面功能。
3. **共用內容卡**：Project Card 與 workspace `CollectionItem` 各自收斂 anatomy，再用 page / content variant 決定 metadata、visual 與 actions。
4. **公開頁面**：首頁、探索、追蹤頁先套用，驗證品牌方向和效能。
5. **工作台**：沿用既有資訊架構，替換 visual surface 與 mobile breakpoint 樣式。
6. **閱讀頁**：調整 hero / paper / fixed dock，和既有 reading preference 一起驗證。
7. **Editor 最後處理**：因 slash menu、selection menu、AI panel 與 editor focus 行為最敏感，應另開一輪專門設計與 regression。

此 branch 不設 classic 切換；需要回退時直接回退 commit，避免在正式程式內永久背負雙 design system。

- 舊 localStorage 的 light 映射為紙本、dark 映射為夜織，並清除舊 mode／palette key。

- Project Card 持續供首頁、工作台、追蹤與作者頁共用；頁面只注入各自 actions。

## 驗證重點

- Viewport：320、390、768、1024、1440 px。
- 夜織／紙本／稜光、`prefers-reduced-motion`、鍵盤 focus、touch target、safe-area。
- 舊版 localStorage 有／無 palette 與 mode 值時的 migration、fallback 和跨分頁同步。
- shared project card 在首頁、探索、追蹤、工作台各 context 的 CTA 與 menu 是否正確。
- reader fixed dock 不遮蔽內文，進度、章節與書籤在 mobile keyboard / browser chrome 變化時仍可用。
- editor 的 selection toolbar、slash menu、AI panel、modal / snackbar z-index。
- 所有主要文字與互動狀態的 contrast；稜光只作 accent，不以顏色單獨傳達狀態。
- 背景 texture、blur、font load 對 LCP、scroll 與低階手機 GPU 的影響。
