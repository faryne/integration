# SteamLoom 全站視覺風格提案：光織工房

## 結論

這次不把「更 fancy」理解成加入更多齒輪、銅色邊框、陰影或裝飾，而是把 SteamLoom 從目前較一致但偏厚重的 steampunk UI，推向一個更像成熟創作產品的 **editorial sci-fantasy** 風格：

- 保留「工房、織物、機械」的品牌記憶。
- 以字體層級、版面留白、線性織紋、局部光澤建立辨識度。
- 探索頁可以有戲劇性；工作台維持效率；閱讀頁維持沉浸。三種情境共享語言，但不硬套相同密度。
- 先作為可切換的視覺 preset，不直接取代既有主題，降低全站一次翻新的風險。

Mockup 上方可切換「探索／工作台／閱讀」三個代表頁，也可以切換「夜織／紙本／稜光」觀察同一套構圖在不同調性下的表現。

## 核心方向

### 1. 從齒輪轉向「織造」

目前 SteamLoom 的機械感大量依靠褐金色、粗框、鉚釘與齒輪符號。這套語言容易辨識，但套用到所有 surface 後，資訊密度會顯得偏重。

新方向以更抽象的品牌元素取代重複裝飾：

- 經緯線、套色標記、編號、細網格與局部光絲。
- 機械意象保留在結構與微互動，不讓每張 card 都長得像控制面板。
- 邊框減量，改用對齊、留白和背景層次區隔內容。

### 2. Fancy 來自構圖，而不是元件膨脹

首頁與探索頁使用較大字級、非對稱編排、帶編號的策展卡，讓內容像雜誌封面與展覽目錄。工作台則收斂為高密度清單與清楚的導航欄；閱讀頁讓紙面成為唯一主角，控制列固定在底端。

這樣不需要為了新風格大量增加 UI 元件，主要成本會落在 tokens、shared shell 與共用 card 的視覺重整。

### 3. 一套結構，三種強度

- **探索頁：高表現力。** 品牌 hero、策展編號、較明顯的動態線條。
- **工作台：中度表現力。** 保留品牌字體與線條，操作面維持安靜、易掃描。
- **閱讀頁：低干擾。** 以紙張、字體與閱讀節奏為主，品牌效果退到頁面外圍。

因此這不是把首頁樣式整批複製到每一頁，而是共享 design tokens 與視覺文法。

## 色彩策略

Mockup 的三個色調是方向測試，不代表正式版必須新增三套完整主題。

- **夜織（建議主方向）**：深藍黑底、暖紙色文字、青綠與紫色光絲。品牌感最明確，也最能和現有褐金 steampunk 拉開距離。
- **紙本**：適合閱讀與日間使用，用暖灰紙色與深墨色維持 editorial 質感。
- **稜光**：保留較高彩度的探索性，適合作為活動、featured content 或局部 accent，不建議全站長時間大面積使用。

正式實作不建議立刻為現有 11 組 palette 各重做一份 fancy 版本。較務實的做法是：

1. 新增 `visualStyle: classic | atelier`，先讓新風格成為 opt-in preset。
2. `atelier` 先支援 light / dark 兩組完整 semantic tokens。
3. 現有 palette 偏好仍保留給 `classic`；之後若確定採用，再決定要把 palette 映射成少量 tone family，或逐組調校。

## 三個代表頁的設計意圖

### 探索／首頁

- Hero 從傳統大卡片改為 editorial spread，降低「每個區塊都是 panel」的感覺。
- 專案卡仍是同一類共用元件，但以 variant 控制 CTA、狀態與管理功能。
- 內容 metadata 直接排版，不堆疊大量 chip。
- 首頁 header 的資訊架構不需要改；只調整 chrome、品牌標誌、間距與狀態呈現。

### 工作台

- 沿用目前已定案的 desktop sidebar / mobile drawer 行為，不重新推翻資訊架構。
- 清單優先於 card，減少創作者每天操作時的視覺負擔。
- project identity、冊／設定集／資產集繼續待在 navigator；手機仍由單一入口開啟。
- Fancy 元素只放在背景、標題、序號和 active state，不干擾排序、公開狀態、更多操作等功能。

### 閱讀頁

- Hero Card / Well Card 進一步轉成章節封面與紙面，而不是兩張有厚重 chrome 的 panel。
- 已定案的 fixed bottom toolbar、閱讀進度數字、章節切換、目錄／書籤與閱讀設定都保留。
- 內文區不使用光暈或高彩裝飾；閱讀設定仍掌管字體、字級、行距與閱讀表面。

## 對現有程式架構的衝擊

現有主題架構已有 `storytellerTheme.ts`、`storytellerSemanticTheme.ts`、`storytellerComponentOverrides.ts`，而 shared shell、project card、top bar 也已有共用層。這使得「加一個視覺 preset」比「逐頁重寫 CSS」更合適。

| 衝擊 | 範圍                                                                                      | 說明                                                                                                                  |
| ---- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 低   | semantic tokens、CSS variables、背景、字體層級、reduced motion                            | 可在既有主題管線擴充，不改資料流或 API。                                                                              |
| 中   | `StorytellerLayout`、`StorytellerShell`、AppBar、shared project/work cards、panel top bar | 共用元件的外觀會一起受影響，需要明確 variant，避免首頁、追蹤頁、工作台互相誤傷。                                      |
| 中高 | 11 palettes × light/dark、seasonal overlay                                                | 若要求每種 palette 都維持完整表現，調校與 regression matrix 會顯著膨脹。                                              |
| 高   | Editor、Reader、fixed dock、popover / drawer / selection menu                             | z-index、scroll container、mobile viewport、safe-area 與 keyboard interaction 容易出現跨頁 regression，應分階段處理。 |

### 不應該做的事

- 不為了視覺更新重寫 API、route、project data model 或 reading preferences。
- 不直接覆寫所有 MUI 元件，使非 Storyteller 頁面也被迫跟著改。
- 不在第一階段把每一張舊 card 個別重畫；先收斂 shared variants。
- 不讓 animated glow、blur 或背景網格進入長文閱讀區與 editor content area。
- 不一次移除 classic 樣式；提案尚未確定會採用，應保留快速比較與回退能力。

## 建議實作順序

1. **Preset 與 tokens**：新增 `classic | atelier` feature flag／本機偏好，只建立 light/dark semantic tokens、字體與 motion 規範。
2. **全站 shell**：header、頁面背景、breadcrumb、shared panel primitives；不碰頁面功能。
3. **共用內容卡**：project / work / search card 收斂為共同 anatomy，加上 context actions variant。
4. **公開頁面**：首頁、探索、追蹤頁先套用，驗證品牌方向和效能。
5. **工作台**：沿用既有資訊架構，替換 visual surface 與 mobile breakpoint 樣式。
6. **閱讀頁**：調整 hero / paper / fixed dock，和既有 reading preference 一起驗證。
7. **Editor 最後處理**：因 slash menu、selection menu、AI panel 與 editor focus 行為最敏感，應另開一輪專門設計與 regression。

每一階段都可以獨立切回 classic，不需要等整站完成才能發布。

## 驗證重點

- Viewport：320、390、768、1024、1440 px。
- light / dark、`prefers-reduced-motion`、鍵盤 focus、touch target、safe-area。
- shared project card 在首頁、探索、追蹤、工作台各 context 的 CTA 與 menu 是否正確。
- reader fixed dock 不遮蔽內文，進度、章節與書籤在 mobile keyboard / browser chrome 變化時仍可用。
- editor 的 selection toolbar、slash menu、AI panel、modal / snackbar z-index。
- 所有主要文字與互動狀態的 contrast；稜光只作 accent，不以顏色單獨傳達狀態。
- 背景 texture、blur、font load 對 LCP、scroll 與低階手機 GPU 的影響。

## 這份提案的邊界

Mockup 用三個代表頁驗證視覺語言與層級，沒有重新定義所有產品流程，也沒有主張必須實作。若方向成立，下一步才需要整理實際 component inventory、token mapping 與逐頁 rollout checklist；如果不採用，這個 branch 可以直接捨棄，不會影響正式 frontend source。
