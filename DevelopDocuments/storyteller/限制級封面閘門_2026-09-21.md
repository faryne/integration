# 限制級專案的封面閘門

> 狀態：**已實作（純前端）**，2026-09-21。branch：`fix/restricted-cover-gate`

## 問題

專案封面（`cover_url`，見 `專案封面圖_2026-09-21.md`）會出現在專案卡片（首頁、我的追蹤、作者頁、搜尋）與閱讀頁。限制級（`rating = restricted`）專案的封面如果在讀者沒確認過年齡前就顯示，等於繞過了站上既有的年齡確認閘門。

## 決策

**規則：限制級專案要有年齡確認 cookie（`nekomaid_r18_confirmed=1`）才顯示封面，沒有就顯示原本的裝飾造型。純前端判斷，後端完全不處理。**

- API 照常回傳 `cover_url` 與 `cover_asset_public_id`，不因評級或 cookie 省略欄位。
- 前端用同一個 hook 決定要不要拿封面去渲染，所有顯示封面的地方共用。

### 已知取捨（使用者知情並接受）

- 直接呼叫 API 的人仍拿得到簽名 URL；這個閘門只保證**網站介面**在未確認年齡時不會顯示限制級封面，不是安全邊界（年齡確認本身就是讀者自我聲明的 cookie，與既有閘門同等信任）。
- 因為純看 cookie，**專案擁有者也一樣**：作者沒確認過年齡時，工作台卡片看不到自己限制級專案的封面。編輯專案頁的封面預覽不套用閘門（那是設定封面用的），永遠看得到。

### 曾經評估、未採用的方案

- 後端在輸出時省略限制級封面欄位（前端另帶 `X-Age-Confirmed` 標頭補足本機跨埠讀不到 cookie 的問題）。優點是 API 層也擋得住；缺點是要改後端多個輸出點、前端要 invalidate 快取、本機還要標頭備援。使用者判斷不需要，採用純前端。

## 實作

- `static_site/src/helpers/storytellerCover.ts`：`useGatedCoverUrl(coverUrl, rating)`，內部用既有的 `useAgeConfirmed()`（`helpers/ageConfirmation.ts`）。按下「我已滿 18 歲」後 cookie 寫入並派發 `faryne:age-confirmed`，hook 會即時更新，**不必重新整理頁面**封面就出現；清掉 cookie 後又隱藏。
- 套用位置：`StorytellerProjectCard.tsx`、`StorytellerProjectSearchCard.tsx`（搜尋結果有 `rating` 欄位）、`Reader.tsx`（標題區塊背景、固定 header 背景、作品資訊浮層縮圖，三者都吃同一個過濾後的 `coverUrl`）。
- 不套用：`StorytellerProjectCoverEditor.tsx`（編輯頁預覽）。

## 驗證（本機）

- 匿名 API 對限制級與一般專案都仍回 `cover_url`。
- 首頁卡片：無 cookie 時一般專案有封面、限制級只有裝飾菱形；設 cookie 並派發事件後**不重整**限制級封面立刻出現；清 cookie 後消失。
- 閱讀頁：年齡閘門確認前沒有封面，確認後出現。
- **搜尋卡片未在畫面上驗證**（本機沒有搜尋服務，測試專案不在索引裡）；邏輯與專案卡片同一個 hook，型別檢查通過。
