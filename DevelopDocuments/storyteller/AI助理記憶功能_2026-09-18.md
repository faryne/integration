# AI 助理記憶功能

- 狀態：**已實作，待 migration 套用與部署**
- 目前範圍：以單人使用為主；協作者共享與 RBAC 暫不納入

## 目的

梭梭目前可從一輪已完成的 AI 助理對話中，整理出一筆原子、可長期使用的記憶候選。候選不會自動生效，必須由使用者確認，後續對話才會依目前 project/story/lore context 自動載入。

目前不做專案層的獨立助理聊天介面；現有 story/lore 編輯頁助理會合併讀取 project → current story/lore 記憶。帳戶層記憶暫不開放建立或讀取，避免跨專案污染且沒有統一管理入口。

## 2026-09-26 調整概要

- **導覽與搜尋**：將「梭梭的記憶」移到工作台主要導覽，與作品、設定、資產同級。文字搜尋統一由工作台搜尋處理，搜尋範圍包含記憶名稱、內容與 tags，點擊結果可直接進入管理頁並定位該筆記憶。
- **管理頁篩選**：移除記憶管理頁內重複的文字搜尋框；scope、kind、釘選狀態改為 filter chips，tags 也可直接點選篩選，讓管理頁專注在瀏覽、分類與維護。
- **Scope 收斂**：現階段停用 account scope，生成、讀取、寫入、管理介面與 MCP 僅接受 project/story/lore。既有 account scope 資料不會被載入 AI context，也不提供管理入口。
- **分類方式**：`kind` 維持固定分類，避免模型與查詢語意漂移；另加入自由 `tags`，由模型先建議、使用者可修改，供管理、搜尋及其他 AI 判讀使用。
- **多輪整理構想**：目前仍以使用者點選的一輪已完成對話產生記憶。後續預計讓使用者以該輪為焦點，自由選擇向前與向後各納入 N 輪；焦點輪是記憶來源，鄰近輪只提供語境，最新一輪的向後數量固定為 0。介面必須明確標示實際納入範圍，避免使用者誤以為整段對話都會寫入記憶。此項尚未實作，待互動方式確認後再進行。

## 資料模型

主表為 `storyteller_assistant_memories`，來源關聯表為 `storyteller_assistant_memory_sources`。

### Scope

| `scope_type` | 目標欄位 | 語意 |
|---|---|---|
| `project` | 只有 `project_id` | 目前專案 |
| `story` | 只有 `story_id` | 指定故事 |
| `lore` | 只有 `lore_id` | 指定設定 |

`public_id` 只是記憶本身的穩定識別碼，scope 與目標仍由上述欄位判定。所有讀寫皆以 `user_id` 隔離；這一階段不共享協作者記憶。

### 狀態

- `in_progress`：背景整理中。
- `completed`：模型已產生候選，尚未經使用者確認。
- `failed`：生成失敗，前端可以原對話重試。
- `confirmed`：已確認，可注入後續 AI context。

只有 `confirmed` 且未被 soft delete、未被新版取代的記憶會被讀取。過期留在 `in_progress` 的孤兒草稿會在輪詢時轉成 `failed`；每日排程會先 soft delete 超過 7 天的未確認草稿，再實體清除進入垃圾區超過 30 天的未確認草稿，處理使用者直接關閉分頁並避免資料無限累積。`confirmed` 記憶不會進入這兩個清理條件。

### 內容與稽核

- `kind`：`preference` / `instruction` / `decision` / `context`。
- `tags`：最多 8 個自由標籤，每個最多 24 字；模型先建議，使用者可編輯，後續會隨記憶提供給 AI 作為判讀方向。
- `priority`：0–100，用於讀取排序。
- `is_pinned`：釘選後不允許模型自動取代。
- `supersedes_public_id`：候選建議取代的舊記憶；確認時會再檢查 user、scope、target 與 pinned 狀態，並在同一 transaction 內寫入舊記憶的 `superseded_by_id`。模型建議了無效目標時只會放棄取代、保留候選；使用者也可在確認畫面選擇「不取代，另存一筆」。
- 相同 scope 內的內容會先正規化空白與大小寫，阻擋明顯重複記憶。
- 生成用的 provider key、model、input/output tokens 會保留在記憶資料，同時寫入 `storyteller_agent_usage_logs` 納入既有用量統計。

## 操作流程

1. 使用者從一則已完成的助理回覆點「整理成記憶」。
2. 後端建立 `in_progress` 草稿，以 graceful-shutdown tracked background work 呼叫 provider；前端每秒輪詢。
3. 模型只回傳 XML 候選，包含 `ShouldRemember`、名稱、內容、scope、kind、tags、priority 與可選的 `SupersedesPublicID`。
4. 使用者可編輯內容、scope、kind、tags、priority 與 pinned 狀態；確認後才轉為 `confirmed`。
5. 失敗草稿可原對話重試；AI 面板的記憶按鈕會帶目前 story/lore context 前往工作台管理頁，左側導覽也把「梭梭的記憶」列為與作品、設定、資產同級的主要區域。
6. 文字搜尋統一使用工作台搜尋，結果可直接定位記憶；管理頁本身使用 filter chips 篩選 scope、kind、釘選狀態及點選 tags，並提供分頁。單筆編輯及刪除確認才使用 modal。

## HTTP API

- `GET /storyteller/projects/:project/search`：工作台統一搜尋，結果包含作品、設定、資產與記憶。
- `GET /storyteller/projects/:project/memories`：列出當前 context 有效記憶。
- `GET /storyteller/projects/:project/memories/manage`：完整管理頁的分頁與篩選查詢；可選擇限制為目前 story/lore context，或以 `memory_public_id` 定位工作台搜尋帶入的記憶。
- `GET /storyteller/projects/:project/memories/search`：依名稱、內容或 tags 關鍵字搜尋。
- `PUT /storyteller/projects/:project/memories/:memory`：編輯或釘選記憶。
- `DELETE /storyteller/memories/:memory`：soft delete 已確認記憶。
- `POST /storyteller/agent-chats/:chat/memory-drafts`：非同步產生候選。
- `GET /storyteller/memory-drafts/:memory`：輪詢候選狀態。
- `POST /storyteller/memory-drafts/:memory/retry`：重試失敗草稿。
- `POST /storyteller/memory-drafts/:memory/confirm`：確認並激活候選。
- `DELETE /storyteller/memory-drafts/:memory`：捨棄未確認候選。

## MCP tools

- `storyteller_list_memories`：依 project 與可選 story/lore context 列出有效記憶。
- `storyteller_search_memories`：在同一有效 context 內搜尋名稱、內容或 tags；於 AI 助理中也是 read-only tool。
- `storyteller_upsert_memory`：MCP-only 寫入工具。未帶 `memory_public_id` 時是新增，必須帶 scope、kind 與 content，可選擇 tags，priority 預設 50；帶 ID 時僅更新有傳入的欄位，ID 不存在會直接回傳 not found，也不允許把別的 context 或已被取代的記憶搬入。

## 安全與界線

- 所有記憶查詢與修改均限當前 authenticated user。
- story/lore public ID 必須先在指定 project 內解析，不允許跨專案讀取。
- MCP upsert 必須帶 `project_public_id` 作為當次授權邊界，且只接受 project/story/lore scope。
- 記憶讀取失敗時會記錄 warning 並降級成本次不帶記憶，不會讓 AI 助理整體停擺。
- 整理 prompt 明確排除密碼、金鑰、token、個資、一次性狀態與未確認推測；最終仍由使用者確認才寫入有效記憶。

## 暫不處理

- 協作者共享與 RBAC：現有多人協作機制還需重新理順，目前不讓記憶功能依賴它。
- 自動無審核寫入：為避免誤記與 prompt injection 直接變成長期狀態，Web 介面仍保留人工確認。
- 前後 N 輪對話整理：方向已記錄於調整概要，待確認選取範圍的互動後再實作；目前維持單輪整理。
