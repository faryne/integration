# MCP 連接頁改版：先選 AI 服務

- 狀態：已實作（`feature/storyteller-mcp-connect-redesign`）
- 驗證：本機假登入走過 faryne.dev 模式（只有 PAT，Claude.ai／ChatGPT 反灰）：選 Claude Code 自動帶入 PAT 並說明原因、當場建立 token 並帶入設定指令、換 Codex 時 token 清掉；Skill 一行安裝指令、其他服務的雙下載、預覽讀後端 v2.1.0；375px 無橫向捲動。curl 實測 skill.md／skill.zip（`steamloom/SKILL.md`）。steamloom.works 的 OAuth 分支本機無法呈現（網域判斷），部署後要實際點一次
- 實作與規格差異：Skill 網址改掛在 `/storyteller-mcp/` 底下（見下方已知 Bug 記錄）；Skill 的連線位址一律寫 steamloom.works；skill.md 也用 attachment，瀏覽器點下載不會直接開內容；原本給前端組 SKILL.md 的 `GET /storyteller/mcp/tools` 已移除
- Mockup：`mcp-connect-mockup/index.html`
- 範圍：「開發者 › MCP 連接」頁（`McpPanel.tsx` 與兩個設定視窗）、Skill 下載

## 問題

1. 第一步就要作者選「OAuth 還是 PAT」，但作者只知道自己用的是 Claude 還是 ChatGPT，不知道這兩個詞代表什麼。
2. 選完授權方式後，設定視窗裡還要再選一次工具，同一件事問兩次。
3. 安裝 Skill 只有一顆「下載 SKILL.md」：
   - Claude.ai 只收 ZIP（裡面要有 `steamloom/SKILL.md` 資料夾），現在給的檔案傳不上去
   - Claude Code／Codex 沒寫要放哪個目錄
   - SKILL.md 是瀏覽器即時產生的，沒有網址，沒辦法寫成一行安裝指令

## 新流程

| 步驟 | 內容 |
|------|------|
| 1. 選擇 AI 服務 | Claude.ai／ChatGPT／Claude Code／Codex／其他，五張卡片 |
| 2. 選擇授權方式 | 只列出這個服務支援的方式。只支援一種時直接帶入，並說明原因 |
| 3. 連線設定 | 依「服務×授權」顯示對應步驟與指令，直接在頁面上操作，不再開視窗。PAT 在這一步當場建立 token |
| 4. 安裝 Skill（選用） | 依服務顯示安裝方式 |

選了服務之後，後面的步驟才展開；換服務時，步驟 2～4 跟著重算。

### 服務 × 授權方式

| 服務 | OAuth | PAT | 說明 |
|------|-------|-----|------|
| Claude.ai | ✅ | — | 自訂 connector 只能用 OAuth，不能自己加 header |
| ChatGPT | ✅ | — | 同上（開發者模式的 connector） |
| Claude Code | ✅ 推薦 | ✅ | PAT 用 `--header "Authorization: Bearer …"` |
| Codex | ✅ 推薦 | ✅ | PAT 用 `config.toml` 的 `bearer_token_env_var` |
| 其他 | ✅ | ✅ | OAuth 要工具支援自動註冊；不支援就用 PAT（JSON 設定） |

**faryne.dev 網域**：OAuth 只在 steamloom.works 開放。在 faryne.dev 上，Claude.ai／ChatGPT 的卡片顯示「請到 steamloom.works 設定」，其他服務只列 PAT。

### 安裝 Skill

| 服務 | 方式 |
|------|------|
| Claude Code | 一行指令：`mkdir -p ~/.claude/skills/steamloom && curl -fsSL <skill.md 網址> -o ~/.claude/skills/steamloom/SKILL.md`。會自動偵測，不用重啟 |
| Codex | 同一行，路徑換成 `~/.agents/skills/steamloom/`（Codex 官方文件目前的路徑） |
| Claude.ai | 「下載 ZIP」按鈕＋步驟：先到「設定 › 功能」開啟「程式碼執行與檔案建立」→「自訂 › 技能」→「＋」→「上傳技能」 |
| ChatGPT | 跟 Claude.ai 一樣用 ZIP：ChatGPT 有 Skills 功能，可以從電腦上傳（官方說明是 Create → Upload from your computer，接受資料夾或 ZIP）。**確切的選單位置與方案限制，官方說明頁（help.openai.com 20001066）擋自動讀取，實作時要人工對照一次** |
| 其他 | 下載 SKILL.md／ZIP，依工具放進它的 skill 目錄 |

每個服務都保留「預覽內容」，並顯示目前版本。指令旁邊註明「Skill 更新時，再執行一次同一行指令即可」。

### Skill 名稱與舊版遷移

- 對外品牌統一用 SteamLoom：skill 名稱（frontmatter 的 `name`）與資料夾名稱從 `storyteller-mcp` 改成 **`steamloom`**，跟 MCP server 名稱一致。Claude.ai 要求兩者相同，ZIP 裡的資料夾也是 `steamloom/`。
- 之前裝過 v2.0.0 以前版本的作者，舊的 `storyteller-mcp` 資料夾還在，新舊兩份會同時載入。安裝區塊下方提示一行：「之前裝過 `storyteller-mcp` 的話，請刪掉那個資料夾」，並附上刪除指令（Claude Code：`rm -rf ~/.claude/skills/storyteller-mcp`；Claude.ai／ChatGPT：在技能列表移除舊的那個）。
- 這次改名算 Skill 的版本更新，版本號跟著升（v2.1.0）。

## 後端：提供 Skill 的公開網址

- `GET /storyteller-mcp/skill.md`：SKILL.md 本體（`text/markdown; charset=utf-8`）
- `GET /storyteller-mcp/skill.zip`：內含 `steamloom/SKILL.md`（Claude.ai 要求資料夾名稱跟 skill 名稱相同）
- 對外網址：steamloom.works 是 `https://steamloom.works/mcp/skill.md`（nginx 的 `location /mcp` 把整個前綴改寫成 `/storyteller-mcp`）；faryne.dev 是 `https://faryne.dev/api-integration/storyteller-mcp/skill.md`。兩個網域都**不用改 nginx**
- 不需登入；內容不含任何憑證
- **Skill 內文從前端 `storytellerMcpSkillDoc.ts` 搬到後端產生**（Go 的 `embed` 讀一份 markdown 範本，再把工具清單、MCP 位址、版本填進去）。前端的預覽改成讀 `skill.md`，前後端只剩一份內容，不會不一致
- 版本號與更新日期跟著搬到後端；前端顯示的版本從 API 回應讀（`skill.md` 的 frontmatter 或另一個欄位）

## 常見 fail 與應對

| 情境 | 應對 |
|------|------|
| 作者用的服務不在清單裡 | 選「其他」：先試 OAuth，工具要手動填 Client ID 就改用 PAT（沿用現在的說明） |
| curl 指令在 Windows 跑不了 | 指令區塊下方提供「或手動下載 SKILL.md，放到 `%USERPROFILE%\.claude\skills\steamloom\`」 |
| Claude.ai 上傳失敗（資料夾名稱不符、沒開程式碼執行） | ZIP 由後端固定產生正確的資料夾名稱；步驟裡把「先開程式碼執行」放第一步 |
| 各工具的指令或路徑改版 | 全部集中在 `mcpClientSetup.ts`，每筆註明對照的官方文件 |
| 後端 skill.md 掛了 | 預覽與下載按鈕顯示錯誤 Snackbar；不影響連線設定的步驟 |
| 作者換服務後，已建立的 PAT | PAT 已經存在後端，頁面只是不再顯示；可以到 Personal Access Token 頁管理或撤銷 |

## 不做

- 自動偵測作者用的服務
- 一鍵安裝（例如 `claude://` 之類的協定連結）

## 已知 Bug 記錄

### 1. steamloom.works 上的 Skill 網址打不開（2026-10-04）

- **現象**：MCP 連接頁顯示的 `https://steamloom.works/api-integration/storyteller/mcp/skill.zip` 下載到的是前端首頁的 HTML，curl 一行安裝也會裝到 HTML。
- **Root cause**：steamloom.works 的 nginx 只有 `location /mcp`（改寫成 `/storyteller-mcp`）和 OAuth 相關路徑會轉給後端，**沒有 `/api-integration/`**（那是 faryne.dev 才有），其他路徑一律交給前端 SPA，回 200 加首頁 HTML。規劃時我只用 curl 看了狀態碼 200，沒檢查內容是 HTML，誤判成這條路徑會轉發到後端。
- **解法**：後端路由改成 `GET /storyteller-mcp/skill.md`、`/storyteller-mcp/skill.zip`（`route/storyteller_mcp.go`，handler 在 `controller/storytellermcp/skill.go`），對外網址變成 `https://steamloom.works/mcp/skill.md`；前端 `mcpClientSetup.ts` 依網域組網址。
- **教訓**：驗證反向代理路徑時，要看回應的 Content-Type 和內容，不能只看狀態碼。
- **狀態**：已修正（`fix/storyteller-mcp-skill-url`），待部署後在正式站確認。
