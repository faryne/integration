# Storyteller 稽核紀錄 UI Mockup 提案

## 本次範圍

這一版只有可直接開啟的靜態 mockup，用假資料確認資訊架構與互動方向；沒有實作 P3 API、React route、資料查詢或 P4 封存工作。

以瀏覽器開啟 `index.html` 後，可從頂部控制列切換：

- 專案稽核
- 封存查詢
- 帳號活動
- 載入／空白／API 錯誤狀態
- Desktop／Mobile 390px
- 深色／淺色模式

## 畫面與位置

### 1. 專案稽核頁

位置：專案 workspace 左側欄，在「梭梭的記憶」下方新增「稽核紀錄」。

理由：這一頁查的是單一專案的事件，且只有 project owner 可見；放在專案 workspace 才能沿用目前專案選擇、sidebar 與權限邊界，不會跟帳號層的登入／憑證事件混在一起。

畫面內容：

- 中文 breadcrumb：`Steamloom > 我的工作台 > 霧港殘響 > 稽核紀錄`。
- 「近期／封存」切換；預設近期。
- 非同步寫入提示：「最近幾秒的事件可能尚未出現」。
- 操作者、類別、入口、結果、時間範圍等 chip filters。
- 時間軸顯示時間、操作者、中文動作、目標、入口、PAT 標籤與結果。
- PAT 讀取、social／bookmark 為低重要度，預設隱藏；使用者可用 toggle 展開。
- 同一 actor、同一 target、短時間連續的 `story.update` 自動儲存合併成一列；展開後仍能看到各版本與時間。
- 點事件後開啟右側 detail drawer。Mobile 版改成內容上方的詳情面板，避免水平擠壓。

事件詳情用四種摘要確認資訊密度：

- `project.update`：allowlist 欄位的 before／after diff。
- `story.update`、`lore.update`：只顯示 version public ID，不顯示本文。
- `agent.run`：chat ID、provider、model、input/output tokens，不顯示 prompt／response。
- `denied`／`failed`：HTTP status、custom code、error category，不顯示 request body 或錯誤訊息。
- 共通欄位：IP、User-Agent、request ID、source、auth method、credential label。

### 2. 封存模式

位置：與專案近期稽核同頁，由右上方 mode switch 切換，不做跨 MySQL／Athena 的混合列表。

互動流程：

1. 月份選擇器只允許 3 個月以前的完整月份；mockup 以 2026-09-27 為基準，最大值為 2026-06。
2. 送出後顯示 `queued`，再由 polling 更新為 `running`。
3. 完成後顯示結果 table 與 pagination；結果列仍可在實作時開啟同一套 event detail。
4. 失敗時顯示 job error category 與可採取的動作，不回傳 Athena 原始錯誤。
5. 超過預設 7 年保存期限的月份標示「已超過保存期限並已刪除」，不可送出查詢。

在 mockup 內按「送出查詢」會自動演示 `queued → running → results`；點 `2018 / 03` 會顯示已刪除狀態。上方「Mockup 狀態」按鈕可直接檢查 queued、running、results 與 failed，正式實作時改由 job status 觸發。

### 3. 帳號活動頁

位置：`我的工作台 > 帳號與安全 > 帳號活動`，在左側欄獨立為「帳號與安全」群組；頁首提供「前往 MCP 與 PAT 管理」，讓憑證管理與追查互相導流。

理由：PAT 目前在 MCP 連接頁、provider keys 在金鑰管理頁。把帳號活動放進同一個 account workspace，既靠近兩者又不硬塞進任一管理表單；登入／登出與 profile 類事件也有合理歸屬。

內容包括：

- `auth.login`、`auth.login.failed`、`auth.logout`。
- `pat.create`、`pat.revoke`、`auth.pat.denied`，包含已知 owner 的過期 PAT 嘗試。
- `provider_key.create|update|delete|test`。
- IP 與 User-Agent 直接顯示，符合事後安全追查需求。
- PAT chip filter 可篩出該 PAT 的 read／write／denied 事件，回答「這支 PAT 讀了什麼、改了什麼」。

### 4. 系統狀態

- Loading：保留頁面骨架，避免 layout shift。
- Empty：說明目前篩選沒有結果，提供清除篩選。
- API error：頁面內保留可重試狀態，並依 `AGENTS.md` 顯示 SNACK；SNACK 不直接回顯後端錯誤內容。
- Mobile：390px 控制模式與 `@media (max-width: 400px)` 都可檢查；sidebar 收進未實作的導覽按鈕、filter chips 可橫向捲動、table 可橫向捲動。

## 建議的 P3 API

以下路徑與欄位是供下一階段確認的 contract 草案；所有識別值對 frontend 使用 public ID，內部 numeric ID 不外露。

### 近期專案事件

`GET /storyteller/projects/:project_public_id/audit-events`

Query params：

| 參數 | 型別／範例 | 說明 |
|---|---|---|
| `cursor` | opaque string | 第一頁省略；依 `(occurred_at, id)` 做 keyset pagination |
| `limit` | `1..100`，預設 `50` | 每頁筆數 |
| `actor_user_public_id` | string | 操作者 |
| `category` | `story,lore,agent,...` | registry category，可重複傳入 |
| `source` | `web,mcp,api,cron` | 可重複傳入 |
| `outcome` | `success,denied,failed` | 可重複傳入 |
| `credential_ref` | PAT public ID | 依 PAT 篩選 |
| `from` / `to` | RFC 3339 | 限定近 3 個月；含更早時間時回 `archive_required` |
| `include_low_importance` | boolean，預設 `false` | PAT reads 與 social／bookmark |

Response：

```json
{
  "data": [
    {
      "event_id": "01K6Q...",
      "occurred_at": "2026-09-27T14:32:48.123456+08:00",
      "actor": { "type": "user", "public_id": "usr_...", "display_name": "Faryne" },
      "source": "web",
      "auth_method": "session",
      "credential": null,
      "action": "story.update",
      "category": "story",
      "importance": "normal",
      "action_label": "更新作品",
      "target": { "type": "story", "public_id": "story_...", "name": "霧醒・第三章" },
      "outcome": "success",
      "summary": { "version_public_id": "ver_..." },
      "ip": "203.0.113.18",
      "user_agent": "Chrome 129 / macOS 15.1",
      "request_id": "req_..."
    }
  ],
  "page": { "next_cursor": "opaque", "has_more": true },
  "meta": { "hot_from": "2026-06-27T00:00:00+08:00", "write_delay_seconds": 5 }
}
```

`credential` 建議只回 `{ "public_id": "pat_...", "label": "Codex 桌機" }`。若 PAT 已撤銷仍使用事件中保存的 public ID，label 找不到時顯示「已撤銷的 PAT」。`summary` 依 action registry 的 allowlist shape 回傳，不提供任意 JSON 展開。

### 帳號活動

`GET /storyteller/account/audit-events`

使用與專案事件相同的 `cursor`、`limit`、`category`、`source`、`outcome`、`credential_ref`、`from`、`to`、`include_low_importance`。後端固定以登入者的 `actor_user_id` 查詢，不接受其他 user ID。

帳號頁若選定 PAT，應同時回傳該 PAT 的帳號層事件及專案 read／write 事件；專案 target 只能顯示使用者在事件發生時／查詢時有權看到的名稱。若避免歷史名稱造成越權，第一版可只回 target public ID 與目前仍可見的名稱。

### Filter options

建議不要讓 frontend 自己從當頁 50 筆推算完整選項：

- `GET /storyteller/projects/:project_public_id/audit-event-filters`
- `GET /storyteller/account/audit-event-filters`

Response：

```json
{
  "actors": [{ "public_id": "usr_...", "display_name": "Faryne" }],
  "categories": [{ "value": "story", "label": "作品" }],
  "credentials": [{ "public_id": "pat_...", "label": "Codex 桌機", "revoked": false }],
  "sources": ["web", "mcp", "api", "cron"],
  "outcomes": ["success", "denied", "failed"]
}
```

## 建議的 P4 API

### 可用／已刪除月份

`GET /storyteller/projects/:project_public_id/audit-archive-months`

```json
{
  "months": [
    { "month": "2026-05", "status": "available", "event_count": 381 },
    { "month": "2018-03", "status": "purged", "purged_at": "2025-04-01T02:00:00Z" }
  ],
  "retention_years": 7,
  "latest_archive_month": "2026-06"
}
```

### 建立封存查詢 job

`POST /storyteller/projects/:project_public_id/audit-archive-queries`

Request：

```json
{
  "month_from": "2026-03",
  "month_to": "2026-05",
  "filters": {
    "actor_user_public_id": "usr_...",
    "categories": ["story", "lore"],
    "sources": ["web", "mcp"],
    "outcomes": ["success"],
    "credential_ref": "pat_...",
    "include_low_importance": false
  }
}
```

Response `202 Accepted`：

```json
{
  "query_public_id": "aq_01K6QX...",
  "status": "queued",
  "poll_after_ms": 3000,
  "created_at": "2026-09-27T15:07:00+08:00"
}
```

後端驗證：月份必須早於 hot boundary、不得包含 `purged` 月份、限制最大月份跨度；project ID 與 owner 條件由後端強制加入 Athena parameterized query。Frontend 不取得 Athena execution ID。

### 輪詢 job

`GET /storyteller/audit-archive-queries/:query_public_id`

```json
{
  "query_public_id": "aq_01K6QX...",
  "status": "running",
  "filters": { "month_from": "2026-03", "month_to": "2026-05" },
  "poll_after_ms": 3000,
  "result_count": null,
  "error": null,
  "created_at": "2026-09-27T15:07:00+08:00",
  "completed_at": null
}
```

狀態：`queued | running | succeeded | failed | expired`。`error` 只回 `{ "category": "query_scan_limit", "retryable": true }` 等 allowlist，不回 Athena 原始錯誤。

### 取得封存結果

`GET /storyteller/audit-archive-queries/:query_public_id/results?cursor=<opaque>&limit=50`

只有 job owner 可取；未完成回 `409 query_not_ready`。事件欄位與 P3 recent API 相同，pagination 使用後端封裝的 Athena `NextToken`，不把原始 token 暴露成可跨 job 重用的憑證。Response：

```json
{
  "data": [],
  "page": { "next_cursor": "opaque", "has_more": false },
  "meta": { "query_public_id": "aq_01K6QX...", "scanned_bytes": 5033165 }
}
```

帳號活動若 P4 也需要查超過 3 個月，建議使用同一個 job model，另加 `POST /storyteller/account/audit-archive-queries`，由 route 決定 scope，不接受 client 傳任意 `actor_user_id`。

## 建議的前端顯示規則

- 日期依使用者瀏覽器時區顯示，detail 同時保留完整 timestamp。
- Grouping 只發生在 frontend 顯示層：相鄰 `story.update`、actor／target 相同、時間差不超過 2 分鐘、outcome 相同才合併。pagination 邊界不要跨頁合併，避免 cursor 行為不穩定。
- `denied`／`failed` 不跟 success 合併。
- 中文 action label 由 frontend 固定 mapping 或 API 版本化欄位提供；不要直接把 action 字串用 `.` 拆成 UI 文案。
- actor 或 target 已刪除時，以事件保存的 public ID 配合「已刪除」顯示；不要因 join 不到就移除事件。
- drawer 預設只顯示 allowlist summary；未知欄位忽略，不做通用 JSON viewer。

## 待確認問題

1. 「稽核紀錄」放在「梭梭的記憶」正下方是否合適，還是要放到下方「專案操作」群組？本提案建議前者，因為它是內容查詢頁，不是一次性操作。
2. 帳號活動要新增獨立「帳號與安全」群組，或併入「我的檔案」？本提案建議獨立群組，讓 PAT／provider key 的安全追查更容易找到。
3. 自動儲存合併時間窗是否接受 2 分鐘？規格只寫「短時間」，mockup 先用 2 分鐘。
4. 近期列表的預設時間範圍要用 24 小時、7 天，還是直接顯示最近 50 筆？Mockup 選 24 小時以凸顯時間 filter。
5. 帳號活動頁是否也要在 P4 首版提供封存模式？規格明確要求專案頁近期／封存；帳號頁未明定。本提案保留共用 job API 的延伸方式，但 mockup 暫不放 mode switch。
6. Archive job 的最大月份跨度建議設多少（例如 12 個月）？這會影響 Athena 成本、掃描上限與 UI 驗證訊息。
7. 封存結果點擊事件時，是否需要與近期完全相同的 drawer，或先只做 table？本提案建議共用 drawer，避免兩套摘要規則。

## 使用者確認結果（2026-09-27）

7 個待確認問題全部採用本提案建議，唯一調整：

1. 「稽核紀錄」放在「梭梭的記憶」正下方。
2. 帳號活動獨立為「帳號與安全」群組。
3. 自動儲存合併時間窗改為 **5 分鐘**（原提案 2 分鐘）。
4. 近期列表預設時間範圍為最近 24 小時。
5. 帳號活動頁 P4 首版不做封存模式，但 API 保留共用 job model 的延伸方式。
6. 封存查詢最大月份跨度 12 個月。
7. 封存結果點擊事件時與近期共用同一個詳情面板。

實作時一併修正 mockup review 發現的三點：封存模式不顯示「最近幾秒的事件可能尚未出現」提示；`auth.pat.denied` 不顯示無從得知的操作內容（驗證失敗時尚未知道要呼叫哪個 tool）；帳號活動頁不顯示專案層的「Owner」標籤。

## 方向調整（2026-09-27，P3 實作後）

實作完 P3 後重新檢視，**專案稽核頁拿掉**，只保留「帳號與安全 > 活動紀錄」一頁（原本 mockup 的「帳號活動」頁改名並擴大範圍）：

- 協作還沒上線，專案裡的操作只可能是擁有者本人，專案頁的內容等同「本人活動＋專案篩選」，沒有獨立價值。
- 活動紀錄改為顯示**本人的所有事件**（包含網頁上的編輯），新增**專案篩選**。
- mockup 中專案稽核頁的元素（時間軸、自動儲存合併、事件詳情、近期／封存切換、封存查詢流程）全部移到活動紀錄頁沿用；工作台側欄不再有「稽核紀錄」入口。
- 原本「帳號頁 P4 首版不做封存模式」的決議作廢：封存查詢改在活動紀錄頁提供。
- 待協作（RBAC）上線、真的需要「看別人在我的專案做了什麼」時，再依當時需求加回專案層的查詢入口。

詳細的前後對照見 `DevelopDocuments/storyteller/稽核功能提案_2026-09-27.md` 的「方向調整」一節。
- 篩選改成兩層：預設只有時間範圍（最近 24 小時／7 天／30 天／自訂日期）；專案、類別、入口、結果、PAT、低重要度收進預設收合的「進階篩選」，並改用下拉選單（PAT 用可搜尋的下拉），不再整排 chips。入口只留「網頁」與「MCP」。
