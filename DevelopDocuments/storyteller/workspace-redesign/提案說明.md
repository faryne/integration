# Storyteller 工作台 UI/UX 重構提案

- 日期：2026-09-13
- branch：`codex/storyteller-workspace-redesign`
- 基準：`refactor/storyteller-optimized` (`22cbaf9`)
- 狀態：提案已確認，正式工作台第一版已完成

## 結論

這一輪應先解決 mobile 的資訊架構，再整理視覺。核心不是把現有側邊列縮小，而是讓它退出正常 document flow：使用者進入工作台後先看到目前內容，按「導覽」才開啟暫時性的專案導覽 Drawer。

desktop 保留側邊列＋內容區的 split workspace，因為寬螢幕下樹狀導覽確實能提升切換效率；但改成更平、更安靜的工具介面，減少卡片、粗邊框與同時競爭注意力的元素。

## 現況問題

### 1. Mobile 先看到導覽，後看到工作內容

目前 `WorkspaceMobileNav` 直接 render 在內容欄上方，展開的 `WorkspaceSidebar` 會把列表標題與項目推到首屏以下。使用者每次切換分類後仍需重新跨過導覽內容，工作台主次顛倒。

編輯器 route 又因 `showBleedEditor` 不 render mobile navigation，形成兩套規則：列表頁導覽過多，編輯頁則完全沒有專案導覽入口。

### 2. Desktop 與 mobile 共用同一種空間模型

樹狀 sidebar 適合 desktop 的持續可見空間，不適合 390px 寬度的頁面開頭。現在只是在 breakpoint 下把兩欄 Grid 疊成一欄，沒有真正改變導覽模式。

### 3. 視覺仍像後台元件集合

列表、Chip、邊框、底色與操作按鈕的權重太接近，缺少「專案位置 → 分類 → 內容」的清楚層級。這不是換一組更鮮豔的顏色就能改善，應先降低 surface 數量與重複 chrome。

## 提案方向

### 1. 共用 header 不大改

- 保留現有 SteamLoom 全站 header、專案建立、搜尋、外觀設定與帳號入口。
- 工作台改動限制在 `WorkspaceChrome` 以下，避免再次影響首頁與閱讀頁。
- 全站 header 下方保留 workspace context bar，表示目前專案、分類與項目。

### 2. Mobile 改成 content-first

- 預設畫面直接從列表標題／編輯器內容開始，不再把完整 sidebar 插在頁面開頭。
- context bar 左側提供明確的「導覽」按鈕，不使用需要猜測的手勢。
- 點擊後從左側開啟寬度 `min(88vw, 360px)` 的 temporary Drawer；背景加上 scrim，點 scrim、關閉按鈕或 `Esc` 都能離開。
- Drawer 裡保留完整的專案樹：作品與冊、設定集、資產集，以及專案層級操作。
- 在列表與編輯器 route 都能開啟 Drawer；切換項目時仍經過現有 unsaved-change guard。
- 選定分類／項目後 Drawer 自動關閉，將空間立即還給內容。

選擇左側 Drawer 而不是 bottom sheet 的理由：專案樹是深度導覽，使用者會在多個 group 與 collection 間上下掃描；左側 Drawer 與 desktop sidebar 的空間語意一致，也比矮版 bottom sheet 更能容納長清單。

### 3. Desktop 保留 sidebar，但整理成真正的 navigator

- 維持約 268px persistent sidebar，不改變大量內容切換的效率。
- 收合後保留 52px icon rail，不把導覽完全藏掉；按鈕位置保持穩定。
- 專案識別、樹狀分類與專案操作分成三個區域；不再於 sidebar footer 放網站色系等全站設定。
- selected state 使用單一 accent bar＋淡色背景，不同層級不再各自套一張卡片。
- 冊與設定集保留獨立 chevron：點 row 是篩選右欄，點 chevron 才展開話／設定，避免「展開」與「切換頁面」混成同一動作。
- 「全部」與「未分冊／未分類」是虛擬節點，不參與排序；實體冊與設定集才能排序。
- desktop 開啟 group 的排序模式後使用 drag handle；mobile 使用相同的「編輯順序」入口，但顯示明確的上移／下移按鈕，不要求使用者在 Drawer 裡精準拖曳。
- 設定集現有資料與更新 API 已有 `sort`，正式實作只需補齊前端 reorder action，不需要 migration。

### 4. 內容區改為 editorial workspace

- 列表標題是第一視覺層級，項目數降為 eyebrow，新增操作維持單一 primary action。
- 故事與設定集改成平面 rows＋水平 divider，不用每筆資料各包 Paper card。
- desktop 顯示狀態、最後更新與 row action；mobile 保留標題、摘要、狀態與 overflow action，次要日期移除。
- 資產仍使用 thumbnail grid，因圖像辨識比純文字列表有效。
- 公開／草稿色彩只表達狀態，不拿 accent color 裝飾所有 icon、Chip 與邊框。

### 5. 「fashion」的處理邊界

這次不另創一套品牌設計，而是把 SteamLoom 現有的黃銅色系收斂成 editorial tool：

- 大面積使用中性 paper／sidebar surface，黃銅只留給 current selection 與 primary action。
- 減少圓角卡片、厚框與陰影；陰影只用在 floating Drawer。
- 標題使用現有 display serif，操作與 metadata 使用 sans-serif，強化內容／工具分工。
- touch target 保持至少 44px；必要功能不依賴 hover。

### 6. Footer 處理

- 專案工作台是固定高度的 app shell，不在內容尾端 render 一般網站 footer；否則 footer 會與 editor command bar、sidebar footer 形成三層底部區域。
- SteamLoom 品牌、帳號與外觀設定已在全站 header，工作台內不再重複。
- desktop navigator 底部只保留「編輯專案／開啟閱讀頁」等 project-scoped actions；mobile Drawer 使用同一區塊並貼齊 Drawer 底部。
- 離開工作台回到首頁、公開列表或閱讀頁後，仍顯示原本的網站 footer。這不是全站移除 footer，只是 workspace route 不把它當內容的一部分。

## Mockup 可操作項目

- desktop 點 sidebar 邊界箭頭可在 268px navigator 與 52px icon rail 間切換。
- 點作品與冊／設定集／資產集內的項目，可切換右側內容型態與 context trail。
- 點 group heading 可展開／收合該分類。
- 點冊／設定集左側 chevron 可展開子項目；點 group 右側 `⇅` 進入排序模式，再用上移／下移按鈕調整順序。
- 點故事 row 可進入示範編輯器；編輯器仍能從 mobile context bar 開啟導覽。
- mobile 點「導覽」可開啟／關閉 Drawer，選定分類後自動關閉。
- `index.html` 是 responsive 正式 mockup；`mobile.html` 以 390px device frame 直接預覽 mobile 狀態。

## 正式實作對照（2026-09-13）

- `WorkspaceChrome` 新增 mobile 導覽 action slot；列表與 story／image／lore／asset／專案編輯 route 都會顯示「導覽」。
- 新增 `WorkspaceMobileNavigatorDrawer`，寬度為 `min(88vw, 360px)`，共用既有 `WorkspaceSidebar`，選定分類或項目後自動關閉。
- 移除正式頁面原本位於內容上方的 `WorkspaceMobileNav`，390px／430px 首屏直接從內容開始。
- desktop navigator 調整為 268px；收合後留下 52px icon rail，可直接切換作品、設定集與資產集。
- 專案操作固定在 navigator 底部；清單過長時只有中間專案樹捲動，操作不會被推離畫面。
- 冊與設定集新增明確的排序模式；desktop 顯示 drag handle 並使用拖放，mobile Drawer 顯示上移／下移按鈕。「全部」與「未分冊／未分類」不參與排序。
- 設定集排序沿用既有 `sort` 欄位與 update endpoint，沒有新增 migration 或 API。
- 故事與設定列表改為平面 row＋divider；mobile 隱藏次要更新日期，保留標題、字數／頁數、狀態與操作。
- 故事與設定 row 點擊即進入編輯，右側只保留單一 `⋮` overflow action；公開／草稿與所屬冊／分類顯示在標題下方，狀態切換、移動與刪除收進 menu，刪除以 divider 分隔。
- 所有 `/my` 工作台 route 不 render 一般網站 footer；首頁、公開瀏覽與閱讀頁仍保留既有 footer。
- 未修改全站 header、公開閱讀頁、API、URL schema、資料模型與 editor 內容行為。

## 建議正式實作拆分

### Phase 1：Mobile 導覽模式

- `ProjectWorkspacePreview.tsx` 新增 `mobileNavigatorOpen`，由 context bar 控制 temporary Drawer。
- 以 `WorkspaceNavigatorDrawer` 取代 inline `WorkspaceMobileNav`。
- `WorkspaceSidebar` 的 tree content 繼續共用，不讓 desktop／mobile 各維護一份資料邏輯。
- 移除 `isMobile && !showBleedEditor` 的例外：mobile list 與 editor 都使用同一個導覽入口。
- 切換 route 前沿用 `guardedNavigate`，不繞過未儲存確認。

### Phase 2：Workspace chrome 與 desktop sidebar

- `WorkspaceChrome` 增加 mobile navigator action slot，context trail 仍以既有 URL state 產生。
- desktop sidebar 收合狀態改為 icon rail；mobile 不讀取或保存此狀態。
- 專案層級操作固定在 navigator 底部，移除非導覽類功能。
- 冊沿用既有 reorder action；設定集以現有 `sort` 欄位與 update endpoint 補上 reorder action。

### Phase 3：列表視覺

- 重整 `WorkspacePane`、`StoryRow`、`LoreRow` 與 `AssetCard` 的 spacing、divider、mobile metadata。
- 保留現有 pagination、drag reorder、collection chip、row actions、Snackbar 與 confirm dialog。
- 不改任何 API、route、資料模型或編輯器內容行為。

## Review 重點

- 390px 與 430px 下，初始首屏是否直接看到內容而不是專案樹。
- Drawer 是否在 list／story editor／lore editor／image editor／asset editor 都有入口。
- Drawer 切換 route 時是否仍正確觸發未儲存確認。
- 長專案名稱、長 collection 名稱與大量 group item 是否能捲動而不擠壓 footer actions。
- 冊／設定集的 row selection、chevron expansion 與排序模式是否各自獨立，不會誤觸 route 切換。
- desktop 收合 sidebar 後，content width 與 scroll position 是否穩定。
- mobile row 的 overflow action 是否不依賴 hover；44px touch target 是否足夠。
- dark mode 與所有網站色系下 selected／public／draft state 對比是否仍清楚。

## 本提案刻意不做

- 不調整 API、資料模型、URL schema 或 pagination 規則。
- 不重寫 Story／Lore／Image editor。
- 不修改全站 header、閱讀頁或首頁。
- 不新增 dashboard KPI、最近活動、AI 建議等未被需求支持的區塊。
- 不把 mockup 專用的示範資料或控制元件帶進正式 React component。
