# 資產上傳流程改版：Drawer + Dropzone + 即時編輯

## 背景

目前 `StorytellerAssetManager.tsx` 的上傳流程是：點「上傳」→ 選單選「圖像」→ 直接觸發隱藏的 `<input type="file">` 原生選擇器 → 選完檔案後在頁面最上方浮現一小塊上傳進度區塊。整個過程沒有 dropzone、沒有拖曳、選檔前完全看不到任何檔案大小/格式限制提示（只有選錯了才用 SNACK 事後告知），上傳完成後要編輯標題/替代文字/描述還得另外點開一個獨立對話框。

`ImageEpisodeEditor.tsx`（故事 > 圖像作品）已經有一套更完整的體驗：常駐 dropzone（拖曳或點擊選檔、支援批次）、選檔後縮圖清單＋逐張上傳進度、縮圖上可直接編輯每頁描述。這份規格是把資產集的上傳流程改成同等體驗，但**觸發方式不同**：資產集是瀏覽整個素材庫的頁面，不適合像圖像作品頁那樣把 dropzone 常駐在畫面最上方（資產一多，每次瀏覽都要先看過一塊上傳區），改成**點擊「圖像」上傳選項時才跳出一個容器，dropzone 放在容器裡面**。

## 共用元件：抽出 `StorytellerAssetDropzone`

Dropzone 這個 UI 元件（拖曳／點擊選檔的那個虛線框）目前只存在 `ImageEpisodeEditor.tsx` 裡（`ImageEpisodeEditor.tsx:800-833`），這次資產集要新增第二個使用場景。兩邊用途高度相似但**不完全一樣**：目前兩邊剛好都是 image-only、都用同一組 `STORYTELLER_IMAGE_PAGE_MAX_BYTES`/`MAX_COUNT`/`ALLOWED_MIME_TYPES`，但資產集之後有可能先支援其他類型（`資產集.md` 的延後項目提到 audio/video），圖像故事作品頁則可能永遠只收圖片——所以拆出來的元件要讓**接受類型、數量/大小上限、提示文案**都是外部傳入的 props，機制（拖曳/點擊/hover 樣式）共用，規則跟文案不共用。

新增 `static_site/src/pages/storyteller/wysiwygCore/`（或現有共用元件目錄，視專案慣例決定）底下的 `StorytellerAssetDropzone.tsx`：

```tsx
interface StorytellerAssetDropzoneProps {
  accept: string[]; // 例如 STORYTELLER_IMAGE_PAGE_ALLOWED_MIME_TYPES
  multiple?: boolean; // 預設 true
  disabled?: boolean;
  hint: React.ReactNode; // 提示文案完全交給呼叫端，兩邊文案本來就不同（見下方兩處文案）
  onFilesSelected: (files: File[]) => void; // 只負責「使用者選了這些檔案」，不做 mime/size/數量驗證
}
```

**驗證邏輯不放進共用元件裡**——`accept` 只用來設定 `<input accept>` 屬性（瀏覽器層級的初步過濾，不是真正驗證），實際的檔案類型/大小/張數檢查與拒絕訊息（SNACK 文案）繼續留在各自呼叫端（`ImageEpisodeEditor.tsx` 現有的 `addFiles` 邏輯、`StorytellerAssetManager.tsx` 這次新增的 Drawer 邏輯），因為兩邊「超過上限之後要顯示什麼訊息、要不要截斷還是整批拒絕」這類行為本來就可能分岔，共用元件只負責「拖曳/點擊/hover 樣式」這個純 UI 機制，不要把驗證規則也耦合進去。

共用元件內部管理自己的 `dragOver` state 與隱藏的 `<input type="file">`，呼叫端不用自己管這兩件事（跟 `ImageEpisodeEditor.tsx` 現有的 `dragOver`/`fileInputRef` 邏輯相比，這兩塊會被搬進共用元件內部）。

`ImageEpisodeEditor.tsx` 這次要同步改成使用這個共用元件（單純替換，行為不變，文案沿用它原本的「拖曳圖片到這裡，或點擊選擇檔案（可一次選多張，支援批次上傳）」）；`StorytellerAssetManager.tsx` 的新 Drawer 則傳入這次規格要求的新文案（含大小/格式/張數限制那行）。

## 容器形式：Drawer（右側、全高、加寬），不用置中 Modal

理由：上傳完成後要顯示縮圖清單＋逐張進度＋逐張編輯欄位，內容量跟 `ImageEpisodeEditor` 的頁面清單同等級，置中 Modal 通常寬度有限、內容一多會要嘛擠壓要嘛出現內部捲軸疊內部捲軸，體驗差。Drawer 從右側整個高度展開，寬度可以抓大一點（例如 720px，手機版滿版），跟頁面主體並存但給內容足夠空間，這也是這個 repo 其他「批次操作+檢視清單」情境慣用的形式。

## Drawer 內容結構

### 1. Dropzone（頂部，常駐在 Drawer 內，非整個頁面）

使用上面新增的共用元件 `StorytellerAssetDropzone`，`hint` 傳入這次要求的文案，**把大小/格式限制寫進常駐說明文字**，解決現有「事先沒有提示限制」的問題：

```
拖曳圖片到這裡，或點擊選擇檔案（可一次選多張，支援批次上傳）
支援 JPEG／PNG／WebP／GIF，單張檔案 {maxMB}MB 內，一次最多 {maxCount} 張
```

`{maxMB}`／`{maxCount}` 對應現有常數 `STORYTELLER_IMAGE_PAGE_MAX_BYTES`／`STORYTELLER_IMAGE_PAGE_MAX_COUNT`（沿用資產集現有引用的常數，不要另外定義一份新的限制數字）。

### 2. 選檔後：縮圖清單（Dropzone 下方）

比照 `ImageEpisodeEditor` 的頁面清單卡片：每個選中的檔案一張卡片，內容包含：

- 縮圖預覽（`URL.createObjectURL`，跟現有 `ImageEpisodeEditor` 做法一致）。
- 檔名、檔案大小。
- 該檔案的上傳進度條（沿用現有 `uploadProgress` state 的資料結構與 `useUploadStorytellerAssets` 的 `onProgress` callback，只是渲染位置從「頁面上方的獨立進度區塊」搬進這張卡片裡）。
- **編輯 icon**：點開後展開一個小表單，欄位是 `title`／`alt_text`／`description`——跟現有獨立的「編輯 metadata 對話框」欄位完全一樣，這裡只是換個位置，讓使用者不用上傳完再回頭找這個資產編輯。

### 3. 底部：總體進度＋動作區

- 總體上傳進度條（沿用現有 `overallProgress` 計算邏輯，原本渲染在頁面最上方，這次搬進 Drawer 底部）。
- 全部上傳完成後顯示完成狀態（例如「已上傳 3 張」），**不自動關閉 Drawer**——讓使用者可以在完成後從容編輯每張圖的標題/替代文字，關閉交由使用者自己按右上角關閉或 Drawer 遮罩點擊。

## 上傳與編輯的時序

沿用現有「選檔即自動開始上傳」的行為（現有 `handleFilesSelected` 選完檔案就直接進 `uploadPhase: "uploading"`，不用額外按「開始上傳」按鈕），不要多加一道確認步驟。

metadata 編輯欄位在**每個檔案各自的 asset 建立成功（confirm 完成、拿到 `asset_public_id`）之後才能真正送出**——沒有 `asset_public_id` 就沒有東西可以 `update_asset`。UI 上的處理方式：

- 上傳中的卡片，編輯 icon 可以點開輸入（讓使用者不用等上傳完就能先打好文字），但欄位旁標示「上傳完成後才會儲存」；卡片內部用本地 state 暫存輸入值。
- 該檔案對應的 asset 建立成功後，自動把暫存的 `title`/`alt_text`/`description`（如果使用者有填）透過 `useUpdateStorytellerAsset` 送出。
- 如果使用者完全沒填這些欄位，不用送任何 update 請求（維持現有「上傳時不用一定要填 metadata」的行為，metadata 全部留白也合法）。

## 跟現有「編輯 metadata 對話框」的分工

**不移除、不取代**現有針對已存在資產的獨立編輯對話框（在主要資產網格裡點資產卡片開啟的那個）——那個是「事後管理已存在的資產」，這份規格新增的是「上傳當下順手編輯」的捷徑，兩者並存：使用者這次上傳沒編輯的欄位，之後想改一樣回到主網格點開那個既有對話框改，行為不變。

## 不動的部分

- 「取代檔案」（Replace Asset）流程完全不受影響，維持現有的確認對話框＋單檔選擇器，不放進這個新 Drawer。
- 後端完全不用改，這是純前端 UX 重組，沿用既有的 `useUploadStorytellerAssets`／`useUpdateStorytellerAsset` hook，沒有新增或修改任何 API。
- 資產集網格本身（卡片樣式、拖曳到 collection、搜尋、分頁）不受影響。

## 工程難度

中：主要是把現有分散的 state（`uploadProgress`/`uploadPhase`）跟 UI（進度條、隱藏 input）重組進一個新的 `Drawer` 元件，並新增卡片內編輯欄位跟上傳完成後自動呼叫 `useUpdateStorytellerAsset` 的邏輯。不涉及後端或型別定義的大改動。抓 1-2 個工作天等級。
