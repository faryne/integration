# MCP 內容格式驗證

- 狀態：已實作（`feature/storyteller-mcp-content-validation`），含下方 search_replace 的 `$` 修正
- 驗證：單元測試（`content_format_check_test.go`、`tool_registry_search_replace_test.go`）；本機以測試 PAT 走 MCP JSON-RPC 實測 `initialize`（instructions 含新句）、`tools/list`（66 個工具含 `storyteller_validate_content`）、`tools/call` 驗證工具抓到 4 類錯誤與被移除的段落 id、`search_replace` 保留 `$100` 且回應帶 `format_warnings`（乾淨時為 `[]`）
- 與規格的差異：驗證工具只註冊在 MCP 專用清單（名稱不是 get_/list_ 開頭，放主清單會被站內助理當成寫入工具）；稽核登記為 `content.validate`（read），前端活動紀錄補一筆中文名稱；新增 `chapter_marker_id` 參數，驗證單一章節時只跟那一章比對段落 id；圖像作品的頁面描述不做檢查
- 起因：MCP client 寫錯格式時（例如 `⟦id⟧# 標題⟦/id⟧`），存檔會成功，但閱讀頁直接把符號印出來，要等作者自己發現。Skill 規劃（`Skill規劃_2026-10-04.md`）的驗證清單目前只能「寫完再讀回來」

## User Story

- AI agent 寫入前想確認格式對不對，不想先存一版錯的再改。
- AI agent 寫入後想立刻知道有沒有格式問題，不用另外讀回整篇比對。
- 作者事後發現怪怪的，可以請 agent 對整篇做一次健康檢查。

## 規格

### 1. 共用驗證函式（後端唯一一份規則）

`service/storyteller/content_format_check.go`：`checkStoryContentFormat(content string) storyContentFormatReport`。

規則全部重用既有 parser（`storyMarkerPattern`、`storyTableMarkerPattern`、`storyCodeFence*Pattern`、`storyInlineMarkerPattern`、`walkStoryContentLines`、`storyChapterSpans`），不另外刻一套，避免跟實際存檔／閱讀頁的解析結果不一致。

### 2. 新工具 `storyteller_validate_content`（dry-run，不寫入）

| 參數 | 說明 |
|------|------|
| `project_public_id` | 必填，驗證資產引用要用 |
| `content` | 必填，要檢查的完整內容或單一章節 |
| `story_public_id` / `lore_public_id` | 選填，二擇一。帶了就額外比對「跟目前版本相比，有哪些既有段落 id 不見了」 |

### 3. 寫入工具回應附上 `format_warnings`

`upsert`／`patch`／`replace_chapter`／`insert_chapter`／`search_replace`（story 與 lore）存檔後，回應多一個 `format_warnings` 陣列（沒問題就是空陣列）。**只警告、不擋寫入**：

- 擋寫入會讓既有流程突然失敗，而且有些問題存檔時已經自動修了（前綴搬到 marker 外）
- agent 看到警告可以馬上修，不用另外呼叫驗證工具

### 回傳格式

```json
{
  "ok": false,
  "summary": { "paragraphs": 312, "chapters": 6, "word_count": 5783 },
  "chapters": [{ "level": 1, "title": "第一幕", "marker_id": "8a8b000000000001" }],
  "warnings": [
    {
      "line": 1,
      "code": "block_prefix_inside_marker",
      "message": "標題前綴包在 marker 裡面，閱讀頁會把 # 印出來",
      "auto_fixed_on_save": true,
      "suggestion": "# ⟦8a8b000000000001⟧第一幕⟦/8a8b000000000001⟧"
    }
  ],
  "removed_marker_ids": []
}
```

`ok` 只看「不會自動修正」的警告；`chapters` 讓 agent 不用再呼叫 `list_story_chapters` 就能確認標題有被認到。

## 檢查項目

| code | 檢查 | 會造成什麼 | 存檔自動修？ |
|------|------|-----------|-------------|
| `block_prefix_inside_marker` | `⟦id⟧# …`、`⟦id⟧> …`、`⟦id⟧- …` | 符號直接印出來、章節工具認不到 | ✅（非網頁來源） |
| `unpaired_paragraph_marker` | 行首有 `⟦id⟧` 但結尾缺 `⟦/id⟧`，或開頭、結尾 id 不一致 | 整行連 `⟦⟧` 一起印出來 | ❌ |
| `duplicate_marker_id` | 同一份內容裡兩段用同一個 id | 書籤、大綱跳到錯的段落 | ❌ |
| `unbalanced_inline_marker` | `⟦footnote-x …⟧`、`⟦comment-x …⟧` 等行內 marker 開了沒關，或關了沒開 | 腳注／註解失效，符號外露；註解內容可能被讀者看到 | ❌ |
| `unclosed_code_fence` | ```` ``` ```` 開了沒關 | 後面整篇都變成程式碼區塊 | ❌ |
| `table_rows_not_adjacent` | 同一個 `tableId` 的列中間夾了別的段落 | 一張表被拆成兩張 | ❌ |
| `gfm_strikethrough` | 出現 `~~文字~~` | 會被解析成下標，不是刪除線（本站是 `--文字--`） | ❌ |
| `unbalanced_inline_style` | 同一段裡 `**`、`++` 成對數量是奇數 | 符號外露 | ❌（啟發式，可能誤報，標成 info） |
| `invalid_asset_reference` | 圖片不是本專案的 `steamloom-asset://` | 目前存檔直接回錯 | 存檔時本來就擋 |
| `removed_marker_ids`（欄位，不是警告） | 帶了 story／lore id 時，列出目前版本有、這次內容沒有的段落 id | 作者的書籤可能對不到段落 | — |

**不檢查**：文風、錯字、標點、劇情一致性。那些是 Skill 驗證清單的事，交給 agent 判斷，不是格式規則。

## 影響檔案

- 新增 `service/storyteller/content_format_check.go`＋`_test.go`：驗證函式
- `service/storyteller/tool_registry_story.go`／`tool_registry_lore.go`／`tool_registry_chapter.go`：寫入回應加 `format_warnings`
- 新增驗證工具的 ToolSpec。名稱用 `storyteller_validate_content`；工具清單附錄（Skill、MCP 連接頁）是自動產生的，不用另外改
- MCP server instructions 的 EDITING 段落加一句「寫入前可用 `storyteller_validate_content` 檢查，寫入後看 `format_warnings`」
- 不改前端；不改資料庫

## 常見 fail 與應對

| 情境 | 應對 |
|------|------|
| 驗證規則跟前端 parser 不一致（後端說 OK、閱讀頁還是壞） | 只重用存檔／章節工具已經在用的 Go pattern；測試案例直接拿今天〈製作我〉第八章的真實內容和幾種錯誤格式 |
| 啟發式檢查誤報（例如內文真的需要單獨一個 `**`） | 標成 `severity: info`，不計入 `ok` |
| 很長的內容（十萬字）驗證太慢 | 單次掃描、線性時間；比對段落 id 只在帶 story／lore id 時做 |
| 舊資料本來就有問題，每次寫入都噴同樣警告 | 這是正確行為，讓 agent 有機會順手修；訊息裡寫清楚哪一行 |
| AI 助理（站內）的工具清單 | 驗證工具是唯讀，命名不會被歸到寫入工具；站內助理目前停用，不影響 |

## 順帶：search_replace 的 `$` bug

`is_regex=false` 時 replace 仍走 `ReplaceAllString`，`$100` 這種字串會被當成群組參照吃掉，而且不會報錯（2026-10-04 實測：「售價 $100 元」→「售價  元」）。修法是 literal 模式改用 `ReplaceAllLiteralString`，跟工具說明「literal」的語意一致。改動很小，可以跟這次一起做，或先單獨修。
