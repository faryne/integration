# AI 助理提案：diff 預覽與套用前存檔（2026-09-23）

## 背景

prod 測試「我想要重寫第二幕的故事 @thisStory」時發現兩個問題：

1. 提案卡片沒有任何可以看 diff 的入口。
2. 按「套用提案」前不檢查編輯區有沒有未存檔變更，使用者沒存的修改會被直接蓋掉。

## 做法

### diff 預覽

- 新增 `POST /storyteller/projects/:project/agentic-proposals/:proposal/preview`（`service/storyteller/agent_proposal_preview.go`），只計算不寫入。
- 支援 `patch_story／patch_lore／search_replace_story／search_replace_lore`，呼叫的是各工具 handler 本來就在用的純函式（`mergeStoryPatch` 對應欄位、`compileStorytellerSearchPattern`＋`replaceStoryContent`），確保預覽跟真正套用的結果一致。前端不自己算，因為 search_replace 用的是 Go RE2，跟 JS regex 有差異。
- body 帶編輯區目前的 title／summary／content（可能包含未存檔變更），預覽就會等於「先存檔再套用」之後的實際結果。
- upsert 類的參數本身就是全文，維持前端直接畫 diff。
- 前端 `PREVIEW_TOOLS`（`StorytellerAgenticProposalCard.tsx`）必須跟後端 `proposalPreviewers` 保持一致。
- 章節寫入工具（`replace/insert/delete_*_chapter`）只放在 `StorytellerMCPOnlyToolRegistry`，AI 助理面板看不到，不會變成提案，所以不在預覽清單裡。之後如果開放給面板，要一併補進兩邊的清單。

### 套用前存檔

- 判斷條件：提案目標是目前開著的這篇（工具種類對得上 `targetKind`，而且 `story_public_id／lore_public_id` 等於目前這篇），加上 `hasUnsavedStoryChanges()／hasUnsavedLoreChanges()` 為真。符合時跳「編輯區還有未存檔的變更」對話框，主按鈕是「先存檔再套用」。
- 先用一般存檔流程（`handleSaveStory／handleSave`，現在會回傳 `Promise<版本 id | null>`）存成一個版本，再走原本的套用路徑。存檔拿到的版本 id 就是「回復到套用前版本」要退回的目標，所以使用者當時沒存的修改也救得回來。
- 存檔失敗（回傳 null）就中止套用，卡片顯示「存檔失敗，提案沒有套用。」。
- Story／Lore 兩個編輯器同步修改（雙胞胎原則）。

## 已知 Bug 記錄

### 1. 非 upsert 提案沒有 diff 入口（已修）

- **現象**：AI 用 `patch_story` 或 `search_replace_story` 改內容時，卡片只剩「套用／否決」兩顆按鈕。
- **Root cause**：卡片的「檢視 diff」按鈕只綁 `isUpsertStory`。而且這些工具的參數只有片段，前端拿不到改完之後的全文。
- **解法**：新增上面的 preview API。
- **狀態**：已修。

### 2. 套用提案會吃掉未存檔修改（已修）

- **現象**：編輯區有沒存的修改時按套用，修改就消失了，也沒辦法用「回復到套用前版本」救回來。
- **Root cause**：
  - upsert 同目標：`applyAgenticProposalToEditor` 直接 `setContent` 再存檔，沒有檢查 dirty。
  - 其他工具：後端直接寫入之後 `invalidateQueries`，StoryEditor 裡 `story?.content` 的 effect 會把編輯區重設成 DB 內容，同時把「已存檔」的基準也重設掉。
  - 「回復到套用前版本」退回的是 `apiStory.latest_version_id`，也就是上次存檔的版本，未存檔的修改本來就沒進過版本歷史。
- **解法**：套用前先存檔，見上面「套用前存檔」。
- **狀態**：已修。

### 3. 套用不可執行的提案會把使用者登出（地雷，已修）

- **現象**：本機測試套用一筆工具不在允許清單的提案時，畫面直接跳回登入頁。
- **Root cause**：`controller.ApplyAgentProposal` 把 `ErrAgentProposalToolNotAllowed` 和 `ErrAgentToolScopeViolation` 回成 401，前端 `httpInterceptors` 把 401 當 session 失效處理，直接清掉登入狀態。實際情境：AI 提案寫到別的專案（scope violation）時，使用者一按套用就被踢出去。
- **解法**：改回 400（`output.BadRequest`），錯誤訊息照常顯示在卡片上。
- **狀態**：已修。
