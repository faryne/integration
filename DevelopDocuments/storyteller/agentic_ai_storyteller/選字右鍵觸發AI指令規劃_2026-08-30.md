# 選字右鍵觸發 AI 指令規劃（2026-08-30 提出，2026-08-31 定案）

規格已定案，準備交給 Codex 實作。

## 背景

`/rewrite`／`/expand`／`/translate`／`/custom` 這些單輪 skill 指令，實際上**沒有接編輯器的選取範圍**——`selected_content` 在前端是寫死的空字串（`StorytellerAgenticPanel.tsx` 的 `runSkill()`），使用者要處理某段文字時只能自己複製、切到 AI 助理面板貼上再打指令。這份規劃把「選字 → 右鍵選單 → 直接觸發」接上，讓選取範圍真的送進 `selected_content`。

## 確認後的操作流程

1. 使用者在編輯器選取一段文字。
2. 右鍵選單出現 `/rewrite`／`/expand`／`/translate`／`/custom` 幾個選項（不含 `/continue`——續寫不吃選取範圍，語意上跟選字操作無關，不放進這個選單）。
3. 點選後跳出一個小彈窗，讓使用者輸入「額外需求」（可留空，直接送出就套用預設規則）。**彈窗送出這個動作本身不呼叫任何 API**——純粹是把「當下選取的文字」（直接從編輯器同步讀出，不用等）、選的 mode、打的額外需求，整理成一份待處理內容。
4. 上面那份待處理內容往上傳給頁面層（`StoryEditor.tsx`／`LoreEditor.tsx`），頁面層 `setSidePanel("agentic")` 開啟 AI 助理面板（面板本來就開著的話這步是 no-op）。
5. AI 助理面板收到這份待處理內容後：
   - 用一張跟現有「回覆」功能一模一樣的**引用卡片**顯示「選取文字：{截斷預覽}」，附「取消」按鈕——這張卡片獨立於輸入框，不是塞進同一個文字字串裡。
   - 把輸入框內容預填成 `/rewrite 改寫得更色一些` 這種「指令 + 額外需求」的純文字，讓既有的 `parseSkillSlashCommand` 可以正常辨識（純文字必須以 `/` 開頭才吃得到，所以選取內容不能跟這行文字混在一起）。
6. 使用者可以在送出前繼續編輯這行文字，或直接按面板既有的「送出」按鈕——這時才真的呼叫 API，走現有的 `runSkill()` 路徑，這次 `selected_content` 真的帶著剛才選取卡片裡的文字。使用者也可以先點卡片的「取消」放棄這次選取（不影響已經打進輸入框的文字）。
7. 送出後在面板裡等待執行結果，跟現有 `/rewrite` 等指令的既有流程完全一樣。

## 為什麼不做成「送出彈窗後直接呼叫 agent」

原本考慮過「彈窗送出＝直接呼叫 agent，面板只是拿來顯示結果」，但使用者最後決定比照「回覆／否決提案」的既有做法：彈窗送出只是把內容**展開到輸入框讓使用者看到、可以再編輯**，真正呼叫 API 的動作還是使用者自己按面板的「送出」鍵才觸發。好處：
- 完全不用碰面板內部的 `runSkill` 呼叫邏輯，只是多一個「外部把 prompt/選取內容灌進去」的入口，跟現有 `promptReferences`／`replyTarget` 那套 props 下傳的風格一致。
- 使用者送出前還能改字，跟現有其他指令的使用習慣一致，不會因為多了右鍵入口就變成「一鍵直接送出、不能反悔」的例外流程。
- 不用處理「面板還沒掛載時要怎麼呼叫」的問題（AI 助理面板是條件式掛載的，`sidePanel !== "agentic"` 時整個元件不存在）。

## 技術限制查證結果（部分推翻原本的猜測）

- **選取範圍收合的疑慮已經不存在**：原本以為右鍵選單會把選取範圍收合成單點，需要另外處理。實際查證 `handleEditorContextMenu`（`StorytellerWysiwygEditor.tsx` 約 674 行）發現這個問題早在 2026-07-09（commit `dd744b2`）就修好了——右鍵點在「選取範圍裡面」會保留選取，只有點在「選取範圍外面」才收合。現有右鍵選單（`StorytellerWysiwygContextMenu.tsx`）已經在用這個正確的 `hasSelection` 狀態分支顯示粗體/顏色選項。**這部分完全不用改。**
- **`selected_content` 後端管線本來就是完整的**：`SelectedContent`／`SelectionStart`／`SelectionEnd` 欄位、驗證邏輯（`validateSelectionAgentRunRequest`）、prompt 組裝邏輯（`buildAgentRunPrompts`）全部都在，就是前端從沒送過非空值。這次接上完全不用改後端的 prompt 組裝邏輯。
- **跨元件狀態傳遞**：AI 助理面板（`StorytellerAgenticPanel`）跟編輯器（`StorytellerWysiwygEditor`）是同一個頁面（`StoryEditor.tsx`／`LoreEditor.tsx`）底下的兩個獨立元件，且面板是條件式掛載（`sidePanel === "agentic"` 才 render）。新增一個頁面層 state（例如 `pendingSelectionAgentTrigger`），存 `{ mode, selectedText, instruction }`，往下當 prop 傳給面板；面板用 `useEffect` 監聽這個 prop 變化去套用（涵蓋「面板本來就沒開，這次順便掛載」跟「面板本來就開著，只是這次又選了一次字」兩種情況），套用完呼叫一個 callback 通知頁面層清空這個 state，避免面板之後重新掛載又誤套用一次。

## `/custom` 的 `custom_chapter` 徹底移除（2026-08-31 決定）

**背景**：原規劃打算讓 `/custom` 依「有沒有選取文字」動態決定要用 `custom_chapter` 還是 `custom_selection`——但查證後發現這個判斷本身反映一個更根本的問題：`custom_chapter` 名義上是「整個章節範圍」，但這個 repo 目前**沒有辦法在編輯區分辨出章節**（沒有章節/段落邊界的資料結構，要做到位還得處理 TOC 之類的東西，範圍遠超這次要做的事）。使用者決定**徹底拿掉 `custom_chapter` 這個模式**，`/custom` 一律用 `custom_selection`；沒有選取文字時，靠後端既有的 `hasSelection` 判斷（`agentRunModeRequiresSelection(mode) && SelectedContent != ""`）自動退回整篇內容當上下文——跟 `rewrite_selection`／`expand_selection`／`translate_selection` 目前「沒選字時」的行為完全一致，不用另外設計任何動態切換規則。

**移除範圍**：

後端：
- `model/entity/storyteller/storyteller.go`：刪掉 `AgentRunModeCustomChapter` 常數（`custom_chapter` 這個 mode 字串值完全不再是合法輸入）。
- `service/storyteller/storyteller.go`：
  - `validateAgentRunRequest` 的 switch 拿掉 `AgentRunModeCustomChapter`（原本 `case ContinueChapter, CustomChapter: return nil` 改成只剩 `case ContinueChapter: return nil`）。
  - `agentRunOutputInstruction` 拿掉 `case AgentRunModeCustomChapter` 那個分支（`custom_selection` 的分支已經存在、不受影響）。
- `ai_provider_test.go`／`agent_run_test.go` 裡目前用到 `AgentRunModeCustomChapter` 的測試（約 8 處），依原本測試想驗證的行為決定要刪掉還是改用 `AgentRunModeCustomSelection`／`AgentRunModeContinueChapter` 頂替（不是機械式全部換字，要看每個測試原本想確認什麼）。

前端：
- `static_site/src/types/storyteller.ts`：`StorytellerAgentRunMode` union 拿掉 `"custom_chapter"`。
- `StorytellerAgenticPanel.tsx`：`SKILL_SLASH_COMMANDS` 的 `custom: "custom_chapter"` 改成 `custom: "custom_selection"`。
- `StorytellerAgentPanel.tsx`（這是另一個舊版單輪 Agent 面板，`AGENT_RUN_MODE_LABELS` 這個 map 目前兩個 key 都指到同一句 `"/custom 自訂指令"`）：刪掉 `custom_chapter` 那個 key，`custom_selection` 已經有一模一樣的 label，刪掉不會造成顯示空白或查表落空。

移除後，前端不需要任何「依選取狀態動態決定 mode」的邏輯——`/custom` 不管從輸入框打字還是這次新增的右鍵選單觸發，一律固定送 `custom_selection`。

## 存檔前鎖定（沿用原規劃，未變動）

- **AI 助理送出按鈕：已經免費具備。** `canRun` 本來就檢查 `Boolean(targetPublicId)`，新故事在第一次存檔前 `apiStory` 查不到、`public_id` 是 `undefined`，送出鈕本來就鎖死。
- **右鍵選單：需要額外處理。** `StorytellerWysiwygContextMenu` 沒有「這篇有沒有存過」的概念，選單項目是靜態列表。要補一個 prop（例如 `hasSavedTarget`，沿用頁面層已經有的「`targetPublicId` 是否存在」這個事實往下傳），選單渲染時用它決定要不要顯示這幾個 AI skill 項目——**沒有 `targetPublicId` 時整個不列出這些選項**，不是顯示但禁用變灰。

## 額外需求彈窗的 UI

直接沿用「否決提案」已經有的 `Dialog` + `TextField` + `DialogActions` 樣式（`StorytellerAgenticProposalCard.tsx` 的否決彈窗），風格一致、不用另外設計元件。彈窗裡可以順便顯示選取內容的截斷預覽（例如前 50 字 + `...`），方便使用者送出前確認選取範圍對不對。
