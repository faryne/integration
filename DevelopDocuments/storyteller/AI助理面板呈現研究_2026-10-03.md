# AI 助理面板呈現研究

- 狀態：**已決定停用站內 AI 助理**（2026-10-03，見文末「決定」）；以下研究內容保留供日後重啟時參考
- Branch：`feature/storyteller-ai-panel-ux`（從 `feature/storyteller-mobile-editor-focus` 切出）
- 前情：`ai-assistant-no-drawer-redesign/提案說明.md`（2026-09-11 放棄 Drawer、改成插在段落後方）、`行動版編輯頁_2026-10-03.md`（行動版實測數據）

## 現況流程

1. 入口：選字浮動選單「問 AI」、右鍵「問 AI」、`/` 選單「問 AI」、工具列 ✦。
2. 觸發當下 snapshot `selectedText`＋結尾段落 `markerId`，接著**收合選取並讓編輯器失焦**（`StorytellerWysiwygEditor.tsx` `handleRequestAI`）。
3. AI 工作區（完整的 `StorytellerAgenticPanel`：對話歷史＋composer）以 portal 插在 marker 段落後方，固定高 500px（手機）／600px（桌機）。
4. 回覆底下只有「附加末尾」「複製」「回覆」。

## 問題

| # | 問題 | 證據／根因 |
|---|---|---|
| 1 | **佔編輯區高度**，行動版尤其嚴重 | 面板固定 500～600px，跟內文共用同一個捲動區；行動版鍵盤彈出時 AI 輸入框容易被蓋住（見行動版文件實測）。 |
| 2 | **`/rewrite` 結果放不回原位** | 回覆只有「附加末尾」（加到整篇最後，離原段落可能很遠）和「複製」。「取代選取／插入游標」是 2026-06 的原始設計（`replace_selection`），換成 Tiptap 後停用至今（`StoryEditor.tsx` 註解：「插入游標/取代選取這兩個需要 textarea 游標位置的動作這次先停用」）。 |
| 3 | **選取一觸發就消失**，看不出 AI 正在處理哪一段 | 觸發時刻意收合選取（為了讓浮動選單消失）；snapshot 只存文字與結尾 marker，**沒有存範圍**，所以既無法高亮、也無法事後取代。 |
| 4 | 對話與內文糾纏 | 看 AI 回覆往上捲會捲到內文；面板移動會帶動內文位置。 |

## 方向比較

### A. 維持內嵌，縮小／可收合

面板預設縮成一列 composer，展開才看歷史。
- 優點：改動最小。
- 缺點：問題 2、3 沒解；展開後一樣佔高度；行動版鍵盤問題依舊。

### B. 停靠面板（桌機右側／手機底部 sheet）

回到 9 月前的停靠式，但補上「來源高亮」與「取代／插入」。
- 優點：不佔編輯區；行動版可以做成標準 bottom sheet，輸入框跟著鍵盤（`visualViewport`）。
- 缺點：9 月放棄 Drawer 的理由是「AI 要回到編輯上下文」；單純停靠會再度失去「結果就在原文旁邊」的感覺。

### C. 混合（建議）：結果回到原文旁、對話停靠

把「改寫結果」和「對話」拆開：

1. **選取持久高亮**：觸發時把選取範圍存成 ProseMirror decoration（跟著編輯 mapping 移動，不進文件、不進 undo）。浮動選單照樣收起，但原文保持淡色高亮，看得出 AI 在處理哪一段。
2. **單輪指令結果內嵌成「建議卡」**：`/rewrite`、`/expand` 等單輪結果，在原文段落後面顯示一張精簡建議卡（只有結果文字＋操作），不是整個聊天室：
   - **取代原文**：用高亮範圍直接取代；送出後原文若被改過，改提示「原文已變更」並只提供插入。
   - **插入到段落後**、**複製**、**重試**、**捨棄**。
   - 套用後的變更是一次 undo 可以復原的 transaction。
3. **完整對話停靠**：多輪對話、歷史、Agent 提案（diff 預覽）移到停靠面板。
   - 桌機：右側面板（overlay 疊在稿紙右側空白，不擠壓正文欄寬，延續 9 月「不讓文章重新換行」的原則）。
   - 手機：底部 sheet（半高／全高），composer 固定在 sheet 底部、高度跟著鍵盤。
   - 面板裡的訊息可以「跳到原文」：捲回高亮段落。
4. 建議卡也可以「在面板繼續討論」：把那次結果帶進停靠面板當上下文。

**為什麼建議 C**：最常用的改寫／擴寫是「選一段 → 拿結果 → 放回去」，這條路徑應該全程留在原文旁邊、一鍵完成；需要來回討論時才用停靠面板，那時編輯區高度不再被吃掉。

## 技術要點（C）

- 來源範圍：新的 decoration plugin，存 `{from, to}` 並在每個 transaction 用 mapping 更新；範圍被整段刪除時標記失效。取代前比對範圍內現在的文字與 snapshot 是否相同。
- 建議卡沿用現有 inline anchor（`inlineAssistantAnchor.ts`）的單一 host／portal 機制，只是內容從完整面板換成精簡卡片，高度依內容而定。
- 停靠面板沿用 `StorytellerAgenticPanel`（已有 `floatingDock` presentation 可參考），Story／Lore 兩邊同時改（雙胞胎）。
- 後端不需要改：單輪 skill 的 request／response 不變，只是前端多了「取代」的套用方式。

## 建議分期

1. **P1 取代原文＋選取高亮**（不動版面）：先解決問題 2、3，內嵌面板照舊。價值最高、風險最低。
2. **P2 單輪結果改成建議卡、對話停靠**：解決問題 1、4，桌機右側 overlay＋手機 bottom sheet。
3. **P3 行動版鍵盤細節**：`visualViewport` 跟隨、斜線選單高度限制。

## 決定（2026-10-03）

使用者的考量：站內 AI 助理要使用者自備 API key，但多數人已有 AI 訂閱，且 MCP 已可讓 Claude／ChatGPT／Codex 直接讀寫故事；介面無論放 Drawer 或內嵌都不順手。目前沒有使用者，影響小。

做法：**入口全部藏起來、程式碼暫時保留**，由同名開關統一控制：

- 後端 `STORYTELLER_AI_ASSISTANT_ENABLED`（`config/index.go`，預設 false）：36 條 AI 路由（agent chat、provider API key、Skill、用量、記憶草稿、AI 提案、chat history）逐條掛 `middleware/storytellerai.Gate()`，關閉時回 403（custom code `403101`）；每週模型目錄同步排程跳過。
- 前端 `STORYTELLER_AI_ASSISTANT_ENABLED`（`data/storyteller.ts`，讀 `VITE_STORYTELLER_AI_ASSISTANT_ENABLED`，預設 false）：
  - 編輯器：不傳 `onSelectionAgentTrigger`／`inlineAssistant`，`/`、右鍵、浮動選單的「問 AI」與工具列 ✦ 都不出現。
  - 工作台：側欄拿掉 Skill／金鑰管理／用量報表，舊網址（含 Skill 表單、Skill 版本比對）轉回創作專案；首頁不顯示 Skill 數。
  - 歡迎導覽不介紹 AI Agent；MCP 說明補上 Claude、ChatGPT。
  - `apis/storyteller/agent.ts` 會自動發請求的 AI query 都加上開關，頁面不會打到被擋的 API。
- 不受影響：MCP（不經過上述路由）、梭梭的記憶管理、工具定義（tool registry）、版本歷史、稽核。

**刻意保留**：停用的程式碼不是死碼，不要依 AGENTS.md「ALWAYS REMOVE UNUSED CODE」刪除。

**重新評估的觸發條件**：主流 AI 服務開放第三方以訂閱帳號 OAuth 登入使用時，再評估是否以「獨立對話頁＋工具呼叫」的形式重啟（不再內嵌在編輯頁）。屆時需確認該服務條款是否允許第三方使用。
