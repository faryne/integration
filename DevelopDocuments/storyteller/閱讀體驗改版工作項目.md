# 閱讀頁閱讀體驗改版工作項目

本文件記錄 Storyteller 閱讀頁（`Reader.tsx`）這一輪「閱讀體驗」改善的討論結果與工作項目，範圍包含閱讀體驗本身（欄寬、字級、圖片顯示方式）與社群分享功能（分享按鈕、社群預覽卡）。**不含**討論區／留言等社群互動功能、也不含版面架構重做——這些是更大的擴充方向，之後要做會另外獨立規劃，不要跟這輪混在一起做。

## 背景

`Notion風工作台交接.md` 收尾後回頭檢視閱讀頁，發現目前版面「堪用但不利未來擴充」。討論後把範圍先收斂到「閱讀體驗本身有沒有明顯不足」；後續使用者補提了「社群分享功能」，一併納入這輪，範圍是分享按鈕＋分享時的社群預覽卡，不含討論區／留言（那個明確排除，見下方）。

## 現況診斷

- `Reader.tsx` 2613 行，包在 `StorytellerShell`（本身無寬度限制）之下，外層又被 `StorytellerLayout` 的 `Container maxWidth="xl"`（1536px）包住。
- 文字內容區塊沒有自己的 `maxWidth`，索引欄收起來時內文會撐到接近全螢幕寬，行寬對長時間閱讀偏寬。
- 沒有任何閱讀個人化設定：`lineHeight: 1.9` 寫死，段落間距 `& p { my: 0.5 }` 偏窄，字級無法調整。
- 閱讀頁尚未套用 `useStorytellerPalette` 色系系統，明暗模式是否有正確涵蓋內文顏色還沒盤點過。
- 圖像作品目前是「單頁點擊／方向鍵翻頁」模式，頁面容器固定 `height: min(70vh, 800px)`，圖片依此高度縮放——螢幕越高，圖片反而可能被壓得越小，對話框文字可能看不清楚。
- 原圖模式（lightbox）只能整張塞進視窗＋用捲動看溢出部分，沒有縮放功能，長條直式頁面不好瀏覽。
- 方向鍵翻到最後一頁會卡住（`Math.min(index + 1, totalEpisodePages - 1)`），不會自動跳到下一話第一頁。
- 閱讀頁沒有任何分享按鈕，讀者要分享只能自己複製瀏覽器網址列的連結。
- 全站的 SEO/OG meta（`helpers/title.tsx` 的 `useTitle`/`useSeo`）是 client-side JS 動態寫入 `document.head`，只有執行 JS 的瀏覽器看得到，社群平台的連結預覽爬蟲不執行 JS，抓不到這些動態值。
- **但這不代表要從零蓋社群爬蟲渲染機制——這套基礎設施其實已經存在，只是壞掉了**：`httpd_conf/nginx` 裡已經有 `map $http_user_agent $is_social_bot`（判斷 `facebookexternalhit`／`Twitterbot`／`LINE`／`Discordbot` 等），偵測到是社群爬蟲就轉給 Go 後端的 `/sns/*`（`route/sns.go` → `service/sns/meta.go`），後端依路徑動態組出正確的 `og:title`／`og:description`／`og:image` 回一份輕量 HTML；SteamLoom 網域也已經接了自己的分支（`@steamloom_sns` → `/sns/storyteller/...`）。查了之後發現兩個問題：
  1. **路徑比對是舊的**：`meta.go` 的 `pathCollection` 比對 `^/storyteller/story/...`，但前端閱讀頁路由早就從 `story/` 改名成 `work/`（`App.tsx` 裡的 `LegacyStorytellerRedirect` 只在瀏覽器執行 JS 後才生效，對社群爬蟲沒用）。**代表現在分享任何 storyteller 連結出去，這條管線完全比對不到，直接落到全站通用 fallback meta，等於名存實亡**。
  2. **粒度只到「專案」，沒到「故事/話」**：即使路徑修好，目前 `applyStorytellerPublicProjectMeta`／`applyStorytellerSharedProjectMeta` 只抓 `project.Name`／`project.Description`，沒有再往下抓故事/話本身的標題與摘要——分享某一話時，預覽卡顯示的還是整個作品名稱，不是那一話。

## 本輪工作項目

### 文字作品

1. **限制閱讀欄寬**：內文區塊固定一個舒適閱讀寬度並置中，不論索引欄開合都套用同一個寬度，不要讓行寬隨版面跳動。
2. **可調字級**：提供小／中／大／特大四段即可，不用做到電子書等級的精細調整。
3. **段落間距微調**：放寬目前偏窄的 `& p { my: 0.5 }`。
4. **確認並補齊 dark mode 涵蓋範圍**：盤點目前明暗切換有沒有正確套用到內文顏色，缺的部分補上。

### 圖像作品

1. **顯示邏輯改成寬度優先**：拿掉固定 `height: min(70vh, 800px)` 造成的壓縮，改成以內容欄寬為主，高度依圖片比例自然撐開，讀者用捲動閱讀單頁內容。
2. **原圖模式（lightbox）補上縮放**：加滾輪／手勢縮放，或至少讓原圖模式維持原始寬度顯示、用捲動瀏覽，取代現在硬塞進視窗的做法。

### 社群分享功能

1. **分享按鈕**：閱讀頁（故事／圖像頁）標題附近或工具列加分享入口。
   - 平台先做 Facebook、X（Twitter）、LINE（台灣讀者常用）、複製連結（一定要有，最泛用、無平台依賴）；行動裝置可以優先呼叫瀏覽器原生 `navigator.share`，桌面版 fallback 用各平台的 share intent 網址（`facebook.com/sharer/sharer.php`、`twitter.com/intent/tweet`、`social-plugins.line.me/lineit/share` 這類）。
   - 分享的網址預設用「目前正在看的這篇/這話」的連結，不是整個作品的索引頁——比較貼近使用者當下想分享的內容。
   - `work/share/:shareToken` 這種「與親友分享」層級的連結本身就代表拿到連結的人都能看，加分享按鈕不會改變這個隱私語意（連結本身沒變，只是幫使用者把同一條連結貼去社群更方便），不用額外做權限判斷。
2. **社群預覽卡（Open Graph／Twitter Card）**：讓分享出去的連結在 Facebook／LINE／X 上顯示正確的故事標題、簡介、封面圖。**基礎設施已經存在（nginx 社群爬蟲判斷 + Go 後端 `/sns/*` 動態組 meta），不用重蓋**，但目前對 storyteller 閱讀頁是壞的（見上方現況診斷），需要修：
   - **修正路徑比對**：`service/sns/meta.go` 的 `pathCollection` 裡兩條 `^/storyteller/story/...` regex，要改成比對現行的 `^/storyteller/work/...`，涵蓋 `stories`、`story/:storyId`、`image/:episodeId`、`share/:shareToken` 等現在實際存在的路由形狀。
   - **粒度延伸到故事/話層級**：新增對應的 `Apply` 函式，依 regex 抓到的 `storyId`／`episodeId` 再查一次故事/圖像作品本身的標題、摘要（圖像作品可以拿第一頁當封面圖），讓分享單篇/單話時預覽卡顯示的是那篇/那話的資訊，不是整個專案籠統帶過。
   - 這兩項都在 Go 後端（`service/sns/meta.go`），跟這輪其他前端項目不同 codebase 區塊，要分開執行，但排進同一輪工作項目一起做，不再另外評估要不要做。

## 共用機制

- 新增一個輕量的「閱讀設定」入口（icon 開 popover 或 drawer），依 `content_type` 顯示對應控制項：文字作品顯示字級；圖像作品視第 2 點的實作方式決定要不要放縮放相關設定。
- 設定值一律存瀏覽器本機（localStorage），不依賴登入、不需要後端支援。

## 不在這輪範圍（已討論並明確決定不做）

- **跨頁（雙頁對開）模式**：保留。這是 `漫畫插圖閱讀器.md` 裡已經定案的長期方向之一（「閱讀模式只做兩種：單頁與跨頁」），只是還沒實作；這輪不做，之後有餘力再排。
- **無限捲動式長條漫畫（webtoon）**：明確不考慮，除非之後真的決定要推出長條漫畫這個內容型態。`漫畫插圖閱讀器.md` 也已經記錄過同樣結論（不同內容形態、UX 要整套重做，不能沿用單頁／跨頁介面）。
- **方向鍵在最後一頁自動跳到下一話第一頁**：討論過，明確決定不加入這輪工作項目（不是技術債，是刻意決定不做）。
- **討論區／留言等社群功能**：本輪只聚焦閱讀體驗本身，社群功能屬於更大的擴充方向，之後要做會獨立規劃。這也呼應 `漫畫插圖閱讀器.md` 裡「留言／閱覽數要跨文字圖像一起規劃、不掛在單一內容類型上」的既有結論。

## 建議實作順序

前端（`static_site/`）：

1. 文字內容欄寬限制
2. 字級調整
3. 圖像頁寬度優先顯示邏輯
4. 段落間距微調、dark mode 涵蓋度盤點與補齊
5. 原圖模式縮放
6. 分享按鈕

第 1～3 項影響最大、彼此獨立、風險最低，優先處理；第 4、5、6 項可以合併在同一輪但重要性稍低。

後端（Go，`service/sns/meta.go`）：

7. 修正 `pathCollection` 路徑比對（`story/` → `work/`），先讓既有機制對現行路由重新生效
8. 延伸到故事/話層級的 `Apply` 函式

第 7、8 項跟前端 1～6 項是不同 codebase 區塊，但排進同一輪一起執行；第 7 項是修正既有 bug，優先度不低於前端項目。

## 備註

- `Reader.tsx` 目前 2613 行，這輪改動範圍不大，先不強制拆檔。如果之後閱讀設定要擴充更多控制項（例如圖像縮放偏好持久化），建議屆時評估把閱讀設定相關邏輯拆成獨立檔案／hook，避免繼續往這個巨檔堆。
