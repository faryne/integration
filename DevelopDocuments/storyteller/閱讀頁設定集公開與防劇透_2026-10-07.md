# 閱讀頁設定集公開與防劇透（2026-10-07）

- 狀態：規格已確認（2026-10-07，見文末「已確認決策」），待排程實作
- Mockup：`reader-lore-mockup/index.html`
- 範例作品：`https://steamloom.works/work/8f904197d2c92093-Sextet_Resonance`

## 背景

SteamLoom 成長策略改為「讀者先行」：先吸引讀者，再讓讀者把作者拉進來。閱讀頁裡「故事 × 設定集」的整合體驗，是其他連載平台（鏡文學、POPO、Penana、巴哈小屋）給不了的差異化。目前 `Lore` 完全沒有公開機制，`WYSIWYG` 的站內連結也因為「設定集還沒有公開機制」而暫緩（見 `所見即所得編輯器_issue.md`）。

**§0 用詞定案（作者端與讀者端統一）：`LoreCollection`＝「設定集」、`Lore`＝「設定」。** 工作台現在把單篇 lore 叫「設定集」、collection 叫「分類」，這輪一起改掉（見 §7）。

**分層原則：依「怎麼讀」切開，不依「內容類型」切開。**
- **本篇**＝線性閱讀（文字故事＋圖像作品，依冊分組、上一篇／下一篇、閱讀進度）。維持現狀。
- **設定**＝查閱型。在網址、列表、閱讀中的導覽、閱讀紀錄等每一層都和本篇分開。

## 需求（使用者定案）

1. `work/:projectPath` 就是作品首頁，有兩個 Tab：「故事」（文字＋圖像）和「設定」。設定列表的顯示方式比照故事列表。
2. 內容網址改成 `story/<publicId>` 和 `lore/<publicId>`（原本提的 `story-<publicId>` 因 React Router 不支援半段參數而改用這個寫法）。
3. 設定可以標記 `spoiler`，作者可以指定 `dependsOn`（故事、圖像作品、其他設定）。讀者還沒讀過時要先確認才能閱讀，所以需要記錄閱讀紀錄，並顯示在列表上。
5. 列表上顯示**閱讀進度百分比**，不是只有讀完打勾。
4. 故事內文和圖像說明可以插入「設定連結」（比照 `steamloom-asset://`），點擊後開啟該設定的摘要，同樣受 spoiler／dependsOn 控制。

## 1. 網址

| 網址 | 內容 |
|---|---|
| `work/:projectPath` | 作品首頁，「故事」Tab |
| `work/:projectPath/lores` | 作品首頁，「設定」Tab；`#<collectionPublicId>` 會捲動到對應的設定集 |
| `work/:projectPath/story/:publicId` | 文字故事或圖像作品（兩者都是 `Story`，用 `content_type` 區分） |
| `work/:projectPath/story/:publicId/versions/:versionId` | 故事的版本歷史（沿用現有功能） |
| `work/:projectPath/lore/:publicId` | 設定頁 |
| `work/share/:shareToken[/lores｜/story/:id｜/lore/:id]` | 分享連結，規則相同 |

- 用真正的路由參數，不需要自己解析前綴。現有的 `work/:p/story/:storyId` 舊路由**直接轉正**成 canonical 網址，舊連結天生就能用。
- `lores`、`stories` 是靜態片段，React Router 的排序會優先於 `:itemId`，不會跟沒有前綴的舊網址撞在一起（publicId 是 hex，也不可能剛好叫 `lores`）。
- **舊網址導向**（社群上已經流通，不能壞）：
  - `work/:p/stories` → `work/:p`
  - `work/:p/:bareId`（沒有前綴）→ `work/:p/story/:bareId`
  - `work/:p/image/:id` → `work/:p/story/:id`
  - `story/` 開頭的舊路由鏈，改成直接導向新格式，不要多跳一次
- **社群預覽卡**（`service/sns/meta.go`）：regex 同時接受新舊格式。順便補上 `閱讀體驗改版工作項目.md` 裡未完成的「單篇層級」預覽卡：`story/` 顯示該篇的標題和摘要，`lore/` 顯示設定標題和摘要；如果是劇透設定，**只顯示「〈作品名〉的設定（含劇透）」**，不把摘要貼到社群上。

## 2. 資料模型（MySQL 5.7）

### `storyteller_lores` 新增欄位

| 欄位 | 型別 | 說明 |
|---|---|---|
| `status` | `varchar(16)` default `'draft'` | 沿用 `StoryStatus` 的 `draft`/`completed`。**預設不公開**：設定裡常有作者的私人筆記和未揭露伏筆 |
| `summary` | `varchar(500)` default `''` | 給列表和連結摘要用。空字串時前端改取正文前 120 字（去掉 markdown） |
| `is_spoiler` | `tinyint(1)` default `0` | 劇透標籤 |

### 新表 `storyteller_lore_dependencies`

| 欄位 | 說明 |
|---|---|
| `lore_id` | 被保護的設定 |
| `target_type` | `story` / `lore`（圖像作品也是 `story`） |
| `target_id` | 必須在同一個專案，且不能是自己 |
| `sort` | 顯示順序 |

- `is_spoiler = 1` 且**沒有** dependsOn：每次都要確認（泛用劇透警告）。
- `is_spoiler = 1` 且**有** dependsOn：全部讀過就直接顯示，否則要確認。
- `is_spoiler = 0` 時忽略 dependsOn（保留資料，取消勾選後重新勾回來不會遺失）。
- 循環依賴（A→B→A）**不用擋**：防劇透是軟性閘門，讀者確認後一定讀得到，不會卡死。

### 新表 `storyteller_reading_records`（只記錄已登入的讀者）

| 欄位 | 說明 |
|---|---|
| `user_id`、`project_id`、`target_type`、`target_id` | unique (`user_id`, `target_type`, `target_id`) |
| `progress` | `tinyint unsigned` 0～100，**讀過的最遠位置**（只增不減，回頭重讀不會倒退） |
| `completed_at` | 第一次到達 100% 的時間；`NULL`＝還沒讀完 |
| `created_at` / `updated_at` | |

- **未登入的讀者**：localStorage 用相同的結構（key：`steamloom.reading.<projectPublicId>`）。
- **登入時合併**：前端把 localStorage 的紀錄 batch POST 給後端，取聯集；成功後清掉本機資料。
- **進度的計算**（故事和設定一致，符合「前端 UI 統一」的原則）：
  - 文字故事、設定：沿用 `Reader.tsx` 現有的 `readingProgress`（捲動百分比），正文結尾進入可視範圍就算 100%。內容短到一個畫面就放得下時，打開就是 100%。
  - 圖像作品：`目前頁數 ÷ 總頁數`，翻到最後一頁就是 100%。
- **寫入頻率**：進度比已記錄的值高 **5%** 以上才更新，另外在離開頁面（`visibilitychange`／換篇）時補一次。未登入寫 localStorage；已登入用 debounce（約 3 秒）呼叫 API，離開頁面時改用 `fetch(..., { keepalive: true })`。
- **「讀完」**＝`completed_at` 不為空。dependsOn 用這個判斷是否滿足。
- **繼續閱讀**：重新打開一篇讀到一半的內容時，捲到記錄的位置（圖像作品跳到對應頁），並用 snack 提示「已回到上次的位置」，同時提供「從頭開始」的按鈕。

## 3. 防劇透的行為

採用**軟性閘門**（已確認）：還沒讀過的讀者會看到警告和未讀清單，按「我了解，繼續閱讀」就能看，而不是沒讀完就完全看不到。理由：硬性鎖會擋掉「先查設定再決定要不要追」的讀者，而且未登入讀者的紀錄存在 localStorage，本來就擋不住。

- **防劇透是 UX，不是權限**：公開 API 一律回傳完整的設定資料，由前端依閱讀紀錄決定要不要遮。後端不做保密。
- **列表上**：還沒解鎖的劇透設定**連標題都遮**，顯示成「🔒 含劇透的設定・需先讀過：第一冊 03〈頻率不合〉」。因為標題本身就常是劇透（例如「XX 之死」）。點下去走確認流程。
- **設定頁**：正文換成確認卡片（列出還沒讀完的 dependsOn 和各自的進度，每一項都可以點過去讀），確認後才顯示。確認本身不算進度，之後依實際閱讀照常計算。
- **確認後的效果**：只解鎖這一個設定（本機記住「已確認」，下次不用再問），不會把它的 dependsOn 也標成讀完。
- **dependsOn 指向未公開或已刪除的內容**：視為已滿足，也不顯示在未讀清單上（避免洩漏未公開內容的標題）。

## 4. 作品首頁（`work/:projectPath`、`work/:projectPath/lores`）

- Hero 維持現狀。按鈕依閱讀紀錄切換：「從第一篇開始」，或「繼續閱讀：〈最近讀的那篇〉 42%」（最近讀的那篇如果已經讀完，就改指向它的下一篇）。Hero 的資訊列加上整部作品的進度：「已讀完 12 / 24 篇」。
- **故事 Tab**：沿用現有依冊分組的列表，每一列右側加上**進度**：沒讀過就不顯示；讀到一半顯示細進度條＋百分比（例如 `▰▰▱▱ 42%`）；讀完顯示 `✓ 讀完`。
- **設定 Tab**：比照故事列表的樣式，**依設定集（`LoreCollection`）分組**，對應故事的冊；沒有設定集的設定排在最後，標題叫「未歸類」。每一列：標題、摘要、更新時間、進度（和故事列表同一個元件），劇透未解鎖時改成上面的遮罩列。只顯示 `status = completed` 的設定；collection 底下全部都沒公開時，整組隱藏。
- Tab 標籤上顯示數量（「故事 24」「設定 12」）。如果沒有任何公開的設定，**整個「設定」Tab 隱藏**。

## 5. 設定頁（`lore/:publicId`）

- 麵包屑：`首頁 › 〈作品〉 › 設定 › 〈設定集〉 › 〈標題〉`。「設定」連到 `work/:p/lores`，設定集名稱連到 `work/:p/lores#<collectionPublicId>`。
- **不做「同設定集的其他設定」區塊**：底部導覽和麵包屑上的設定集連結已經涵蓋這個需求。
- 正文渲染沿用文字故事的渲染器（asset 簽名、`StorytellerMarkdown`），也支援設定連結。
- 底部導覽列：**只在設定之間**依列表順序（設定集順序 → 設定集內排序）做上一則／下一則，不會跳進故事。
- 有閱讀紀錄時顯示「你讀到〈XX〉→ 回到故事」，避免從分享連結進來的人迷路。
- **限制級**：沿用專案的分級閘門。設定頁和設定摘要彈窗都要先過年齡確認。
- 設定的版本歷史**不公開**（讀者不需要，也可能洩漏刪掉的伏筆）。

## 6. 設定連結（`steamloom-lore://`）

### 語法

```markdown
[白瀨澪](steamloom-lore://<lorePublicId>)
```

- 是 markdown **連結**，不是圖片；顯示文字由作者自己決定（可以寫別名）。
- 可以用在：文字故事正文、圖像作品每一頁的說明（`StoryImagePage.Description`）、設定正文（設定互相連結）。

### 寫入時（後端，比照 `asset_reference.go`）

- `validateMarkdownLoreReferences`：引用的設定必須屬於同一個專案，否則存檔失敗並回傳明確錯誤。**不檢查是否已公開**（作者可以先寫連結，之後再公開）。
- 圖像作品要對每一頁的 `Description` 都做驗證。
- `storyteller_validate_content`（MCP）也要能辨識這個語法。

### 讀取時（公開 API）

- 故事、設定的內容回應新增 `lore_refs` 欄位：`{ [publicId]: { title, summary, collection_name, is_spoiler, depends_on: [{type, public_id, title}] } }`
  - 只包含**已公開**的設定；未公開或已刪除的不放進去。
  - 摘要也直接附上（反正是軟性閘門），點擊時不用再發一次 request。
- 前端渲染：
  - 在 `lore_refs` 裡 → 虛線底線連結，點擊後開摘要小卡（劇透未解鎖就先顯示確認）。小卡上有「看完整設定」，開右側面板（手機版是 bottom sheet），不離開目前的閱讀位置。
  - 不在 `lore_refs` 裡 → **只顯示文字**，不顯示連結、不報錯（讀者不會發現那裡有一個未公開的設定）。
- 圖像說明目前是用 `plainTextFromMarkdown` 渲染成純文字，要改成「純文字＋設定連結」的輕量行內渲染器（只處理 `steamloom-lore://` 連結，不開放其他 markdown）。

### 編輯端

- WYSIWYG：`isSafeHref` 放行 `steamloom-lore://`，工具列和 bubble menu 加「插入設定連結」（選取文字後從設定清單挑，比照 asset picker）。
- 編輯器裡顯示成帶設定圖示的連結；指向已刪除設定的連結標成紅色。
- 圖像作品編輯頁的頁面說明欄位，也要有同樣的插入入口。

## 7. 作者端（工作台／MCP）

- **用詞統一**：工作台、LoreEditor、設定管理、搜尋、通知、稽核紀錄等所有作者端文案：單篇 lore「設定集」→「設定」，collection「分類」→「設定集」（「未分類」→「未歸類」）。MCP 工具描述、server instructions、Skill 文件裡的中文用詞一併修正。
- **LoreEditor**：新增公開狀態開關、摘要欄位、劇透勾選，以及 dependsOn 選擇器（同專案的故事、圖像作品、設定，可以多選、可以排序）。
- **工作台列表**：設定項目加上公開／劇透的狀態圖示（比照故事的 status 呈現）。
- **MCP**：`storyteller_upsert_lore`／`patch_lore` 新增 `status`、`summary`、`is_spoiler`、`depends_on`；`get_lore`／`list_lores` 回傳這些欄位。Server instructions 和 Skill 文件要補上 `steamloom-lore://` 語法說明（讓作者的 AI 能自己幫忙加設定連結）。
- **公開設定時的提醒**：設定正文裡如果引用了未公開的設定或資產，跳出提示（不擋）。

## 10. User Stories

1. 讀者從社群點進 `work/…-Sextet_Resonance`，看到作品首頁，切到「設定」Tab（`/lores`）依設定集瀏覽，不會跟章節列表混在一起。
2. 讀者讀第 3 話時點了正文裡的「中控室」，跳出摘要小卡；按「看完整設定」打開右側面板，讀完關掉，閱讀位置不變。
3. 讀者點了一個劇透設定，看到「需先讀過：第 12 話」，決定先不看；之後讀完第 12 話再回來，就能直接看到內容。
4. 未登入的讀者讀了 5 話（第 5 話讀到 60%）後登入，這 5 話的進度都還在；回到第 5 話時自動捲到 60% 的位置。
5. 作者叫自己的 AI 透過 MCP 在第 7 話正文裡加上設定連結，同時把三個角色設定標記為公開。
6. 作者發表了一話，裡面連到一個還沒公開的設定；讀者只看到普通文字。作者之後公開那個設定，連結就自動出現。

## 11. 常見失敗情境

| 情境 | 處理 |
|---|---|
| 舊連結 `work/:p/<bareId>` | 導向 `story/<bareId>`；SNS 爬蟲的 regex 也要接受舊格式 |
| publicId 不存在或未公開 | 404 |
| 設定連結指向別的專案 | 寫入時擋下 |
| 設定連結指向的設定之後被刪除或取消公開 | 讀者看到純文字；作者在編輯器裡看到紅色連結 |
| dependsOn 指向的內容被刪除或取消公開 | 視為已滿足，不顯示在未讀清單 |
| 讀者清掉 localStorage | 閱讀紀錄消失，劇透要重新確認（可接受） |
| 作者大幅改寫已經讀完的篇章 | 進度維持不變（不追蹤內容版本，可接受） |
| 同一個讀者開兩個分頁讀不同篇 | 各自更新各自的紀錄，互不干擾；同一篇則取最大值 |
| 登入合併時伺服器上已經有紀錄 | 取聯集；`progress` 取較大值，`completed_at` 取較早的時間 |
| 專案改成私人 | 所有設定一起不可見（沿用專案的可見性檢查） |
| 限制級作品的設定頁被直接分享 | 先過年齡確認；SNS 預覽卡沿用專案的限制級規則 |
| 摘要為空 | 取正文前 120 字（去掉 markdown 和設定連結的語法） |

## 14. 實作紀錄

### 閱讀進度（2026-10-07，先於 P1 實作，branch `feature/storyteller-reader-lore`）

使用者要求先做閱讀進度的記錄與統計，設定公開等 P1 項目之後再做。這輪只記錄故事（文字＋圖像），`lore` 的 `target_type` 欄位先預留。

- **後端**：`storyteller_reading_records` 表；`GET/PUT /storyteller/story/:project/reading-records`（需登入）。`PUT` 是批次寫入，平常的回報和登入後的補寫共用同一支。寫入用 MySQL 5.7 的 `INSERT … ON DUPLICATE KEY UPDATE`：progress 取較大值，`completed_at` 只在第一次到 100% 時寫入，`updated_at` 只有進度往前推進時才更新。讀不到的對象（別人的草稿、取消公開、不存在）一律略過、不報錯。`PUT` 列入稽核豁免（隨捲動頻繁回報，屬於介面狀態）。
- **與規格的差異**：
  - 登入合併不另外掛登入 hook，改成**lazy 合併**：讀者登入後打開某部作品時，若本機還留著這部作品的紀錄，就整批補寫後清掉本機資料。
  - 補寫時**不採用前端帶來的讀完時間**（不信任 client 時間），`completed_at` 以伺服器寫入當下為準。
- **前端**：
  - `readingRecordStore.ts`：資料格式、localStorage 讀寫、回報門檻
  - `useReadingRecords.ts`：API 和 localStorage 雙軌、debounce 3 秒、分頁隱藏時用 fetch keepalive 送出
  - `useReadingResume.ts`：回到上次的位置
  - `ReaderProgressBadge.tsx`：列表上的進度顯示
  - `ReaderWorkLanding.tsx`：作品首頁的進度、「已讀完 x / y 篇」、繼續閱讀按鈕
- **暫態值過濾**：進度值必須**穩定 1.5 秒**才寫入（`useSettledReadingProgress`）。換篇時捲動位置會晚一拍（標題會用 smooth scroll 捲回來），中間可能算出錯誤的 100%；圖像作品快速翻頁時，中間經過的頁數也不會被記錄。
- **繼續閱讀的規則**：最近推進的那篇還沒讀完，就回到那篇；已經讀完就往下一篇；後面沒有篇章了（例如最後一篇先讀完），就找第一篇還沒讀完的；全部讀完才顯示「從頭開始閱讀」。

### P1（2026-10-07，branch `feature/storyteller-reader-lore`）

- **後端**：`storyteller_lores` 新增 `status`（預設 `draft`）、`summary`；`LoreRequest.Status`／`Summary` 是指標，省略就不變更（編輯頁自動存檔、舊版 MCP client 都不會帶）。`PublicProject`／`SharedProject` 透過 `attachReaderLores` 帶出 `lores`、`lore_collections`，只放有公開設定的設定集，內文資產連結當下簽名；作者預覽未公開專案時連草稿一起帶（規則同故事）。MCP 的 `upsert_lore`／`patch_lore` 支援 `status`、`summary`，輸出也帶。閱讀進度可以記錄已公開的設定。SNS 預覽卡支援新網址與單篇層級。
