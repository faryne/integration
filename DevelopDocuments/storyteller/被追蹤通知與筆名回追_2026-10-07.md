# 被追蹤通知與筆名回追

- 狀態：已實作（2026-10-07），在 `feature/steamloom-follow-notifications` 分支，尚未併入 main；mockup 見 `follow-notification-mockup/`
- Branch：`feature/steamloom-follow-notifications`
- 前置：站內通知（`站內通知_2026-10-01.md`）、多筆名（`storyteller_author_profiles`）

## 目標

1. 作者的身份（本人或筆名）被追蹤、作品被收藏時，作者收到站內通知。
2. 兩種通知長相不同：追蹤作者＝「人」為主角（頭像＋回追）；收藏作品＝「作品」為主角（封面＋作品名，頭像較小）。
3. 點追蹤者頭像／筆名 → 對方的創作者頁。
4. 「回追」用**被追蹤的那個身份**去追蹤對方：讀者追蹤了我的筆名 P，回追就是 P 追蹤他，不是我本人帳號。

## 為什麼回追一定要用筆名（隱私核心）

筆名的設計前提是「不能被串回本人帳號」（公開輸出只有 pen_name、作者頁不公開筆名的收藏）。如果 A 追蹤了 P，P 的擁有者 B 用**本人帳號**回追，A 會在幾秒內收到「B 追蹤了你」——等於直接把 P＝B 告訴 A。所以：

- 追蹤關係要多記一個「追蹤者用哪個身份」：`follower_profile_id`（0＝本人）。
- 以筆名做的追蹤**不能**出現在本人帳號的任何公開輸出上（作者頁「追蹤的作家」分頁、計數以外的列表）。

## Schema

```sql
ALTER TABLE storyteller_author_favorites
  ADD COLUMN follower_profile_id BIGINT UNSIGNED NOT NULL DEFAULT 0
    COMMENT '追蹤者用的身份；0 = 帳號本人' AFTER user_id,
  DROP INDEX idx_storyteller_author_favorites_user_author_profile,
  ADD UNIQUE KEY idx_storyteller_author_favorites_follower_author
    (user_id, follower_profile_id, author_user_id, author_profile_id);
```

- 既有資料 `follower_profile_id = 0`，行為不變。
- 同一帳號可以本人追蹤 A、又以筆名 P 追蹤 A，是兩筆獨立關係（各自出現在各自身份底下）。
- 收藏作品（`storyteller_project_rankings`）不加身份欄位：收藏作品本來就不公開身份給作者以外的人看，v1 一律視為本人收藏（見「不做」）。

## 通知類型

| kind | 觸發 | 收件人 | view | group_key（冪等） |
|---|---|---|---|---|
| `author.followed` | 建立追蹤（含取消後重新追蹤） | 被追蹤身份的擁有者帳號 | `follower`（新） | `author.followed:{follower_user}:{follower_profile}:{author_profile}` |
| `project.favorited` | 收藏作品（含取消後重新收藏） | 作品擁有者 | `favorite`（新） | `project.favorited:{user}:{project_id}` |

- **同一對關係只會通知一次**：追蹤／取消／再追蹤反覆按，group_key 相同，`INSERT IGNORE` 擋掉（直到 180 天保留期清掉為止）。
- 作者頁上被設成「隱藏」的追蹤／收藏**照樣通知**：hidden 的語意是「不出現在我的公開頁」，不是「對作者匿名」。
- 發送時機：追蹤／收藏寫入成功後同步呼叫 `Notify`，失敗只記 ERROR log、不影響追蹤本身（同安全通知）。
- 自己追蹤自己的筆名已經被既有檢查擋掉（同帳號不能追蹤），不會發通知。

### payload

```go
// 顯示快照（對外輸出）
Actor        *AuthorIdentityOutput // 追蹤者（pen_name、頭像）
TargetPenName string               // 被追蹤的是我的哪個身份；收藏作品則是作品署名
ProjectPublicID / ProjectSlug / ProjectName / CoverURL // project.favorited 用

// 內部鍵（json:"internal"，輸出前清空，前端永遠拿不到）
Internal *NotificationInternal{ ActorUserID, ActorProfileID, TargetProfileID }
```

- 對外輸出時**依內部鍵即時重查**追蹤者目前的筆名／頭像（筆名改過也能連到正確的創作者頁），查不到（筆名刪了、帳號刪了）就退回快照、不給連結、顯示「此身份已不存在」。
- 同時回傳 `follow_back`：`none`（可回追）／`following`（已回追＝互相追蹤）／`unavailable`（對方身份不存在、或我的那個筆名已刪除）。

## 回追 API

```
POST /storyteller/notifications/:public_id/follow-back
```

- 後端從通知的內部鍵拿「對方身份」與「要用哪個身份回追」，前端不傳任何身份資訊 → 不會因為筆名改名打錯人，也不需要把 profile id 暴露給前端。
- `author.followed`：回追身份＝被追蹤的身份（TargetProfileID）。
- `project.favorited`：回追身份＝作品的署名身份。作品只有一個署名身份就直接用；**多個署名身份**時前端顯示下拉選單，只列這部作品實際署名過的身份（不會列出我其他無關筆名），API 多帶 `as` = 選中的筆名，後端驗證它屬於本人且署名過這部作品。
- 回追本身就是一次正常追蹤 → 對方也會收到 `author.followed`，內容頁顯示「已互相追蹤」。
- 已追蹤則冪等回 200。

## 一般追蹤按鈕（作者頁）的連動

v1 不在作者頁加「以哪個身份追蹤」的選擇器，追蹤按鈕仍以本人追蹤。但狀態要能看到筆名追蹤，否則會誤導：

- `GET /authors/:author/favorite` 回應多帶 `following_as: ["P"]`（只回給本人看，不洩漏）。
- 只有以筆名追蹤、本人沒追蹤時，按鈕顯示「已以 P 追蹤」；點下去是取消 **P 的那筆**（帶 `?as=P`），不是新增本人追蹤——避免使用者以為沒追到又按一次，用本人身份再追一次（又把身份串起來）。
- `DELETE /authors/:author/favorite?as=P`：取消以筆名 P 的追蹤；不帶 `as` 維持原本行為（取消本人追蹤）。

## 以筆名追蹤的作家去哪裡管理

- 本人作者頁「追蹤的作家」：**只列 `follower_profile_id = 0`**（公開與本人自己看都一樣），不混入筆名追蹤。
- 筆名作者頁：本人以擁有者身份瀏覽時，多一個「此筆名追蹤的作家」分頁（`is_owner` 才顯示），可取消追蹤；其他人看筆名作者頁仍然沒有收藏分頁（維持 `show_favorites` 現況）。
- 工作台的 `GET /favorites/authors`（我追蹤的作家）回傳全部，每筆多帶 `as`（本人為空、筆名為 pen_name），前端以 chip「以 P 追蹤」標示。

## 前端

- 新 view `follower`：大頭像（點擊→創作者頁）＋「**A** 追蹤了你」／「**A** 追蹤了你的筆名 **P**」＋「回追」按鈕（以 P 回追時按鈕文字「以 P 回追」）。已回追顯示「已互相追蹤」disabled chip。

## 不做（這一輪）

- 以筆名收藏作品
- 被追蹤通知的聚合（「A 等 12 人追蹤了你」）：目前量級一人一則即可；之後粉絲多再改成依日聚合

## User Stories

| # | 情境 | 期望 |
|---|---|---|
| U1 | 讀者 A 追蹤我本人 | 收到「A 追蹤了你」，點 A 頭像到 A 的創作者頁，按回追＝我本人追蹤 A |
| U2 | 讀者 A 追蹤我的筆名 P | 收到「A 追蹤了你的筆名 P」，按「以 P 回追」；A 收到「P 追蹤了你」，看不出 P 是我 |
| U3 | A 收藏我以 P 署名的作品 | 收到「A 收藏了你的作品《X》」，回追預設用 P |
| U4 | A 追蹤／取消／再追蹤反覆按 | 我只收到一則 |
| U5 | 我以 P 回追 A 之後到 A 的作者頁 | 按鈕顯示「已以 P 追蹤」，不會誘導我再用本人追一次 |
| U6 | A 改了筆名後我才點通知 | 頭像連到 A 的新筆名頁 |
| U7 | 我刪掉筆名 P | P 做過的追蹤一併取消；舊通知的回追按鈕變 unavailable |

## 實作備註（跟規格草稿不同的地方）

1. **payload 的 actor 快照只存筆名與頭像**：一開始把整份 `AuthorIdentityOutput`（含整段自介、SNS 連結）存進去，一則就 2KB 上下。輸出時本來就會依內部鍵即時換成最新身份，所以快照只留 `pen_name`／`avatar_url`／`use_default_avatar`（`identityBook.snapshot`）。
2. **沒有筆名的追蹤者一律顯示「一位讀者」**：`fallbackAuthorName` 在沒有筆名時會退回 display name，再退回 **email**，通知文字絕對不能用它。`identityBook.lookup` 把「本人身份但 pen_name 空白」視為不存在，標題用 `anonymousReaderName`，也不給連結、不能回追。
3. **即時補資料走 `storytellernotify` 的 Decorator**：通知層不認識筆名／追蹤，所以 `storytellernotify.Service.WithDecorator` 讓上層在輸出前補資料（`rows` 帶內部鍵、`outs` 已清空）。controller 的 `notifications()` 統一掛上 `storyteller.Service.DecorateNotifications`；列表一頁的追蹤類通知用固定 4 次批次查詢處理（署名身份、身份資料×2、我目前的追蹤），不會隨則數增加。
4. **回追 API 回傳更新後的那一則通知**（含新的 `follow_back`），前端直接 invalidate 通知、作者追蹤狀態、我的追蹤三組快取。
5. **收藏作品的回追候選＝專案所有未刪除的話署名過的身份**（`ProjectSigningProfiles`，沒有 pivot 列算本人），不限公開的話；收件人是作者本人，不會洩漏。已刪除的筆名不會列入。
6. **共用元件**：作者頁與閱讀頁的追蹤按鈕合併成 `FollowAuthorButton.tsx`；作者頁「追蹤的作家」與「我的追蹤」原本各一份幾乎相同的卡片，合併成 `StorytellerFavoriteAuthorCard.tsx`；`AuthorBio` 搬到 `StorytellerAuthorBio.tsx`。`UserProjects.tsx` 672 → 518 行。
7. **筆名頁的「此筆名追蹤的作家」沿用既有 API**：`GET /storyteller/user/:pen/favorites/authors` 對筆名頁原本一律回空陣列，現在改成擁有者看時回傳以該筆名做的追蹤，不另開端點。

## 已知 Bug 記錄

### 作者頁永遠判斷不出「本人」（is_owner 永遠 false）

- **現象**：本人看自己的作者頁時，「追蹤的作品／作家」卡片上的公開／隱藏切換不會出現；追蹤按鈕沒有停用（按下去後端回 "cannot favorite yourself"）。這次的「此筆名追蹤的作家」分頁也因此出不來。
- **Root cause**：`static_site/src/apis/storyteller/project.ts` 的 `usePublicUserStorytellerProjects` 呼叫 `GET /storyteller/user/:username` 時沒帶 `X-Encrypt-Key`，後端 `optionalViewerID` 拿不到登入者，`is_owner` 一律 false。同檔的 `usePublicFavoriteStoryteller*` 其實都有帶，只有這支漏掉。
- **解法**：登入時帶上 session header，query key 加上 `session?.user.id`，切換帳號時會重抓。
- **狀態**：已修（本分支）。
