# Storyteller 成功回饋準則（Snackbar vs 看板娘 Dialog）與導入紀錄

## 背景

Codex 在 `codex/storyteller-dialog-project-mcp` branch 完成 Dialog 重新設計骨架（`StorytellerDialog`／`StorytellerMascotDialog`／`StorytellerConfirmNameDialog`，見同資料夾〈提案說明.md〉）後因額度用盡中斷。Faryne 接手時發現：新骨架大多只套用在「危險操作確認」上，全站多處「操作成功」卻完全沒有任何回饋（不彈窗也不提示），使用者只能從畫面局部變化或頁面跳轉推斷是否成功。這份文件記錄後續補完時定調的準則，以及實際改動的位置，供之後 review 或繼續擴充時參考。

## 準則

- **新增／建立／狀態切換等操作，若成功後不需要使用者做出任何下一步決定** → 直接用 `CustomSnackbar`（`components/common/CustomSnackbar.tsx`）。
- **需要使用者查看重要且僅顯示一次的資訊（如 MCP Token 明文）、需要下一步決定、或屬於危險／不可逆操作** → 用看板娘 Dialog 家族（`StorytellerMascotDialog`／`StorytellerConfirmNameDialog`）。
- Snackbar 沿用全站既有的 local state + `<CustomSnackbar>` 慣例，不引入全域 Provider／Context——這是站上原本就通用的模式，維持一致比另立一套更重要。
- 「成功」與「失敗」不一定要對稱處理：拖曳排序這類已有即時視覺回饋的操作，只補失敗提示，成功不額外提示（理由見下方）。

## 刻意不做／本次範圍外

- **拖曳排序「成功」不額外提示**：與 Faryne 討論後確認——拖曳排序本身就有即時視覺回饋（項目立刻移動到新位置），再跳 snackbar 是重複資訊；且一次拖曳可能連動觸發多筆 `sort` 更新（每個被擠動的項目各自呼叫一次 API），逐筆跳成功 snackbar 反而會洗版。只有「背後持久化失敗、畫面卻已經樂觀更新看起來排好了」這種使用者無從得知的情境才需要提示。
- **MCP Token Dialog 沒有改成 snackbar**：token 明文只顯示一次且需要使用者複製走設定範例，屬於「需要下一步」情境，符合準則應維持 Dialog，只調整視覺骨架。
- **金鑰刪除、Skill 刪除、Token 刪除、專案刪除等危險操作**：這次沒有變動，這些本來就已經是 `StorytellerMascotDialog`／`StorytellerConfirmNameDialog`（`state="danger"`），符合準則不需要調整。

## 驗證方式

- `npx tsc -b`（在 `static_site/` 底下；這個 repo 是 project references 模式，`tsc --noEmit -p .` 不會真的檢查，必須用 `-b`，見〈project_static_site_tsc_check_command〉）。
- 本機用 `POST /storyteller/auth/dev-session`（需後端 `.env` 有 `ENABLE_DEV_AUTH_BYPASS=true`）換一組測試帳號 session，注入 `localStorage["faryne.auth.session"]` 後在瀏覽器逐項操作：新增／編輯金鑰、測試連線（含成功與失敗）、建立 MCP Token、追蹤／取消追蹤專案與作者、我的追蹤頁面公開切換、建立 Skill、編輯專案公開屬性，確認 snackbar 與看板娘 Dialog 都正確出現且清單即時更新。測試用的金鑰／Token／Skill／專案可見度已於驗證後清除或還原。

| --- | --- |

保留例外：刪除成功後清單項目消失、專案刪除後跳列表、AI 回覆／提案狀態更新、以及拖曳排序已直接反映在畫面上的動作，不額外疊成功 snackbar；錯誤仍要可見。表單欄位驗證與需要保留在畫面上的詳細錯誤仍可用 inline `Alert`，不把單次短訊息當作唯一資訊來源。

批次資產直傳並非資料庫交易：若前幾筆已 confirm、後面才失敗，先前建立的資產仍可能保留。這次確保不會回報整批成功，並在失敗後刷新資產清單；重試前仍須確認已建立的項目，完全避免重複上傳需要後續設計 idempotency。

本輪已跑 TypeScript project build、ESLint、56 個 frontend 測試與 production build；尚未指定本機／staging／prod，因此不連資料庫或實際帳號逐頁操作，這裡的「全項目巡查」指前端程式路徑與靜態驗證。
