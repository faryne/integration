# Storyteller Dialog 系統互動提案

## 要解決的問題

- 舊 Dialog 太依賴 title、content、actions 之間的水平線，資訊層級偏硬。
- 看板娘不該被當成每個 Dialog 都必須出現的裝飾。
- 一般操作、重大決策與內容工具需要一致的基礎元件，但不需要完全相同的版型。

## 互動稿涵蓋範圍

1. **刪除作品**：重大且不可復原，梭梭出場；保留輸入名稱確認與危險操作色。
2. **建立作品完成**：重要成功節點，梭梭出場；提供明確的下一步，而不是只顯示「確定」。
3. **重新命名**：一般操作，不顯示梭梭；以精簡版型完成工作。

控制列可切換桌面／手機尺寸，以及 Nocturne、Ivory、Prism 三種 appearance。三種情境由畫面底部切換。

## 視覺原則

- Dialog 內不使用水平分隔線，改以留白、字級與局部底色建立層級。
- Mascot 區只出現在重大決策或重要完成狀態，並佔有明確版面，不貼在角落當裝飾。
- 危險色只放在狀態、主要警告與最終動作，不把整張卡片染紅。
- 手機版把 Mascot 區移到內容上方，保留角色存在感但避免壓縮表單寬度。
- 正式元件仍需沿用既有 theme token、focus handling、keyboard navigation 與 MUI Dialog accessibility。

## 預計元件邊界

```tsx
<StorytellerDialog>...</StorytellerDialog>

<StorytellerMascotDialog
  pose="error"
  tone="danger"
  eyebrow="刪除作品"
>
  ...
</StorytellerMascotDialog>
```

- `StorytellerDialog`：Paper、Backdrop、spacing、responsive layout 與 actions。
- `StorytellerMascotDialog`：在基礎 Dialog 上增加 mascot zone、pose、tone 與 appearance asset。
- `ConfirmNameDialog` 保持全站中性；Storyteller 由 wrapper 承接，不污染其他頁面。

## Review 後第一批導入

- 刪除作品確認。
- 建立作品成功／下一步引導。
- 一般重新命名。
- 收斂工作台既有 `WorkspaceConfirmNameDialog` 與 preview dialog 重複樣式。
