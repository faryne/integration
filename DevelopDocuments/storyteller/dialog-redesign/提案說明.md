# Storyteller Dialog 系統互動提案

## 要解決的問題

- 舊 Dialog 太依賴 title、content、actions 之間的水平線，資訊層級偏硬。
- 看板娘不該被當成每個 Dialog 都必須出現的裝飾。
- 一般操作、重大決策與內容工具需要一致的基礎元件，但不需要完全相同的版型。

## 互動稿涵蓋範圍

1. **刪除作品**：重大且不可復原，梭梭出場；保留輸入名稱確認與危險操作色。
2. **建立作品完成**：重要成功節點，梭梭出場；提供明確的下一步，而不是只顯示「確定」。
3. **重新命名**：一般操作，不顯示梭梭；以精簡版型完成工作。

控制列可切換桌面／手機尺寸，以及 Nocturne、Ivory、Prism 三種 appearance。三種情境由畫面底部切換。

## 視覺原則

- Dialog 內不使用水平分隔線，改以留白、字級與局部底色建立層級。
- Mascot 區只出現在重大決策或重要完成狀態，並佔有明確版面，不貼在角落當裝飾。
- 危險色只放在狀態、主要警告與最終動作，不把整張卡片染紅。
- 手機版把 Mascot 區移到內容上方，保留角色存在感但避免壓縮表單寬度。
- 正式元件仍需沿用既有 theme token、focus handling、keyboard navigation 與 MUI Dialog accessibility。

## Dialog 專用狀態圖

Dialog 不再把既有 `error` pose 當成危險操作提醒，改用獨立狀態圖：

| State | 語意 | 動作 |
| --- | --- | --- |
| `danger` | 不可逆或高風險操作 | 冷靜制止，以手掌與紅橙色安全線形成阻擋 |
| `success` | 重要流程完成 | 展示完成的金色線圈，給出克制但明確的肯定 |
| `thinking` | AI 分析或較長時間處理 | 托腮思考，搭配筆記本與單一發光線圈 |
| `neutral` | 一般重要提醒 | 正視使用者、雙手自然交疊，不帶警告或慶祝語意 |

每個 state 都提供 `nocturne`、`ivory`、`prism`，以及 `256`、`512`、`master` 三種尺寸。CDN 命名為：

```text
https://cdn.faryne.dev/steamloom_assets/suosuo-dialog-{state}-{appearance}-{size}.png
```

## 預計元件邊界

```tsx
<StorytellerDialog>...</StorytellerDialog>

<StorytellerMascotDialog
  pose="error"
  tone="danger"
  eyebrow="刪除作品"
>
  ...
</StorytellerMascotDialog>
```

- `StorytellerDialog`：Paper、Backdrop、spacing、responsive layout 與 actions。
- `StorytellerMascotDialog`：在基礎 Dialog 上增加 mascot zone、pose、tone 與 appearance asset。
- `ConfirmNameDialog` 保持全站中性；Storyteller 由 wrapper 承接，不污染其他頁面。

## Review 後第一批導入

- 刪除作品確認。
- 建立作品成功／下一步引導。
- 一般重新命名。
- 收斂工作台既有 `WorkspaceConfirmNameDialog` 與 preview dialog 重複樣式。

## 驗收條件

- 三個代表情境可在 Desktop／Mobile 與三套 appearance 下正確顯示、操作，沒有內容溢出。
- `danger`、`success`、`thinking`、`neutral` 各自使用 Dialog 專用圖，不再把 `error` 當成 `danger`。
- 12 組 state／appearance 的 `256`、`512`、`master` PNG 都有真正透明背景，能從 CDN 取得正確 `Content-Type`。
- Major Dialog 的 title、content、actions 不使用水平分隔線；內容工具只保留資料結構真正需要的線。
- Mascot 只出現在重大決策、重要完成與長時間處理，不出現在高頻一般操作或內容工具。
- Desktop 採左右配置、Mobile 採上下配置；按鈕、輸入框與文字不因 mascot 壓縮到不可用。
- 危險操作預設不能提交；需要名稱確認時，必須完全符合目標名稱才啟用 destructive action。
- 正式 MUI 元件具備 focus trap、初始焦點、Escape 關閉、ARIA label／description 與鍵盤操作。
- 切換 appearance 後，Dialog 圖片與色彩同步更新，不需要 reload。

## 不做範圍

- 不修改 Storyteller 以外的全站共用 Dialog 外觀。
- 不讓所有 Dialog 都出現梭梭，也不一次替換全部既有 Dialog。
- 不以 `danger` 取代真正執行失敗時使用的 `error` pose。
- 不在這一階段加入角色動畫、語音、Live2D 或新的 appearance。
- 不重寫 MUI Dialog、theme provider 或全站 focus management 基礎設施。
- 不把大型版本比對、資產選擇器等內容工具硬塞進 mascot layout。
