# 專案封面圖

> 狀態：規格已與使用者確認方向（2026-09-21），待實作。branch：`refactor/remove-project-content-type`（沿用，使用者指定）。

## 目的

專案可以設定一張封面圖，顯示在專案卡片上。封面來源是「專案資產集裡既有的圖片」，可以從資產挑選，也可以選本機檔案先上傳成資產再使用。

## 設計

### 存 `cover_asset_id`，不存 S3 key

- 資產是私有的，讀取要走 `signImageURL` 產 CloudFront 簽名 URL，前端不能直接用 key；後端輸出專案時簽出 `cover_url`。
- 「資產原地替換」（`ConfirmAssetReplace`）會換掉 S3 key；專案若存 key，替換後封面就壞了。存 asset id，輸出時才用該資產當下的 `S3Key` 簽，替換不受影響。
- 刪除保護靠 `storyteller_asset_references`：封面要註冊一筆引用（新增 `assetReferenceTargetProjectCover = "project_cover"`，`target_id = project.id`），`DeleteAsset` 現有的引用數檢查就會自動擋下「正在當封面的資產」，不用改孤兒清理。

### 資料表

`storyteller_projects` 新增 `cover_asset_id BIGINT UNSIGNED NULL`（加 index；**不加 FK**，資產是軟刪，由 service 驗證與輸出時過濾）。純 DDL migration（Up／Down），格式參考 `migration/20260921130000-…`。

### 驗證規則（設定封面時）

資產必須：屬於**同一個專案**、`asset_type = image`、未刪除（`is_deleted = 0`）。不符回明確中文錯誤。

### API 語意（重點：整包覆蓋的陷阱）

`PUT /storyteller/projects/:project`（`UpdateProject`）是整包覆蓋，而且首頁「切換公開狀態」（`static_site/src/pages/storyteller/HomeCards.tsx`）會送一份**不含封面欄位**的完整專案資料。所以：

- `ProjectRequest` 新增 `CoverAssetPublicID *string`（`json:"cover_asset_public_id,omitempty"`）：
  - `nil`（欄位省略）＝ **不變更**現有封面；
  - `""` ＝ 清除封面；
  - 非空 ＝ 設為該資產。
- `PatchProject`／`projectRequestWithPatch`（MCP 用）同理，要把現有封面帶過去，不可因為 patch 別的欄位而清掉封面。
- `ProjectOutput` 新增：`CoverAssetPublicID string`（`cover_asset_public_id,omitempty`）、`CoverURL string`（`cover_url,omitempty`，簽名 URL，有時效，前端不落地存）。

### 輸出（批次，不可 N+1）

在 `finalizeProjectOutputs`（[service/storyteller/storyteller.go](../../service/storyteller/storyteller.go)，所有專案輸出的共同收斂點）批次補封面：收集這批專案的 `cover_asset_id` → **一次查詢**取回資產（repository 新增 `AssetsByIDs` 之類，放 `repository/storyteller/asset.go`）→ 逐一簽名。

- 簽名失敗（例如本機沒設 CloudFront 私鑰）**不可讓整個列表 500**：記 log、該專案不帶 `cover_url` 即可。
- 資產已被軟刪或找不到 → 當作沒有封面。
- 封面資產與專案同屬一個專案，所以封面 URL 的可見性自然跟隨專案輸出本身的可見性（private／unlisted 不會被列出），不需另外處理權限。
- 搜尋結果卡片（`/storyteller/search/projects` 系列）的專案資料若不是走 `finalizeProjectOutputs`，要確認有沒有辦法一併補封面（同樣批次查詢）；做不到就先不在搜尋卡片顯示，並在回報中說明。

### 引用登記

- 設定封面：`ReplaceAssetReferences("project_cover", project.ID, [ref])`；清除封面：傳 `nil`；換封面：Replace 自然覆蓋。
- 刪除專案（`DeleteProject`）時一併清掉該專案的 `project_cover` 引用（比照刪 story 時清引用的寫法，見 `storyteller.go` 約 1125 行）。

### 前端

**只在「編輯專案」模式提供封面設定**（`static_site/src/pages/storyteller/NewProject.tsx` 的 `isEditing`）：資產是專案範圍，建立當下沒有 project id，所以建立模式只放一行提示「建立後可在編輯專案設定封面」。

編輯模式新增「封面」區塊：
- 預覽（有封面顯示圖，沒有顯示佔位）。
- 「從資產選取」：重用 `StorytellerAssetPickerDialog`（傳 `projectPublicId`）。
- 「上傳圖片」：選本機檔案 → 走既有資產上傳流程（presign → PUT S3 → confirm，見 `static_site/src/apis/storyteller/asset.ts` 與 `StorytellerAssetUploadDrawer*.tsx`，找現成 hook 重用，不要另寫一套）→ 上傳完成後自動設為封面。
- 「移除封面」（送 `cover_asset_public_id: ""`）。
- 只接受圖片（jpeg／png／webp／gif，與資產規則一致）。

卡片顯示：`StorytellerProjectCard.tsx`（我的專案）、`HomeCards.tsx` 相關卡片、`StorytellerProjectSearchCard.tsx`。有 `cover_url` 時用在卡片頂部原本的裝飾橫幅區塊（`object-fit: cover`、置中裁切），沒有時維持現有的裝飾樣式。**不做**裁切編輯器，圖片比例由使用者自己準備。前端 UI 統一：三種卡片用同一個封面呈現邏輯（抽共用元件或 helper，不要各寫一份）。

其他既有會送整份專案資料的呼叫端（除 HomeCards 外若還有）一律不帶 `cover_asset_public_id`，確認封面不會被清掉。

### MCP

- `storyteller_patch_project` 新增選填 `cover_asset_public_id`（傳資產的 public_id 設定；傳空字串清除；省略不動）；`service/storyteller/tool_registry_project.go` 的參數結構、schema、空 patch 檢查、`ProjectPatch` 都要接上。
- 專案摘要（`toStorytellerProjectSummary`）回傳 `cover_asset_public_id`（不回簽名 URL，agent 用不到且會過期）。
- `storyteller_create_project` **不加**（新專案尚無資產）。

### 不做（刻意）

- 裁切／縮放編輯器；沒有封面時「自動用第一話第一頁當封面」；OG／分享預覽圖；閱讀頁（Reader）標頭的封面；把封面獨立於專案資產集之外的上傳通道。

## 常見 fail 與對策

- 切公開狀態（HomeCards）或其他整包 PUT 把封面清掉 → 依「API 語意」用 `*string`，省略＝不變；務必實測「設定封面後切換公開狀態，封面仍在」。
- `PatchProject` 改別的欄位時清掉封面 → `projectRequestWithPatch` 要帶現有封面。
- 專案列表 N+1 或簽名失敗導致整頁 500 → 批次查詢；簽名失敗只略過該專案封面。
- 資產被替換（`ConfirmAssetReplace`）後封面壞掉 → 因為存 asset id，輸出時用當下 `S3Key` 簽；實測替換後封面仍正常。
- 把正在當封面的資產刪掉 → 引用登記後 `DeleteAsset` 會擋；實測。
- 跨專案資產被拿來當封面 → 設定時驗證資產屬於同一專案。
- 本機沒有 S3／CloudFront 設定，無法實測上傳與簽名 → 至少驗證：API 語意（設定／清除／省略不變）、驗證規則、引用登記、簽名失敗不會弄壞列表；真的無法實測的部分在回報中明說，不要宣稱已驗證。
- 前端型別檢查用 `tsc -b`（不是 `tsc --noEmit -p .`）。
