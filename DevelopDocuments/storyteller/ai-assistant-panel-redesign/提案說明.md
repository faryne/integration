# Storyteller AI 助理面板重新設計提案

日期：2026-09-11  
範圍：故事／設定集編輯器的 AI 助理 Drawer，不改正式功能與 API。

## 結論

建議不要再把 AI 助理視為一個塞進 Drawer 的聊天頁，而要把它做成**貼著編輯器工作的伴隨面板**。

這次提案保留現有能力：

- 一般多輪問答
- `/rewrite`、`/expand` 等單輪 skill
- Agent 人設、API Key、model override
- 選取文字與回覆訊息
- 工作軌跡與 token usage
- 修改提案、diff、套用／否決／復原

但重新安排層級：

1. 作者正在看的內容與這輪帶了哪些上下文，永遠比 model／key 設定重要。
2. AI 的思考過程不搶版面，只交代讀了什麼、有沒有失敗。
3. 修改提案是需要作者決策的「工作成果」，不能只是回覆底下另一張普通卡片。
4. 手機版不接受固定 45vh；改用可停靠 bottom sheet，讓閱讀、輸入與 review 各有合理高度。

## 目前介面的主要問題

### 1. 常駐控制吃掉太多垂直空間

目前結構由上到下是：Drawer 標題、Agent 選單、警告、訊息區、reply／selection banner、TextField、key/model 控制列。桌面尚可，但手機 45vh 幾乎沒有空間同時放對話與輸入。

問題不是再縮小幾個 padding 就能解決，而是重要性排序錯誤：model 與 key 是低頻設定，卻跟對話內容一起常駐。

### 2. 每一種資訊都長得像容器

使用者 bubble、assistant bubble、工作軌跡、引用、提案卡片、composer 都有框線或底色。Drawer 寬度有限時，容器一層包一層會產生大量視覺噪音，也讓真正的決策點不夠突出。

### 3. 上下文是暫時提示，不像可管理的輸入

選取文字目前會在 composer 上方出現 banner，但作者不容易一眼確認這輪還帶了哪些設定集、前後段落或引用訊息，也不容易在送出前移除其中一項。

### 4. skill 與 agentic 問答共用輸入框，但入口仍像隱藏語法

雖然 `/rewrite` 等指令已有說明 Drawer 與選單，使用者仍要先理解 slash command 才能發現。這對熟悉系統的人不難，但在高頻編輯流程中多一次記憶成本沒有必要。

### 5. 手機底部面板只有一個高度，無法同時服務三種任務

手機至少有三種不同需求：

- 快速問一句並回到文章
- 閱讀 AI 長回覆
- 檢視與套用修改提案

固定 45vh 只能勉強照顧第一種；把所有內容繼續壓縮會犧牲後兩種。

## 提案資訊架構

### Header：只保留方向感與待處理事項

常駐內容：

- `AI 助理`
- 目前作用對象，例如「第三章：雨夜」
- `1 項待審`：有提案時才出現，點擊直接捲到最近的 pending proposal
- 更多選單
- 關閉

Agent 人設、model、API Key 移進更多選單。它們仍能逐輪 override，但不再長期佔一整行。

### Conversation：以一輪工作為單位，不以 bubble 為單位

- 使用者訊息保留淡色容器，快速區分指令來源。
- AI 回覆改成接近文件註解的平面內容，左側用細線與 `✦` 標出 speaker。
- 讓回覆正文取得完整寬度，Markdown、code block、引用都少一層內縮。
- 回覆、複製、重試降為弱操作，只在內容底部出現。

### Work trace：一行摘要，必要時才展開

收合狀態只顯示：

```text
✓ 參考 3 項內容 · 12.4k tokens
```

展開後顯示中文化動作與結果，不預設顯示 tool name、arguments、raw response。單一工具失敗留在這裡；整輪失敗才使用 inline error 與 Snackbar。

### Proposal：在回覆裡形成明確的 review checkpoint

提案卡片使用比一般對話更高的 surface、左側黃銅到紅銅的狀態線，固定露出：

- 動作摘要
- 目標範圍
- 修改量
- base version
- status
- 單一 primary action：`檢視變更`

不在窄卡片裡同時放「檢視 diff」「套用」「取消」三個等權按鈕。套用放在完整 diff Dialog，作者讀完內容後才做決定；卡片只留 `不採用` 次要動作。

套用後卡片不消失，改顯示：

- 已套用
- 查看新版本
- 復原

否決後保留紀錄並提供「說明不採用原因」，可直接把原因帶回 composer。

### Composer：先管理上下文，再輸入需求

輸入框上方改為可橫向捲動的 context shelf：

- 選取內容，附一行預覽
- 前後段落
- 設定集數量
- 回覆的訊息／提案
- `＋ 加入`

每一項都能在送出前移除。這讓作者清楚知道 AI 會看到什麼，不必等模型回覆後才發現讀錯範圍。

輸入區內提供高頻 skill 捷徑：

- `/ 改寫`
- `/ 擴寫`

按下仍只是插入既有 slash command，不需要改後端 contract，也保留進階使用者直接打 `/` 的方式。其他指令留在 slash menu，避免 toolbar 再次變得擁擠。

composer 底下只用一行淡字顯示本輪 Agent 與 model；點擊可開同一個設定 popover。

## 桌面行為

### 建議形態

- 寬度：`clamp(440px, 35vw, 520px)`
- 預設：右側 non-modal Drawer，沒有 backdrop
- 編輯器在面板開啟時仍可捲動、選字與修改
- Drawer overlay 不重新計算稿紙寬度，避免開關時文章換行跳動
- 待審提案數量顯示在 Header，作為唯一需要立即注意的 badge

這裡刻意不採固定 dock。作者通常只在需要時打開 AI，關閉後應立刻拿回完整寫作空間；但開啟時也不應用 modal backdrop 鎖死編輯器，因為選字與核對原文是這個流程的一部分。

## 手機行為

改用同一個元件的 `anchor="bottom"`，但支援三個停靠高度：

| 狀態 | 高度 | 用途 |
| --- | ---: | --- |
| Peek | 約 122px | 看目前狀態、補一句需求、立即回文章 |
| Half | 約 58vh | 預設對話與短回覆 |
| Full | 扣除底部工具列後的可用高度 | 讀長回覆、看工作軌跡、處理提案 |

正式版建議支援拖曳；mockup 先以點擊 handle 在三個高度循環。打開 diff 時沿用既有 full-screen Dialog，原文／提案改為上下排列。

不加 backdrop，底下文章維持可見。Half／Full 狀態的 sheet 自己攔截 pointer event；面板以外仍可操作編輯器。

## 狀態處理

### 沒有 API Key

不再放三行常駐 Alert。改在 composer 位置顯示單一 setup state：

```text
尚未設定模型　[設定 API Key]
```

歷史訊息仍可閱讀；只停用送出按鈕。這比讓警告長期佔掉對話高度更符合問題範圍。

### 執行中

- 送出後立即建立 user turn。
- AI turn 顯示目前動作，例如「正在讀取莉亞・人物設定」。
- Drawer 可關閉，後端繼續執行。
- 底部工具列的 AI 按鈕顯示 processing state；完成且有提案時才改成待審提示。

### 失敗

- 單一 tool call：留在 work trace。
- 整輪 run：在對應 AI turn 顯示 inline error，提供 `重試`。
- 網路／API 錯誤同時使用既有 `CustomSnackbar`，符合專案慣例。

### 多提案

Header 顯示待審數量。回覆內仍依提案出現順序顯示卡片，但一次只強調第一個 pending proposal。點 Header 的待審 badge 直接跳到下一筆，不額外新增一套全域列表。

## 實作映射

本提案可以漸進改造，不需一次改後端：

| 現有位置 | 建議調整 |
| --- | --- |
| `StorytellerEditorSideDrawer.tsx` | 桌面 non-modal；手機支援 peek／half／full snap points |
| `StorytellerAgenticPanel.tsx` | 拆成 Header、Conversation、Composer 三區；設定移入 popover |
| `StorytellerAgentPanel.tsx` | 訊息外觀改為 turn；保留既有資料形狀與 action callback |
| `StorytellerAgenticProposalCard.tsx` | 只留一個 primary review action；狀態與回退保留 |
| `StorytellerAgentReferenceDrawer.tsx` | 仍作完整說明；高頻 skill 另外在 composer 提供 shortcut |
| `StorytellerVersionCompareDialog.tsx` | 沿用現況；Dialog footer 承接套用決策 |
| `StorytellerEditorSideTabs.tsx` | 加入 processing／pending review 狀態，不增加新按鈕 |

建議拆出的共用元件：

- `StorytellerAgentHeader`
- `StorytellerAgentTurn`
- `StorytellerAgentWorkTrace`
- `StorytellerAgentContextShelf`
- `StorytellerAgentComposer`

不用把所有內容繼續堆回 `StorytellerAgenticPanel.tsx`；該檔目前已同時負責 query、polling、資料轉換、reference、send flow 與整個畫面，重設 UI 時正好把純呈現區拆開。

## 不在這次提案內

- 不改 agentic API 或 message schema。
- 不改 proposal 安全確認規則。
- 不加入 prompt library、conversation 分頁或獨立 AI 頁面。
- 不把 raw tool log 永久露在主要介面。
- 不做 AI 自動套用。
- 不改 storyteller 全站 theme；mockup 沿用目前 brass dark／light tokens。

## Mockup 操作

開啟同目錄 `index.html` 後可操作：

- 切換桌面／手機尺寸
- 切換深／淺色
- 關閉並重新開啟 AI 助理
- 手機點擊頂部 handle，切換 half／full／peek
- 展開工作軌跡
- 開啟修改提案 diff
- 套用或不採用提案
- 移除／切換 context chips
- 點 `/ 改寫`、`/ 擴寫` 帶入 composer
