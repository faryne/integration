# 檢舉機制

- 狀態：已實作（`feat/steamloom-report`，未 commit）；部署需跑新 migration `20261012100000-create_storyteller_moderation.sql`
- Branch：`feat/steamloom-report`

## 定案的決定

1. **理由表 `storyteller_moderation_reasons`**：讀者檢舉、內部後台封禁／刪除共用同一份理由，只存 key（`reason_key`），文字由前端依 key 對照顯示（日後 i18n 用）。
   - **DB 只存短 slug**（`spam`），不存完整 i18n key；namespace 由前端統一加：`moderation.reason.<slug>`。全站 i18n 的 key 結構日後要調整，只改前端一處，不用跑資料 migration；namespace 前綴寫死在同一處，slug 再怎麼取也不會撞到其他模組的 key。
   - **slug 格式**：`^[a-z][a-z0-9_]{0,63}$`。不允許 `.`（i18next 會把點當成巢狀路徑分隔）、`-`、大寫。MySQL 5.7 不支援 CHECK，改在 seed 與 service 層驗證。
   - **slug 一經使用不可改名、不可重用**：已寫進 `delete_reason`／`reports` 的值是歷史資料。要停用就 soft delete，要換說法就改翻譯檔，不改 slug。
2. **內部刪除理由欄位 `delete_reason`**：存 `reason_key`（`VARCHAR(64) NULL`，不加 FK）。使用者自己刪除時維持 `NULL`。
3. **加欄位的 table**（`assets` 沒有直接公開，**先不做**）：

   | Table | 補 `is_deleted` | 加 `delete_reason` |
   |---|---|---|
   | `storyteller_users` | ✅（回填 `deleted_at IS NOT NULL`） | ✅ |
   | `storyteller_author_profiles` | ✅（回填） | ✅ |
   | `storyteller_projects` | ✅（回填） | ✅ |
   | `storyteller_stories` | 已有 | ✅ |
   | `storyteller_lores` | 已有 | ✅ |
   | `storyteller_author_posts` | 已有 | ✅ |
   | `storyteller_discussion_threads` | 已有 | ✅ |
   | `storyteller_comments` | 已有 | ✅ |

4. **顯示行為不變**：原本 404 的繼續 404；原本有「已刪除」佔位的地方照舊顯示，`delete_reason` 不為空時在佔位後補列原因。
5. **檢舉紀錄表 `storyteller_reports`**：讀者送出的檢舉，後台（之後做）依此處理。

## Schema（MySQL 5.7）

```sql
CREATE TABLE storyteller_moderation_reasons (
  id, reason_key VARCHAR(64) UNIQUE,
  applies_to JSON NULL,            -- 適用的 target_type 陣列；NULL = 全部適用
  is_reportable TINYINT(1),        -- 1 = 讀者檢舉可選；0 = 僅內部操作使用
  sort_order INT,
  is_deleted, deleted_at, created_at, updated_at
);

CREATE TABLE storyteller_reports (
  id, public_id,
  reporter_user_id,
  target_type VARCHAR(32),         -- project / story / lore / user / author_profile / author_post / discussion_thread / comment
  target_id BIGINT UNSIGNED,
  reason_key VARCHAR(64),
  note TEXT NULL,                  -- 讀者補充說明（上限 1000 字）
  status VARCHAR(16) DEFAULT 'pending',  -- pending / resolved / dismissed
  handled_by_user_id, handled_at,  -- 後台處理用，先建欄位
  created_at, updated_at,
  KEY (target_type, target_id, status),
  KEY (status, created_at),
  KEY (reporter_user_id, target_type, target_id)
);
```

### 預設理由（seed）

| reason_key | 讀者可選 | 備註 |
|---|---|---|
| `spam` | ✅ | 廣告、洗版 |
| `harassment` | ✅ | 騷擾、人身攻擊 |
| `hate_speech` | ✅ | 仇恨言論 |
| `unmarked_adult_content` | ✅ | 限制級內容未標示（僅 project / story / lore） |
| `copyright` | ✅ | 抄襲、侵權 |
| `impersonation` | ✅ | 冒充他人（僅 user / author_profile） |
| `personal_info` | ✅ | 洩漏他人個資 |
| `illegal_content` | ✅ | 違法內容 |
| `other` | ✅ | 其他（需填補充說明） |
| `tos_violation` | ❌ | 內部：違反服務條款 |

## API

- `GET /storyteller/moderation-reasons?target_type=comment`：公開，回傳該 target 可用、`is_reportable=1` 的 key（依 `sort_order`）。
- `POST /storyteller/reports`（需登入）：`{ target_type, target_public_id, reason_key, note }`
  - 作者類 target 前端送 `target_type=author` ＋筆名，後端解析成 `user`（帳號本人身份）或 `author_profile`。
  - 其餘以 `public_id` 解析。
- 各輸出 DTO 帶出 `delete_reason`（目前只有留言佔位、通知會用到）。

## 前端

- **檢舉入口**（非本人內容才出現；作者可檢舉自己作品底下的留言／討論串）：
  - 作品首頁 hero、創作者頁追蹤按鈕旁：新增 ⋯ 選單 →「檢舉作品／檢舉創作者」
  - 閱讀頁、公開設定頁：**統一放閱讀工具列**，icon-only 旗子＋tooltip「檢舉」；比照 `discussionButton` 走 `reportButton` 插槽，元件放獨立檔，`Reader.tsx` 只多串接
  - 動態卡片、討論串：既有 ⋯ 選單加「檢舉動態／檢舉討論串」
  - 留言：行內動作列加「檢舉」
- **檢舉 dialog**：原因用**下拉選單**（選項依 target 過濾）＋補充說明（後端回 `note_required` 時必填，目前只有 `other`），送出後 snack「已收到檢舉」；失敗時 dialog 不關、保留內容。沿用站內共用的 `StorytellerDialog`（手機版不另做底部 sheet，跟其他 dialog 一致）。
- **未登入**：按檢舉跳既有的 `LoginPromptDialog`（「檢舉需要登入」），跟討論版、追蹤一致，不直接導頁。
- **i18n（2026-10-10 定案）**：全站 i18n 用 `i18next`＋`react-i18next`。翻譯檔依功能分檔放 `static_site/src/i18n/<語系>/<功能>.json`，在 `src/i18n/index.ts` 合併進預設 namespace 的同名 key，所以 key 一律是「功能.路徑」（例：`moderation.reason.spam`）。元件用 `useTranslation()`，非元件 helper 用 `i18n.t`。檢舉這輪放進 `zh-TW/moderation.json` 的有：理由文字、站方移除補述、檢舉 dialog（標題、對象描述樣板、欄位、按鈕、snack、登入提示）、後台處置 dialog 全部文案。後台列表／詳情頁其他文字與全站共用字串（如「更多動作」）留給全站 i18n 一起搬。
  - 已有 `zh-TW`、`zh-CN`、`en`、`ja`、`ko` 五份（key 必須完全對齊；語系代碼用 BCP 47，韓文是 `ko` 不是國家碼 `kr`）。目前固定 `zh-TW`、不做語系偵測與切換按鈕（其他頁面仍寫死中文，避免同頁中英混雜）；開發時可在 console 用 `(await import('/src/i18n/index.ts')).default.changeLanguage('en')` 預覽。
  - 「已由站方移除」一律用整句樣板（`moderation.removedByStaff.comment／reply／notice.comment／notice.post`），主詞跟原因放在同一句，不拼片段，各語系語序才能各自調整。
- **原因顯示**：
  - 本人刪除（`delete_reason` 為空）文字不變：`此留言已刪除`
  - 內部刪除：`此留言已由站方移除，原因：廣告、洗版`
  - 通知：`（留言已由站方移除，原因：廣告、洗版）`／`（動態已由站方移除，原因：…）`
  - 「↪ 回覆 已刪除的留言」不補原因
- mockup：`report-mockup/index.html`

## User Story

- 讀者看到洗版留言 → 留言「⋯」→ 檢舉 → 選「廣告、洗版」→ 送出 → 看到「已收到檢舉」。
- 管理者（之後的後台）以 `tos_violation` 刪除某則留言 → 其他讀者看到「此留言已刪除（原因：違反服務條款）」。
- 管理者刪除某作品 → 讀者照舊 404（作者端通知見 TODO）。

## 常見失敗與應對

| 情境 | 應對 |
|---|---|
| 檢舉自己的內容 | 400，前端不顯示檢舉入口 |
| 目標已刪除／無權限閱讀（私人作品、缺分享 token） | 404，沿用既有閱讀權限檢查 |
| 同一人對同一目標重複檢舉（仍 pending） | 200 不新增，前端一樣顯示「已收到檢舉」 |
| 理由不適用於該 target、或非 reportable | 400 |
| 選 `other` 沒填補充說明 | 400，前端送出前先擋 |
| 未登入 | 點檢舉導去登入 |
| 大量灌檢舉 | v1 只做重複去重；需要時再加 Redis 速率限制 |

## 實作筆記

- **API**：`GET /storyteller/moderation-reasons?target_type=`（公開）、`POST /storyteller/reports`（需登入）。故事／設定要帶 `project_public_id`；不公開作品帶 `share`。
- **前端入口集中在 `ReportProvider`**（掛在 `StorytellerLayout`）：各處只呼叫 `useOpenReport()(target)`，登入提示、dialog、snack 都在 provider 處理。元件在 `components/storyteller/report/`。
- **「是不是自己的」判斷**：作品／創作者用既有 `is_owner`；動態用 `is_owner`；討論串與留言新增 `is_mine`（看的人＝發言帳號，任一身份）。
- **刪除原因輸出**：`CommentOutput.delete_reason`、通知 payload `delete_reason`（貼文整則被移除時以貼文理由為準）。
- `users`／`author_profiles`／`projects` 的既有 soft delete 改成同時寫 `is_deleted=1`；讀取條件仍沿用 `deleted_at IS NULL`（兩者一致，之後要統一再改）。
