# 創作者檔案（多重筆名）

## 目的

同一個 Google 帳號底下，想用不同筆名／創作者身份發表不同類型的故事，例如「Faryne」發表個人創作、「Faryne with Claude」發表跟 AI 共同創作的故事。帳號本身的登入／擁有權維持統一，不受影響——這只是「一個帳號底下的公開創作身份要不要能有多個」的問題。

這份文件目前只整理現況調查跟待確認清單，細節還沒定案。

## 現況（資料模型調查結果）

`storyteller_users`（筆名／作者檔案表）目前 `user_id` 跟 `pen_name` 都是**全站唯一**（1 對 1）：

- migration `20260623123000-create_storyteller_users.sql`：`UNIQUE KEY (user_id)`
- migration `20260704100000-add_unique_index_to_storyteller_users_pen_name.sql`：`UNIQUE KEY (pen_name)`

「`user_id` 就是作者身份」這個假設貫穿了好幾條鏈路，都需要留意：

- **`Project` 直接掛 `user_id`**（`storyteller_projects.user_id`），作者顯示名稱是拿 `project.user_id` 反查唯一一筆 `storyteller_users` 組出來的（`service/storyteller/storyteller.go` 的 `authorOutput()`／`projectOutput()`）。同一帳號的所有作品現在永遠顯示同一個筆名。
- **公開作者頁 `/user/:username`**（`PublicUserProjects`）是「筆名 → 唯一 user_id → 撈這個 user_id 底下所有作品」的兩段查詢。如果一個帳號有兩個筆名，現在的邏輯會把兩個筆名的作品全部混在同一個作者頁裡。
- **追蹤作者**（`storyteller_author_favorites`）的外鍵 `author_user_id` 直接指向 `users.id`（帳號本身），不是筆名。讀者沒辦法只追蹤某個筆名而不追另一個。
- **MCP 工具／PAT**（`service/mcp/storyteller_tools.go`、`middleware/storytellerpat`）也是綁 `user_id`，同一把 PAT 建出來的所有 project 永遠算同一個作者。
- **收藏／評分**（`storyteller_project_rankings`）不受影響——這個表的對象是 `project_id`，跟作者身份無關，只要 Project 本身能歸屬到正確的筆名，這塊不用動。

專案裡有「一個 user_id 底下多筆資源」的既有慣例可以參考（`storyteller_agents`、`storyteller_provider_apikeys`、`storyteller_personal_access_tokens` 都是 `user_id` + 一個區分欄位的簡單 1-to-many 設計），但那些都是使用者自己用的私有工具，不會被其他表拿來當「公開作者身份」JOIN。真正的複雜度在於：要把 `storyteller_users` 從「帳號附屬設定」升級成一個**被 `Project`、`author_favorites`、MCP PAT 都拿來當外鍵引用的獨立身份實體（profile_id）**，而不是帳號本身直接兼任身份。

規模上比分冊功能更大一圈：分冊只動 `Story` 一張表跟它的下游顯示；這個會動到 `Project`、`author_favorites` 兩張核心表的外鍵語意，牽連 Project 歸屬、作者頁查詢、追蹤作者、MCP 授權四條主要鏈路。

## 待確認事項

以下都還沒想清楚，先列出來，之後定案了再回來補開發規劃：

- 筆名要不要各自獨立的簡介／頭像／SNS 連結，還是這些欄位還是掛在帳號層級、共用同一份，只有 pen_name／作品分類可以有多個？
- 舊資料遷移：現有帳號那一筆 `storyteller_users` 要不要自動變成該帳號的「預設筆名」？
- 建立 Project 時要不要能指定用哪個筆名發表？事後可不可以把整個專案改掛到別的筆名底下？
- 追蹤作者的語意：讀者追蹤的是「某個筆名」還是「整個帳號（底下所有筆名）」？兩者都要支援，還是只選一種？
- MCP PAT 要不要綁定特定筆名（一把 PAT 只能幫某個筆名建立內容），還是呼叫工具時額外指定要用哪個筆名？
- 公開作者頁的 URL 結構：每個筆名各自一個獨立的 `/user/:pen_name` 頁面（彼此看起來像不相關的兩個作者），還是同一個帳號頁面下再切換筆名分頁？
- 要不要有「切換創作者身份」的介面（例如工作台選單可以切換目前用哪個筆名在管理專案），還是每個專案固定歸屬某個筆名、不需要「切換」這個概念？
- 這個功能跟未來「單冊／單話販售」規劃有沒有關聯（例如銷售收益要不要按筆名分開統計）？

## 影響範圍（初步預估，待細節定案後展開）

- **後端**：`storyteller_users` schema（拿掉 `user_id` 的 unique、新增可被引用的 profile 主鍵）、`Project` 歸屬欄位、`author_favorites` 外鍵語意、MCP PAT 授權範圍
- **前端**：工作台專案建立／編輯流程可能需要選筆名、公開作者頁與追蹤功能改用筆名識別、可能需要新增「切換身份」的 UI
