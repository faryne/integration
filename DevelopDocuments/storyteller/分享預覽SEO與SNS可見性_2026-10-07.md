| # | 現況 | 影響 |
|---|------|------|

## A. 分享預覽（OG）

### A-1 可見性規則（`/sns` 回應）

| 網址 | 狀況 | HTTP | meta |
|------|------|------|------|
| `work/:project[...]` | 公開專案 | 200 | 完整，`index, follow` |
| `work/share/:token[...]` | 不公開連結專案，token 有效 | 200 | 完整，`noindex, nofollow`（維持現行） |
| `work/:project[...]` | 私人／已刪除／不存在，或不公開連結專案沒走 share token | **404** | 只出「找不到這個作品｜SteamLoom」，不帶任何作品資訊，`noindex` |
| `.../story/:id`、`.../lore/:id`、`.../versions/:v` | 專案可見，但那篇是草稿、設定未公開或已刪除 | **404** | 同上 |
| `work/:project/{lores,stories,images}` | 分頁，不是內容 | 200 | 作品層級 |
| `user/:penName[/...]` | 筆名存在 | 200 | 「筆名的作品」、自介、頭像 |
| `user/:penName[/...]` | 筆名不存在 | **404** | 同找不到 |
| 任何作品頁 | 限制級（`rating=restricted`） | 200 | 標題保留；**描述換成固定的年齡提示**；**圖換成品牌預設圖**（不出封面） |
| 設定頁 | 含劇透的設定 | 200 | 維持現行（標題換成「含劇透的設定」） |

- 404 的 body 還是保留那份輕量 HTML 和 `location.replace`，真人誤用爬蟲 UA 開到時會落到 SPA 的 404 頁。
- nginx 用 `error_page 418 = @steamloom_sns` 轉給後端，沒開 `proxy_intercept_errors`，後端回的 404 會原樣送給爬蟲，不用改。

### A-2 OG 圖卡

**穩定網址**：`og:image` 不放簽名網址，改指向新端點，平台什麼時候重新抓圖都能拿到：

```
https://steamloom.works/og-image/project/{projectPublicID}.jpg
https://steamloom.works/og-image/story/{projectPublicID}/{storyPublicID}.jpg
（分享連結）/og-image/share/{token}[/{storyPublicID}].jpg
```

nginx 的 steamloom server 加 `location ^~ /og-image/`，轉給後端 `/sns-image/...`。faryne.dev 網域用 `/sns-image/...` 原路徑即可。

**端點行為**：
1. 用跟 A-1 相同的可見性判斷：看不到就回 404，限制級就 302 到品牌預設圖。
2. 選圖順序：圖像作品單話用該話第一頁 → 專案封面 → 品牌預設圖。文字故事和設定用專案封面。
3. 用現有的 `disintegration/imaging` 合成 **1200×630 JPEG**，**不在圖上壓文字**（平台卡片本身就會顯示標題和描述，壓字還要內嵌 CJK 字型，成本不划算）：
   - 圖比例 ≥ 1.6（橫幅）：依封面焦點 `cover_focal_point` 裁成 1.91:1。
   - 其他（直式、方形書封）：用同一張圖放大、模糊、壓暗當背景，中間放完整、不裁切的封面。書封不會被裁成一條橫帶。
4. 快取：Redis key `sns:og:{assetPublicID}:{fx}:{fy}`，保留 7 天；換封面、調焦點後 key 就變了，自然失效。回應帶 `Cache-Control: public, max-age=86400`。
5. 品牌預設圖：新增一張 1200×630 的 `steamloom-og-default.jpg`（以現有 `steamloom-icon` 置中、品牌底色），同時修正 SteamLoom 網域用到 faryne 圖示的問題（第 3 點）。
6. meta 補上 `og:image:width`／`og:image:height`、`og:image:alt`（用標題）。

### A-3 單篇層級補強

`storytellerProjectMeta.Items` 多帶 `CoverURL`，圖像作品要有第一頁的 asset 才能選圖。另外帶 `Rating`，限制級規則要用。

## B. SEO

1. **SteamLoom 自己的 robots.txt／sitemap.xml**：nginx steamloom server 加 `location = /robots.txt`、`location = /sitemap.xml`，轉給後端動態產生。
   - robots：`Allow: /`，`Disallow: /my/`、`/oauth/`、`/work/share/`、`/project/`（工作台編輯頁），`Sitemap: https://steamloom.works/sitemap.xml`。
   - sitemap：首頁、公開專案首頁、公開專案中已發佈的故事、已公開而且不是劇透的設定、有公開作品的作者頁。`lastmod` 用 `updated_at`。上限 50,000 筆，超過就截斷並寫 log（目前規模用不到 sitemap index）。
   - 後端快取 1 小時（Redis）。
2. **JSON-LD 修正**：`isPartOf.url` 跟著網域走（SteamLoom 指 steamloom.works）。單篇故事的 `@type` 改成 `CreativeWork`，帶 `author`（筆名）。
3. **faryne.dev/storyteller/\* 的 canonical 統一指向 steamloom.works**（後端 `/sns` 和前端 `useTitle` 都改），避免兩個網域重複收錄。
4. **前端補 `noindex`**：Reader 和作者頁在「找不到／載入失敗」狀態設 `noindex, nofollow`，解決 Googlebot 的 soft 404（第 8 點）。作者頁的 description 帶自介。
5. Googlebot **不**加進 `$is_social_bot`：Google 會執行 JS，餵它輕量 HTML 加 JS redirect 反而像 cloaking，所以維持走 SPA。

## C. SNS 連結可見性

**資料**：在 `storyteller_users`、`storyteller_author_profiles` 各加一欄 `sns_private_keys JSON NULL`（字串陣列，記哪些 key 設成「僅自己」）。

> 為什麼不把 `sns_links` 的值改成 `{url, visibility}`：分開放可以讓 `sns_links` 的對外契約（公開作者頁、MCP client、既有資料）完全不動，也不用寫資料轉換 migration。

- **寫入**：`UserProfileRequest`、`AuthorProfileRequest` 加 `sns_private_keys`。正規化時，不在 `sns_links` 裡的 key 直接丟掉。
- **輸出**：
  - 公開身份（`selfIdentityOutput`、`extraIdentityOutput`，也就是作者頁、作品作者欄、追蹤清單）用同一個 helper `publicSNSLinks(links, privateKeys)` 濾掉私密的連結。
  - 本人看的 `UserProfileOutput`、`AuthorProfileOutput` 全帶，加上 `sns_private_keys`。
  - 本人逛自己的公開作者頁時，看到的也是濾過的版本，跟「公開專案一律排除草稿」的原則一致。
- **MCP**：`storyteller_create_profile`、`storyteller_update_profile` 加選填的 `sns_private_keys`，輸出也帶。
- **前端**：抽出共用元件 `StorytellerSnsLinksEditor`，`Profile.tsx` 和 `AuthorProfilesPanel.tsx` 目前各自有一套 SNS 編輯 UI，這次合併成一套。每一列多一個「公開／僅自己」切換，新增的列預設公開。改 key（換類型、改自訂名稱）時，可見性設定跟著那一列走。
- 預設全部公開，舊資料 `NULL` 等同全公開。

## User Story

1. 讀者在 LINE 群組貼某一話的連結，預覽卡顯示「話名｜作品名」、那一話的摘要，以及用封面合成的橫式圖卡；書封是直式的也不會被裁成一條。
2. 作者把作品改成私人。之後有人在 Discord 貼舊連結，爬蟲拿到 404，不出預覽卡；Google 下次爬到時是 noindex 或 404，作品會退出索引。
3. 作者想把 Discord 邀請連結留給已經追蹤的熟人，又不想被陌生人看到：設成「僅自己」後，公開作者頁和公開 API 都不會出現這個連結。

## 常見失敗情境與處理

| 情境 | 處理 |
|------|------|
| 平台已經快取舊卡（作品改私人後，FB 上還是舊預覽） | 我們這邊清不掉平台快取。文件註明可以用 FB Sharing Debugger 重新抓；Discord、LINE 的快取過一段時間會自己失效 |
| 封面在 S3 讀取失敗，或是格式不支援 | 退回品牌預設圖並寫 warn log。另外 import `golang.org/x/image/webp`，支援 webp 封面 |
| 超大圖解碼吃爆記憶體 | 先用 `image.DecodeConfig` 看尺寸，超過 40MP 就直接用預設圖 |
| 爬蟲大量打 og-image | Redis 快取加上 `Cache-Control`；合成失敗也短暫快取（5 分鐘）預設圖結果，避免重試風暴 |
| 舊網址 `work/:p/:id` 沒有種類前綴，而 id 剛好是 `lores`／`stories`／`images` | 視為分頁不是內容，不誤判成 404 |
| 改 SNS 類型或自訂名稱後，私密設定掉了 | 前端用列（row）保存可見性，送出時才組 `sns_private_keys`；後端把孤兒 key 丟掉 |
| 舊版 MCP client 更新筆名時不帶 `sns_private_keys` | 指標欄位，省略就不變更（跟 `LoreRequest.Status` 同一套規則） |
| sitemap 把草稿或劇透設定洩漏出去 | sitemap 跟 `/sns` 共用同一組可見性條件，`meta_test`／`sitemap_test` 都要涵蓋私人、草稿、劇透、限制級 |

## 不做

- 圖卡上壓標題文字（需要內嵌 CJK 字型，平台卡片本身已經會顯示標題）
- 限制級作品的封面模糊版預覽圖（直接用品牌預設圖，最省事也最保險）
- 預渲染（prerender）storyteller 動態頁給 Google

## 已知 Bug 記錄

### LINE App 內建瀏覽器開分享連結會無限重新整理（2026-10-07，已修）

- **現象**：在 LINE 裡點 faryne.dev／steamloom.works 的連結，頁面一直重新導向、打不開。
- **Root cause**：nginx 的 `$is_social_bot` 用不分大小寫的 `LINE` 比對 UA；LINE 內建瀏覽器的真人 UA 帶 `Line/13.x`，被當成爬蟲拿到 `/sns` 的 meta HTML，裡面的 `location.replace` 導回同一個網址，又被當成爬蟲。
- **解法**：改成比對 `line-poker`（LINE 預覽爬蟲的 UA 是 `facebookexternalhit/1.1;line-poker/1.0`，本來就會被 `facebookexternalhit` 命中）。
- **狀態**：已修，需要更新 nginx 才會生效。

### 社群爬蟲抓預設圖拿到 HTML（2026-10-07，已修）

- **現象**：預覽卡的預設圖（`/faryne-icon-1024.jpg` 等）破圖。
- **Root cause**：爬蟲抓 `og:image` 用的 UA 跟抓頁面是同一個，nginx 只看 UA，把圖片請求也轉去 `/sns` 渲染 HTML。
- **解法**：新增 `$sns_render` map，「爬蟲而且不是靜態檔副檔名」才轉 `/sns`。
- **狀態**：已修，需要更新 nginx 才會生效。

### SteamLoom 的 og:url 指向不存在的 /sns 路徑（2026-10-07，已修）

- **現象**：分享 steamloom.works 的連結，部分平台（FB 會照 `og:url` 重抓）最後顯示通用卡。
- **Root cause**：`og:url` 一律組成 `{origin}/sns{path}`，但 steamloom.works 的 nginx 沒有 `/sns` 路徑，重抓時打到的是 SPA 或比對不到 meta。
- **解法**：SteamLoom 的 `og:url` 改成等於 canonical（爬蟲打原網址就會被 nginx 轉到 `/sns`）。其他站維持原樣。
- **狀態**：已修。

### steamloom.works 的分頁標題帶著 faryne.dev 後綴（2026-10-07，已修）

- **現象**：steamloom.works 上的 `document.title` 是「X - SteamLoom | Faryne 的實驗室 by faryne.dev」。
- **Root cause**：`helpers/title.tsx` 的 `getRouteSiteName` 只認得 nekomaid、galgame，SteamLoom 落到預設站名。
- **解法**：SteamLoom 頁面（獨立站或 `/storyteller` 巢狀）的站名改成 SteamLoom；標題本身已經帶品牌名時不再重複補。
- **狀態**：已修。

### 作者動態頁沒有社群預覽、創作者頁格式不一致（2026-10-08，已修）

- **現象**：分享 `/user/:筆名/posts`、`/user/:筆名/posts/:id` 只出「SteamLoom」通用卡；作者頁的 `og:image` 是 96px 的 Google 頭像，FB Sharing Debugger 判定未達 200×200 而無效；收藏分頁的標題沿用「X 的作品」。前端標題是「X 的作品 - SteamLoom」，後端卡片是「X 的作品 | SteamLoom」。
- **Root cause**：作者動態上線時，`storytellerUserPattern` 只認作者首頁與收藏分頁；頭像直接拿資料庫網址；前後端標題分隔符各寫各的。
- **解法**：創作者頁 meta 拆到 `service/sns/storyteller_author_meta.go`，標題跟前端分頁名稱一致：

  | 網址 | 標題 | 描述 |
  |------|------|------|
  | `user/:筆名` | `筆名 的作品 \| SteamLoom` | 自介（截 150 字），沒有就「筆名 在 SteamLoom 的作品。」 |

### 需要登入的頁面給爬蟲的是 `index, follow`（2026-10-08，已修）

- **現象**：`/my/workspace/...` 這類工作台網址，社群爬蟲拿到 SteamLoom 通用卡，`robots` 卻是 `index, follow`，跟 `robots.txt` 的 Disallow、前端的 `noindex` 不一致。
- **處理原則**：爬蟲沒有登入狀態，不回 403／404（不然工作台連結一律沒有預覽），維持通用卡、HTTP 200；**不查 DB、不帶作品資訊**（避免拿 `/my/workspace/:id` 試探 id 是否存在）。
- **解法**：`storytellerPrivatePattern`（`/my`、`/oauth`、`/mcp`、`/search`，對應 `sitemap.go` 的 Disallow 清單）只補 `noindex, nofollow`。之後 Disallow 清單有增減要一起改。
- **狀態**：已修，後端重新部署後生效。
