# AV 女優別名（規格＋bug 記錄）

> 狀態：已部署 prod（2026-10-31），已手動跑過 `av-sync-dmm-aliases` 並驗證；每週六排程第一次自動執行（2026-11-07）待確認。mockup：`av-actress-aliases-mockup/index.html`。前置：[AV同名女優區分_2026-10-30.md](AV同名女優區分_2026-10-30.md)（`actressVideoQuery`、對照表）。

## 起因：女優頁漏掉帶別名的影片（已知 Bug 記錄）

- **現象**：DMM 影片的 `actresses` 常寫成 `澤村レイコ（高坂保奈美、高坂ますみ）`，但 xcity 的女優名字只有 `澤村レイコ`。女優頁的出演影片：`澤村レイコ` 0 部（帶別名的寫法有 2,227 部），`川上ゆう` 只有 14 部（`川上ゆう（森野雫）` 有 2,887 部）。影片頁的出演 chip 連到 `/av/actress?name=澤村レイコ（…）`，女優搜尋也找不到人。
- **root cause**：女優頁和影片搜尋的 `actress` 篩選都用 `actresses.keyword` 做 `term` 完全相符查詢，所以括號裡帶別名的寫法永遠對不上。
- **解法**：查詢時多比對「名字（」開頭的寫法（prefix）；另外新增 `aliases` 欄位，讓別名本身也可以當女優頁的入口。詳見下面的規格。
- **狀態**：已修正並部署 prod（2026-10-31）。

## 現況（查 prod ES，2026-10-31，唯讀）

- `dmmvideos` 共 50,512 個不同的女優名字，**帶括號的只有 437 個**，相關影片約 6.6 萬筆次。（主題頁規格寫的「2.2 萬個」是錯的。）
- 寫法：幾乎都是全形 `本名（別名、別名）`。特殊寫法各只有 1 個：半形 `七空うみ(七海そら)`、括號前有空白 `みひな （…）`、全半形混用 `江波りゅう（RYU)`、兩組括號 `シェリー（Shelly、藤井シェリー）（しぇりー）`。
- 437 個裡：本名對得到 xcity／手動上稿女優的有 275 個（其中 3 個是同名女優）；對不到的 163 個，大多是 xcity 用別名建檔，例如 DMM 寫 `芦名未帆（稲森しほり）`、xcity 只有 `稲森しほり`。
- 有 90 個別名剛好也是 xcity 另一位女優的本名，例如 `佐藤みき（佐藤美紀）`，兩筆都在 xcity。
- xcity 個人頁的 h1 本來就有 `名字(かな)[別名,別名]`，`service/xcity` 也已經解析成 `AliasName`，只是同步時沒存。

## 規格

### 1. 名字正規化（共用）

`service/av/actress_name.go`，女優主題頁統計也用同一組：

- `actressBaseName(name)`：取第一個 `（` 或 `(` 之前的部分，去頭尾空白。
- `parseActressAlias(name)`：拆成本名＋別名（括號裡用 `、` 分隔，多組括號一起拆）。
- `actressNameVideoQuery(name)`：`actresses.keyword` 完全相符，**或**以 `name（`、`name(`、`name （`、`name (` 開頭。
  - 跟 `actressBaseName(x) == name` 是同一件事。
  - prefix 只掃 keyword 的 term dictionary，成本跟 term 差不多；一定要緊接括號，`あい` 不會撈到 `あいり`。
- 前端 `helpers/avActressName.ts` 的 `actressBaseName` 是同一條規則。

### 2. 別名欄位 `aliases`

- 存在 `dmm_actresses.info`（JSON）的 `aliases`，ES `dmmactresses` 同名欄位。不含本名，去重複。
- 來源，三者取聯集：
  1. **xcity**：同步時存 `AliasName`。同步會保留 DB 裡已有的別名（`AliasesByDomain` 先載入），不然每週都會把 DMM 補的洗掉。
  2. **DMM 名字括號**：每週 job `av-sync-dmm-aliases`（週六 04:20，排在 xcity 週三同步之後）。一組「本名＋別名」要**剛好對到一位**女優才補：本名剛好一位就是她；本名沒人時，別名裡剛好只有一位女優才算。同名女優分不出是哪一位，跳過。
  3. **手動上稿**：網頁表單、MCP `av_actress_submit` 都可以改 `aliases`。手動改過（`overrides` 有 `aliases`）的女優，DMM job 不會再動她的別名。
- 合併到同名女優（上稿新增單）時，別名跟興趣一樣取聯集。

### 3. 女優頁

- `/av/actress/:name` 的 `:name` 可以是本名或別名。女優搜尋：本名完全相符加權 10、別名完全相符加權 5，所以別名另有一位同名的本名女優時，開的是那一位。
- 出演影片**照網址上的名義分開**：`actressVideoQuery(row, name)`，`name` 由 `actressPageName` 決定（網址上的名字是本名或她的別名就用它，否則用本名）。
  - `/av/actress/澤村レイコ`：`澤村レイコ`＋`澤村レイコ（…）`。
  - `/av/actress/高坂保奈美`：`高坂保奈美`＋`高坂保奈美（…）`。
  - `澤村レイコ（高坂保奈美、…）` 只算在本名底下。
- 同名區分的 ID 規則改成「名字相符，**而且**（ID 在 D 裡，或影片沒有 `actress_ids`）」。原本只要 ID 相符就算、不看名字，同一個 DMM ID 用別名發的作品會混進本名頁。
- 畫面：資料卡名字下面多一排「名義」chip（本名＋別名，目前這頁反白，連到 `/av/actress/<名義>?xcity_id=`）；名義不是本名時，出演影片副標加上「○○ 名義・」。沒有別名不顯示。
- 網址帶參數、名字是她的別名時不會被換成本名網址（`isActressName`）。

### 4. 影片頁出演 chip

顯示文字照 DMM 原文，連結改用 `actressBaseName`：`/av/actress/澤村レイコ?dmm_id=…` 或 `/av/actress?name=澤村レイコ`。

## 部署

- 不用 migration：`info` 本來就是 JSON 字串。
- ES 不用先 PUT mapping：`aliases` 走 dynamic mapping，結果跟 `name` 一樣是 text＋keyword（`ignore_above: 256`）。
- 上線後手動跑一次 `-cmd av-sync-dmm-aliases`，確認 log 的 `names`／`skipped`／`updated`。xcity 的別名等下次週三同步才會補上。
- 驗證：`/av/actress/川上ゆう` 出演影片約 2,901 部；`澤村レイコ` 約 2,227 部。

## 常見失敗情境

| 情境 | 結果 |
|---|---|
| 別名掛錯人 | 上稿改別名，overrides 記住，DMM job 之後不會再加回來 |
| 手動上稿（manual domain）的女優刪掉別名 | 這類通常沒有 overrides，DMM job 下週可能又加回來（已知限制） |
| 網址上的名字既不是本名也不是別名（舊連結、手打） | 出演影片退回用本名 |
| 舊的修改單（建立時還沒有 aliases） | `aliases` 讀成空陣列；DMM job 補了別名後，這類待審單會顯示「提交後資料已變更」 |

## 測試記錄（2026-10-31，本機）

- API：`actress=川上ゆう` 2,901 部（不含 `川上ゆうこ`），`actress=澤村レイコ` 2,227 部。
- 用測試索引 `dmmactresses_alias_test_20261031`（只放一筆 `川上ゆう`，aliases=`森野雫`，測完已刪）看畫面：`/av/actress/森野雫` 開川上ゆう的資料卡、「森野雫」反白；點 chip 在本名和別名之間切換，網址保留 `?xcity_id=246`；修改表單預填別名、顯示「已修改 0 個欄位」；影片頁 `川上ゆう（森野雫）` chip 連到 `/av/actress?name=川上ゆう`。
- 別名頁的影片數這次測不到：判斷名義看的是 DB 的 `info.aliases`，測試只寫了 ES，所以退回用本名。

## 不做

- 用 wildcard 比對括號中間的別名（`*（*高坂保奈美*`）：誤判風險高，改由 `aliases` 欄位處理。
- 名義 chip 顯示各名義的作品數：每個名義要多打一支 count 查詢。
