# 匯率爬蟲移植到 Go＋新增四家銀行

> 狀態：已實作（2026-10-22，branch `feat/rates-go-crawler`）。台銀因 JS challenge 停用。上線後要關掉 PHP 排程（見〈上線注意〉）。

## 目標

- 把 `php7-version` 的台銀（`rate:bot`）、土銀（`rate:land`）、兆豐（`rate:mega`）排程移到 Go。
- 修好已經失效的玉山（`esun`）、國泰（`cathay`），並新增永豐（`sinopac`）、第一（`first`）。
- 寫入原本的 `rates` 表（walolita DB）。`service_name` 沿用舊值，歷史資料不用搬。

## 口徑（沿用舊資料）

- `buy_rate` / `sell_rate` 一律存**現金（現鈔）匯率**的銀行買入／賣出。舊的三支 PHP 都是抓現金價，維持一致。
- 方向是 `base` = 外幣、`to` = `TWD`。這跟欄位註解寫的（`base` 預設 TWD）相反，以實際資料為準：PHP 是這樣寫入的，Go 的 `FetchRates` 也是用 `base IN currencies` 篩選。
- 來源回 `0`、空字串或 `-`（代表該行不提供這個幣別的現鈔）就**略過**，不寫 0。買價 ≥ 賣價視為來源異常，略過並 warn。
- 欄位是 `decimal(8,5)`，寫入前先 round 到小數 5 位。
- prod 已有 unique key `(service_name, record_date, base, to)`，所以不用 migration，upsert 直接用 `ON DUPLICATE KEY UPDATE`。

### 台銀（停用）

- prod 上的台銀資料早就沒在更新了。`rate.bot.com.tw` 跟 `www.bot.com.tw` 整個網域都套了 JS challenge（`Challenge Validation` 頁）。PHP（Guzzle）和純 Go HTTP 都過不去，換 UA 或換路徑也一樣。一般瀏覽器開則正常。
- 有試過 headless Chrome（`chrome_helper`）：challenge 會一直倒數 30 秒、重來，從頭到尾不放行。UA 是 `HeadlessChrome`，判斷是被認出 headless。
- 要過關只能把 headless 偽裝成一般瀏覽器（改 UA、stealth、fingerprint），這不在我們願意做的範圍，所以停用。
- 停用方式：註冊表裡 `BOT` 只留名稱、沒有 `Fetch`。`Run` 會跳過它，`-bank BOT` 會回 `disabled`。`/opendata/rates/banks` 仍然列出台銀，歷史資料照樣能查。
- 之後若台銀提供不經 challenge 的來源（例如 open data API），新增 `bot.go`，在註冊表補上 `Fetch` 即可。CSV 欄位是 `[0]` 幣別、`[2]` 現金買入、`[12]` 現金賣出（PHP 版的對應）。

### record_date

改用**來源自己的報價時間**（土銀 `QuoDate`、兆豐 `last_update`、玉山 `validFrom`、國泰「資料時間」、永豐 `TitleInfo`、第一「Effective Date of Data」），拿不到才用台灣當天。
舊 PHP 用 `date('Y-m-d')`，週末跑會把週五的牌告記成週六／週日。改成來源時間後，週末就算重跑也只會 upsert 週五那筆。
`record_date` 以字串 `YYYY-MM-DD` 寫入，避免 DSN 的 `loc` 設定把台灣午夜轉成前一天。

## 架構

```
model/entity/opendata/rates/record.go  // RateRecord：寫入 rates 表用
repository/rates/upsert.go             // UpsertRates：批次 INSERT … ON DUPLICATE KEY UPDATE buy_rate/sell_rate/updated_at
service/rates/
  fetcher.go   // Bank 註冊表（service_name → 中文名＋Fetch）、BankNames、Run(ctx, bank)
  http.go      // fetch：15s timeout、瀏覽器 UA、共 3 次嘗試間隔 3s、偵測 challenge 頁
  record.go    // recordBuilder（字串轉 float、略過規則、round）、parseDate、台灣時區
  land.go mega.go esun.go cathay.go sinopac.go first.go   // 一家一檔，fetchX + parseX
  parser_test.go + testdata/   // 2026-10-22 抓下來的實際回應當 fixture
cronjobs.go                 // "rates" group：rates-fetch
main.go                     // commandParams 新增 bank
controller/opendata/rate.go // Banks() 改讀 service.BankNames()，拿掉沒有資料的 Chinatrust
static_site/src/types/rates.ts、src/data/rates.ts // 加 sinopac（永）、first（一）
```

- `Run` 依 service_name 排序後依序跑，**單家失敗不影響其他家**。每家各自 log 成功筆數或錯誤，最後回傳 `errors.Join`。解析出 0 筆也算錯誤，通常代表官網改版。
- 排程：`rates-fetch`，`15 9 * * 1-5`（沿用 PHP 早上 9 點多的時段）。
- 手動執行：`go run . -cmd rates-fetch` 跑全部；`go run . -cmd rates-fetch -bank esun` 只跑單家。
- 新增銀行：多一個 `xxx.go`（`fetchXxx` + `parseXxx`）、在 `Banks` 加一行、補 testdata 和 `TestParsers` 一列、前端 `data/rates.ts` / `types/rates.ts` 加 key。

## MCP 查詢（`exchange_rates_query`）

- 掛在既有的 `/mcp`（`service/mcp/rates_tools.go`），查詢邏輯在 `service/rates/query.go`。
- 參數都可省略：
  - `bank`：enum，取自註冊表。
  - `currencies`：ISO 代碼，會自動轉大寫。
  - `begin_date` / `end_date`：`YYYY-MM-DD`。
- 日期預設是台灣今天往回共 7 天。區間上限 93 天，避免一次撈出整張表。
- 回傳 `{begin_date, end_date, banks, rates}`：`banks` 是 service_name → 中文名，`rates` 跟 `/opendata/rates` 的格式一樣。

## 常見失敗與應對

| 情境 | 偵測方式 | 應對 |
|---|---|---|
| 官網改版、selector 失效 | 解析出 0 筆 | 回 `parsed 0 rows`，不寫入；重抓頁面更新 testdata 後修 parser |
| 被 bot challenge／WAF 擋 | 回應含 `Challenge Validation` | 回 `blocked by bot challenge`，不重試、不偽裝 |
| 暫時性網路錯誤／5xx | HTTP error、status ≥ 500 | 重試 2 次（間隔 3s），還是失敗就放棄，等下一輪 |
| 4xx | status 400～499 | 直接放棄，不重試 |
| 部分幣別無現鈔 | 值為 0／空／`-` | 單筆略過，不算錯誤 |
| 數字異常（買 ≥ 賣、≤ 0） | recordBuilder | 單筆略過並 warn |
