# AV 同名女優區分（規格）

> 狀態：後端已實作，前端待 mockup 確認（2026-10-31）。mockup：`av-same-name-actress-mockup/index.html`。前置：[AV女優上稿審核_2026-10-30.md](AV女優上稿審核_2026-10-30.md)「已知限制：同名女優」。

## 目的

現在「女優名字＝同一位」：同名的兩位共用一個女優頁（`/av/actress/:name` 只顯示其中一位），出演影片也混在一起，上稿新增同名只能合併。
這次讓同名女優**各有自己的頁面**，並從現在起用 DMM 女優 ID 分開她們的**新**影片。

## 現況（查 prod ES，2026-10-30，唯讀）

- 影片來自 DMM，女優資料來自 xcity（加上手動上稿的 manual），兩邊沒有共同的 key，xcity 頁面也沒有 DMM 的連結或 ID。
- `dmmvideos`：53 萬筆，`actresses` 只存名字。DMM GraphQL 明細的 `actresses` 其實有 `id`，`service/dmm/video.go` 原本只取了 `name`。
- `dmmactresses`：xcity 16,431 筆、manual 9 筆，另有約 4.27 萬筆 2021 年舊文件（沒有 `domain`，`type=dmmactress`，`aid` 就是 DMM 女優 ID，有生日、三圍）。搜尋用 domain 過濾，所以這批舊文件不會出現在搜尋結果。
- DMM 本身也有同名：舊文件 42,229 個名字中有 264 個重複，同名但 ID 不同。
- **xcity 的 65 個同名（131 筆）**對到舊 DMM 文件的情況：0 筆 17 個、1 筆 34 個、2 筆以上 14 個。只靠名字對不出來；再比生日或三圍，可以對到 29 筆，其中 26 組名字可以完全分開。

## 方案

### 1. 用什麼 key 串影片與女優

- **影片**：存 DMM 女優 ID。`DmmVideoBody` 加 `actress_ids []string`，順序跟 `actresses` 一樣，存進 MySQL `dmm.info` 和 ES。舊影片不回補，但詳細頁的「同步資料」會順手補上。
- **女優**：用 xcity／manual 自己的 ID（`dmm_actresses` 的 `domain`＋`id`），不加新欄位，也不開放上稿填 DMM ID。
- **對照表**：新增 MySQL `dmm_actress_maps`，記錄 DMM 女優 ID 對到哪一位女優：

  | 欄位 | 說明 |
  |---|---|
  | `dmm_id` | PK，DMM 女優 ID（字串） |
  | `domain`, `aid` | 對到的女優（`xcity`／`manual`＋該 domain 的 id），加 index |
  | `created_at`, `updated_at` | |

  - 一個 DMM ID 只對到一位女優（PK 保證）。一位女優可以有多個 DMM ID（例如 DMM 端改名後換了 ID）。
  - 只需要涵蓋**有同名問題**的女優。沒有同名的女優不用建：DMM ID 對不到時，退回用名字查，結果本來就是對的。
  - 怎麼建：**待決定**，見下面「對照表怎麼建」。

### 對照表怎麼建（已定案）

- 手動建，不做管理介面，用 SQL 維護。
- 起手式：我寫一支一次性的比對腳本，用 2021 年舊 DMM 文件比對 xcity 的同名女優（生日相同，或兩邊都沒有生日時三圍相同），產出 `INSERT` 的 SQL 檔：[av_dmm_actress_maps_seed_2026-10-31.sql](av_dmm_actress_maps_seed_2026-10-31.sql)，共 28 筆（生日 21、三圍 7），每筆附上比對依據；一筆 DMM 被兩位搶到這種一對多的跳過。檢查過後在 prod 手動跑，其餘的再手動補。
- 腳本只讀 ES 和 DB，不寫任何東西。

### 2. 女優頁網址：三種參數，舊網址相容

- 網址維持 `/av/actress/:name`，可以帶三種參數其中一個：
  - `?xcity_id=123`、`?manual_id=45`：直接查出這位女優。
  - `?dmm_id=1075832`：先查對照表，對應到 `xcity_id` 或 `manual_id` 再查；對照表沒有就當成沒帶。
  - 同時帶多個時，順序是 `xcity_id` → `manual_id` → `dmm_id`。
- 沒有帶參數（舊網址、外部連結）或參數對不到：照名字查，顯示同名中排第一的那位，跟現在一樣。
- 站內連結：
  - 女優搜尋結果、上稿表單的同名提醒、審核頁 → 帶 `xcity_id`／`manual_id`。
  - 影片詳細頁的出演 chip：影片有 `actress_ids`（新影片）就連到 `/av/actress/:name?dmm_id=`，沒有（舊影片）維持現在連到女優搜尋頁。從 `dmm_id` 進來卻找不到任何女優資料時，`replace` 到女優搜尋頁 `?name=`，不要顯示 404。
- 同名有兩位以上時，資料卡上方顯示同名切換（照片縮圖＋出生年／罩杯），點了換成那位的 `xcity_id`／`manual_id` 網址。只有一位就不顯示。
- 參數對到的女優名字跟網址不一樣（核准改名）→ `replace` 成新名字的網址。
- 分頁要保留參數（現在 `setSearchParams({page})` 會把其他參數洗掉）。
- `/av/actress/:name/edit` 用同樣的規則。
- API：女優搜尋和影片搜尋都接受 `xcity_id`／`manual_id`／`dmm_id`，規則跟頁面一樣。

### 3. 女優頁出演影片怎麼查（含舊影片退回用名字）

service 找出這位女優（名字 N、對照表裡對到她的 DMM ID 集合 D），以及同名其他女優在對照表裡的 DMM ID（集合 S），再組查詢：

| 這位女優 | 條件 |
|---|---|
| D 不是空的 | `actress_ids` 在 D 裡 **或**（`actresses = N` 且影片沒有 `actress_ids`，也就是舊影片） |
| D 是空的 | `actresses = N` 且 `actress_ids` 不在 S 裡（S 是空的時候就跟現在一樣） |

- 結果：新影片照 ID 分開；舊影片因為沒有 ID 無法區分，會出現在同名的每一位頁面上，跟現在一樣，不會退步。
- 原本的 `actress`（名字）參數保留，給 MCP 和舊呼叫端用。

### 4. 上稿審核：同名開放「新增為另一位」

- 網址可以區分同名後，新增單遇到同名時，核准對話框除了「合併到 X」之外，再加一個「新增為另一位」，由管理者選，沒有預設值。
- API：`approve` 的 `merge_target` 可以是 `{domain}-{aid}` 或 `new`。
- 新增為另一位之後，如果要分開兩位的新影片，要手動在對照表加上她的 DMM ID。

### 5. DB／ES

- MySQL：新增 `dmm_actress_maps`（migration `20261031120000-create_dmm_actress_maps.sql`，MySQL 5.7 相容）。`dmm_actresses` 不改。部署順序：migration → seed SQL。
- ES：**不用 reindex**。`dmmvideos` 部署前先跑 `PUT dmmvideos/_mapping {"properties":{"actress_ids":{"type":"keyword"}}}`（忘記跑的話 dynamic mapping 也查得到，只是型別不一致）。`dmmactresses` 不改。
- 2021 年那批舊 DMM 女優文件不刪，給比對腳本當字典用。

### 6. MCP：不動

`service/mcp/` 不改程式。`av_video_search` 的回傳會自然多出 `actress_ids`，不另外處理。

## User stories

1. 讀者從搜尋結果點進「七瀬くるみ（1984 生）」，網址是 `?xcity_id=1201`，看到的是這一位的資料卡，上方可以切到另一位同名的。
2. 讀者用舊網址 `/av/actress/七瀬くるみ` 進來，看到的跟現在一樣，可以從同名切換換到另一位。
3. 讀者在新影片的詳細頁點出演 chip，進到 `?dmm_id=1075832`。對照表對到 `xcity_id=20877`，直接看到正確的那一位。
4. 管理者在對照表加上 `1075832 → xcity-20877` 後，這位的女優頁新影片只剩這個 ID 的作品，另一位同名的頁面也自動把這些影片排除掉。
5. 使用者新增一位跟既有女優同名、但其實是不同人的女優。管理者選「新增為另一位」，核准後兩位各有自己的頁面。

## 常見失敗情境

| 情境 | 處理 |
|---|---|
| `xcity_id`／`manual_id` 對到的女優不存在（被合併、打錯） | 忽略參數，照名字顯示，網址換成不帶參數 |
| `dmm_id` 不在對照表 | 照名字顯示；名字也查不到 → `replace` 到女優搜尋頁 |
| 參數對到的女優已改名 | `replace` 成新名字的網址 |
| 對照表指向已不存在的女優 | 當成對不到，照名字顯示 |
| DMM 明細的女優沒有 id | `actress_ids` 那一格存空字串，維持跟 `actresses` 同順序 |
| 舊影片（沒有 `actress_ids`） | 照名字比對，出現在同名每一位的頁面上（跟現在一樣） |
| 同名女優都不在對照表 | 頁面分開，但出演影片列表一樣（跟現在一樣） |
| 沒有先 PUT mapping | dynamic mapping 也查得到，事後補 PUT 會報型別衝突，就維持現狀 |
