# AV 女優主題頁（規格）

> 狀態：規格已定案（2026-10-31），尚未實作。mockup：`av-actress-topics-mockup/index.html`。前置：[AV同名女優區分_2026-10-30.md](AV同名女優區分_2026-10-30.md)（同名處理與 `actressVideoQuery`）。

## 目的

用「主題」整理女優，例如：牡羊座、90 年代出生、A 型、熟女類、新人。每個主題一頁，可以分享，可以換排序。
所有主題**每週算一次**，結果存成 JSON 放到 S3，前端直接透過 CloudFront 讀取，不經過後端 API。

## 現況（查 prod ES，2026-10-31，唯讀）

`dmmactresses` 裡 xcity＋manual 共 16,444 位：

| 欄位 | 有資料 | 備註 |
|---|---|---|
| 生日（年月日都有） | 5,848（36%） | `horoscope` 欄位**全部是空的**：xcity 沒有給，上稿也不收，星座只能從生日算 |
| 身高 | 8,874（54%） | |
| 罩杯 | 4,172（25%） | |
| 出身地 `born_city` | 約 4,350（26%） | 東京都 1,640、神奈川県 589 … |
| 血型 | 約 3,200（20%） | |

`dmmvideos` 約 59 萬部，`tags` 共 475 種：
- 前 20 名裡有一半不是「類型」：ハイビジョン、単体作品、独占配信、4時間以上作品、ベスト・総集編、デジモ、4K 這些是格式或販售分類，幾乎每位女優都有。
- 後 20 名全是雜訊：亂碼標籤（共 71 種、228 部，見最後的「另外發現」）和促銷標籤（`〇〇30％OFF` 共 53 種）。
- 出現 ≥ 1,000 部的標籤有 181 種。這群標籤的尾段是真正的冷門類型，例如：母乳、女医、秘書、スチュワーデス、女捜査官、日焼け。
- `デビュー作品` 共 10,639 部，每年 500～700 部。

其他限制：
- 女優文件裡沒有出演數和出演日期。
- 女優頁 `/av/actress/:name` 在找不到女優資料時會顯示 404。
- 前端放在 Firebase Hosting；公開 JSON 沿用台電統計的做法：S3 `PutObject`，加上 `Cache-Control`，前端用 `VITE_CDN_BASE` 讀取。

## 主題清單

網址是 `/av/actress/topics/:slug`，總覽頁是 `/av/actress/topics`。

| 類別 | slug 範例 | 條件 | 頁數 |
|---|---|---|---|
| 星座 | `horoscope-aries` … `horoscope-pisces` | 生日月日落在該星座區間（西洋星座，日本通用的日期） | 12 |
| 出生年代 | `born-1970s` … `born-2000s` | `birth_year` 落在該年代 | 4 |
| 血型 | `blood-a`、`blood-b`、`blood-o`、`blood-ab` | `blood` | 4 |
| 罩杯 | `cup-a` … | `cup`；人數少於 30 的罩杯不開 | 約 10 |
| 身高 | `height-150-under`、`height-170-over` 之類 | `height` 區間 | 4～5 |
| 出身地 | `pref-tokyo`、`pref-kanagawa` … | `born_city` 完全相符；47 個都道府県配羅馬字 slug，人數少於 30 的不開 | ≤47 |
| 新人 | `newcomer` | 第一部配信日在最近 12 個月內 | 1 |
| 近期活躍 | `active` | 最後一部配信日在最近 6 個月內 | 1 |
| 熱門類型 | `genre-<tag>` | 每週從標籤 facet 取，見下方「類型主題」 | 20 |
| 冷門類型 | `genre-<tag>` | 同上 | 20 |

- **年齡做「出生年代」，不做「現在幾歲」**：現在幾歲每年都會變，同一個網址的內容會漂移；早就沒拍片的人也會被算進高齡區間。
- **不做「引退」**：一年沒有新片不代表引退。只做正向的「近期活躍」。
- 出身地的 slug 用 `pref-`，跟出生年代的 `born-` 分開。

### 類型主題

每週用 `tags.keyword` 的 terms aggregation（facet）挑：
1. 先排除下面兩種標籤，其他類型標籤不另外過濾：
   - **格式／販售標籤**：寫成常數清單（ハイビジョン、単体作品、独占配信、4時間以上作品、ベスト・総集編、デジモ、4K、VR専用、特典画像付き、ファン感謝・訪問 …）。
   - **雜訊標籤**：促銷標籤（含 `OFF`、`％`、`%`）、亂碼。
2. **熱門類型**：剩下的標籤依部數取前 20 名。
3. **冷門類型**：剩下的標籤中，只看出現 ≥ 1,000 部、而且排行有 ≥ 20 位女優的，取部數最少的 20 個。
   - 直接取最後 20 名會全是只有一部的雜訊。
   - 只看部數不看人數的話，會出現 `処女`（1 位）、`お嬢様・令嬢`（9 位）這種撐不起一頁的主題。
4. 每個類型的女優排行：
   - 對「含該標籤、且不是 `ベスト・総集編`」的影片，用 `actresses.keyword` 聚合出演部數。
   - 取 ≥ 5 部的人，最多 1,000 位。`巨乳`、`中出し` 這類標籤有 4～5 千人，全放進去檔案太大。
   - 只列女優資料存在的名字，因為沒有資料的名字點進去是 404。
   - 舊影片只有名字，同名女優的部數會算在一起，**接受這個誤差**。點進去的女優頁本身就有同名切換。

slug 用 `genre-` 加標籤原文（例如 `genre-熟女`）。前端一律先讀 `index.json`，再用 slug 找對應的檔案，不直接用標籤組 S3 路徑，避免 `・`、空白等字元的編碼問題。

## 方案

### 1. 每週產生主題 JSON

新增排程 `av-actress-topics`，每週四 04:30 跑，排在週三 01:37 的 xcity 同步之後。手動可以用 `-cmd av-actress-topics` 執行。全部在記憶體裡算：

1. **載入所有女優**：從 `dmmactresses` scroll 出 xcity＋manual，約 1.6 萬筆。
2. **算每位女優的統計**：出演數、第一部配信日、最後一部配信日。
   - 一般女優：對 `dmmvideos` 做 composite aggregation，以 `actresses.keyword` 分組，取部數、`min(vod_date)`、`max(vod_date)`，再用名字對回女優。
   - **DMM 的名字會帶別名**，例如 `澤村レイコ（高坂保奈美、高坂ますみ）`，但 xcity 只存 `澤村レイコ`。全站 5 萬個名字裡有 2.2 萬個帶括號。比對前要先去掉全形括號的部分；同一位的多種寫法要合併計算，類型排行也一樣。
   - 同名女優（現在約 65 組、131 位）：改用 `actressVideoQuery(row)` 逐位查，結果跟女優頁的出演影片一致。
   - 出演數包含總集編，跟女優頁顯示的出演影片一致。
3. **屬性類主題**：在 Go 裡依條件篩女優。星座用月日區間判斷，人數門檻和 2/29 這類邊界都在這裡處理。
   - **星座排除 11/30 生日**：xcity 有 342 位女優的生日是 11/30，一般日期大約 40 位，而且年份分散，判斷是 xcity 只知道年份時填的預設值。不排除的話，射手座會變成其他星座的兩倍（877 位）。這些人仍然算進出生年代。
4. **類型主題**：facet 挑標籤 → 每個標籤做一次聚合。
5. **上傳 S3**：每個主題一個 JSON，加上 `index.json`。

不用改 ES mapping，不用加 DB 欄位，也不用改女優搜尋 API。統計只活在 JSON 裡，所以 xcity 同步整份覆寫女優文件也不影響。

### 2. S3 檔案格式

路徑：`opendata/av/actress-topics/`，`Cache-Control: public, max-age=3600`，`Content-Type: application/json; charset=utf-8`。

- `index.json`：
  ```json
  {
    "generated_at": "2026-11-05T04:31:00+08:00",
    "groups": [
      { "key": "horoscope", "label": "星座",
        "topics": [{ "slug": "horoscope-aries", "label": "牡羊座", "count": 498, "file": "horoscope-aries.json" }] }
    ]
  }
  ```
- 每個主題 `<file>`：
  ```json
  {
    "slug": "genre-熟女", "label": "熟女", "generated_at": "…",
    "actresses": [
      { "domain": "xcity", "aid": 123, "name": "…", "photo": "…",
        "video_count": 210, "first_vod_date": "2008/03/01", "last_vod_date": "2026/10/20",
        "genre_count": 88 }
    ]
  }
  ```
  - 只放卡片需要的欄位。`genre_count` 只有類型主題才有。
  - 最大的主題約 2 千人，gzip 後幾十 KB。
- 類型主題的檔名用標籤的雜湊，例如 `genre-1a2b3c4d.json`，對應關係寫在 `index.json` 裡。
- 某個類型下週掉出名單時，舊檔案留在 S3，但 `index.json` 不再列它，網址會顯示 404，接受。

**寫入保護**：本機也會跑全部排程，所以只有 production 會上傳 S3。非 production 改寫到本機 `tmp/actress-topics/`，方便檢查。

### 3. 前端

- `/av/actress/topics`：讀 `index.json`，依類別分區顯示主題 chip，附人數。
- `/av/actress/topics/:slug`：
  - 先讀 `index.json` 找到檔案，再讀主題 JSON。
  - **排序和分頁都在前端做**：
    - 出演數（預設）
    - 最近出演
    - 名字
    - 類型主題多一個「該類型出演數」，而且預設用它
  - 頁碼和排序存在網址（`?page=&sort=`）。
  - slug 不在 `index.json` 裡時顯示 ErrorPage 404。
- 女優卡片從 `pages/av/actress.tsx` 抽成共用元件。`actress.tsx` 現在 508 行，順便瘦身。
- 兩頁都放在 `AgeConfirmationGate` 裡面。
- 麵包屑：AV 女優搜尋 › 女優主題 › 牡羊座。
- 入口：
  - 女優搜尋頁加「女優主題」按鈕。
  - `navigation.ts` 的 AV 女優搜尋加子頁面。
  - 女優頁的星座、血型、出身地等欄位，改成可以點進對應主題的連結。連結只在 `index.json` 有這個主題時出現。
- CDN 讀取失敗時用 snackbar 顯示。
- 動前端之前先做 mockup：`av-actress-topics-mockup/index.html`。

### 不做

- MCP 工具。
- 後端主題 API、女優搜尋新增的條件與排序（v1 草稿裡有，v2 改成靜態 JSON 後就不需要了）。

## User stories

1. 讀者在女優頁看到「牡羊座」，點下去進到牡羊座主題，看到出演數最多的牡羊座女優。
2. 讀者打開「新人」，看到最近一年出道的女優，切成「最近出演」排序找最新的。
3. 讀者在總覽頁的冷門類型裡看到「女捜査官」，點進去看到這類作品出演最多的女優，總集編不會灌水。

## 常見失敗與處理

| 情境 | 處理 |
|---|---|
| 排程失敗 | 不覆蓋 S3，前端繼續讀上週的檔案；發 TG 告警。先全部產生在記憶體，全部成功才開始上傳；`index.json` 最後上傳。 |
| 上傳到一半失敗 | 主題檔已經更新、`index.json` 還是舊的，前端仍然能讀；下次重跑覆蓋。 |
| 資料延遲 | 上稿核准、照片更新，最慢要等到下週主題頁才會反映，接受。女優頁本身是即時的。 |
| 生日資料不完整 | 星座和年代主題只涵蓋約 36% 的女優，接受。不加說明文字。 |
| 類型主題每週變動 | 掉出名單的類型網址會 404，接受。 |
| CDN 快取 | 每週更新後最多延遲 1 小時（max-age=3600）。 |
| 本機誤跑 | 非 production 不上傳，只寫本機目錄。 |

## 另外發現（不在這次範圍）

**女優頁漏掉帶別名的影片**：女優頁用 `actresses.keyword` 完全相符查出演影片，所以 DMM 名字帶別名的影片都查不到。例如 `澤村レイコ` 的女優頁是 0 部，但 `澤村レイコ（高坂保奈美、高坂ますみ）` 有 2,227 部；`川上ゆう` 14 部，`川上ゆう（森野雫）` 805 部。這是既有的 bug，跟主題頁無關，要另外修。


`dmmvideos` 有 71 種**亂碼標籤**，出現在 228 部影片裡，例如 `è¶…ä¹³`，是 `超乳` 被錯誤解碼的結果。其中包含 2026/01/30 配信的 `bmyb238`，表示不只是早期的舊資料，Go 版同步可能也會寫出這種資料，要另外查。這次主題頁先用排除規則擋掉。
