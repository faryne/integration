# AV 影片修改與審核（規格草稿）

> 狀態：已實作（2026-11-04，branch `feat/av-video-submission`），本機用測試索引驗證過提交、autocomplete、核准、否決、各種提醒與 MCP。mockup：`av-video-submission-mockup/index.html`
>
> 部署：見下方「部署」，要先 PUT mapping 再跑兩支 migration（`20261104120000`、`20261104120100`）。
>
> 流程、權限、限流、審核規則都照 [AV 女優上稿審核](AV女優上稿審核_2026-10-30.md)，這份只寫**跟女優不一樣的地方**。

## 目的

DMM 的影片資料有缺漏或錯誤：出演漏掉、標籤／系列不對、下架片（約 11%）沒有官方番號所以沒有 MissAV 連結。
開放使用者送出影片的**修改**，管理者看 diff 後核准或否決，核准後才寫進搜尋，而且之後的 DMM 同步不會把它洗掉。

## 跟女優上稿的差異（一覽）

| 項目 | 女優 | 影片 |
|---|---|---|
| 提交類型 | 新增＋修改 | **只有修改**（見「不做」） |
| 同名合併 | 有 | 無 |
| 手動修正存在哪 | `dmm_actresses.overrides` 欄位 | **另開 `dmm_video_overrides` 表**（`dmm` 有 53 萬筆，ADD COLUMN 會重建整張表） |
| MySQL `info` | 存合併後的資料 | **維持 DMM 原始資料**（批次 upsert 時還沒有 id，不方便先合併；也保留「DMM 原值」可以對照） |
| 目前資料從哪讀 | MySQL `info` | **ES 文件**（logstash 時代的舊片，ES 才是完整資料） |
| 限流 | 每 IP 每小時 60 張 | **跟女優共用同一個額度**（AV 上稿合計 60 張） |

## 可修改欄位

| 欄位 | 形式 | 備註 |
|---|---|---|
| 標題 | 多行文字 | 必填 |
| 官方番號 `maker_no` | 文字 | 填了就會出現 MissAV 按鈕、網址也會換成官方番號；格式不檢查（DMM 本來就有 `HODV-00071` 這種） |
| 配信日、發售日 | 日期 | 存成 `YYYY/MM/DD`（跟 DMM 同步一致） |
| 片長 | 數字（分鐘） | |
| 出演、監督、系列、發售商、品牌、標籤 | autocomplete（多選 chip，見下節） | 出演的名字與 `actress_ids` 規則見下方「出演與女優頁的對應」 |
| 參考連結 | `[{title, url}]` | 新欄位；顯示在詳細頁「基本資料」最後一列「連結」。只收 http／https、URL 去重 |

### 出演與女優頁的對應

沿用[女優別名](AV女優別名_2026-10-31.md)、[同名女優區分](AV同名女優區分_2026-10-30.md)的規則，修改不另外發明新的對應方式：

- 填別名（例如 `森野雫`）：chip 連到 `/av/actress?name=森野雫`，打開的是川上ゆう的女優頁，影片算在「森野雫 名義」底下。
- 填 DMM 寫法 `本名（別名…）`：算在本名底下。
- 女優資料裡還沒登記的別名：當成另一位女優。要合在一起，另外送女優上稿單補別名。
- `actress_ids` 對齊：
  - 保留下來的名字沿用原本的 DMM ID，新加的名字給空字串。
  - **原本沒有 `actress_ids` 的舊片，修改後也不建立這個欄位**。女優頁對「在對照表裡的女優」靠「沒有 `actress_ids`」收舊片，一旦補上空陣列，影片就會從她的頁面消失。
- 已知限制：新加的名字如果是對照表裡的同名女優（目前 28 位），因為沒有 DMM ID，分不出是哪一位，影片可能出現在另一位同名女優的頁面。審核頁會標「同名女優，歸屬可能不正確」，管理者可以否決。
- 審核頁的出演 chip 都連到女優頁（規則同影片頁的出演 chip），點開就能確認對到哪一位。

### 陣列欄位的 autocomplete

- 選項來源：`dmmvideos` 對 `{欄位}.keyword` 做 terms aggregation（跟搜尋頁「篩選」同一套 `termsAgg`），`include` 用「包含輸入字」的 regex（輸入會先 escape），依作品數排序取 10 筆，每筆附「N 部」。
  - 出演也從影片統計拿，不查女優名冊：沒有 xcity 資料的女優也會出現在影片裡，這樣才補得到。
- API：`GET /opendata/av/video/suggest?field=actresses|directors|series|makers|labels|tags&q=`，不用登入。
  - `q` 1～30 字，超過就截斷；結果用 Redis 快取 1 小時（key `av:video-suggest:{field}:{q}`），前端 debounce 300ms。
  - 不另外限流：快取＋長度上限擋得住正常使用；之後真的被濫用再補 IP 限流。
- 可不可以填清單外的值：
  - **標籤：只能從現有選項選**。DMM 的類型是固定清單，自己打的新標籤只會變成雜訊。
  - 其他五個欄位：**可以填新值**（新女優、DMM 沒登錄的系列／監督）。
- 審核頁：提交裡的值如果在 `dmmvideos` 一部影片都沒有，就標「新值」，管理者可以順便抓錯字（例如全形／半形、少一個字）。
- MCP：`av_video_submit` 的回傳多一個 `new_values`（同樣的判斷），讓 agent 自己檢查有沒有打錯；不另外開 suggest 工具，agent 用 `av_video_search` 的 facets 就查得到。

**不開放**：內部番號 `no`（影片的身分）、封面與樣本圖（只能來自 DMM，避免外連任意圖片）、DMM 網址、orphan 狀態。

## 流程

1. 提交（網頁或 MCP）→ 從 ES 讀目前資料當 `base_snapshot` → 驗證、算 diff（沒變更直接拒收）→ 限流 → 建立 `pending` 單。
2. 審核頁看 diff：同女優（預設只顯示有變更的欄位、現值 ≠ 提交當下時顯示三欄警告）。陣列欄位逐個 chip 標新增／移除。
   - 官方番號改成**已經被別部影片用掉**的值時，額外提醒並連到那部（不擋核准，DMM 本來就有少數重複）。
3. 核准 → 交易內：讀目前 ES 文件 → 只套用提交者改過的欄位 → upsert `dmm_video_overrides`（跟既有覆寫合併）→ ES index（`refresh=wait_for`）→ 提交單改 `approved`。ES 失敗整筆回滾。
4. 否決、已否決改為核准、已核准不能否決：同女優。

## 權限與限流

- 同女優：送出不擋登入、有登入就記錄；審核要 `users.is_admin`。
- 限流：把 `acquireActressSubmit` 改名成 AV 共用的 `acquireAVSubmit`，Redis key 改 `av:submit:ip:{ip}`，女優與影片合計每 IP 每小時 60 張。
- 寫入保護：沿用 `videoWritesAllowed()`；本機用正式索引名時核准回 503，要測就設 `DMM_VIDEO_INDEX` 為測試索引。

## 常見失敗與處理

| 情況 | 處理 |
|---|---|
| 提交後 DMM 同步改了資料 | 審核頁「資料已變更」三欄警告；核准只套用提交者改過的欄位 |
| 核准時 ES 寫入失敗 | 整筆回滾、維持原狀態，snack 顯示錯誤讓管理者重試 |
| 目標影片在 ES 找不到（被刪或 id 變了） | 審核頁顯示「找不到這部影片」，只能否決 |
| 官方番號跟別部重複 | 審核頁提醒＋連結，管理者自己判斷 |
| 出演／系列打錯字（全形半形、少字） | autocomplete 先擋一層；漏網的在審核頁標「新值」 |
| suggest 查詢 ES 失敗 | 下拉選單顯示「讀取選項失敗」，仍可直接輸入（標籤除外） |
| 舊片（沒有 `actress_ids`）改了出演 | 不建立 `actress_ids`，對照表女優的頁面照常收得到 |
| 新加的出演是同名女優 | 審核頁標「同名女優，歸屬可能不正確」；已知限制 |
| 出演改了，DMM 之後補上正確的女優 ID | 覆寫優先，維持手動版本；要改回來得再送一張修改單 |
| 本機誤核准寫到正式索引 | `videoWritesAllowed()` 擋下回 503 |

## 已知 Bug 記錄

### autocomplete 按 Enter 加入的是打的字，不是反白的選項

- **現象**：出演欄打「胡桃」，下拉第一個「胡桃さくら」有反白，按 Enter 卻加入「胡桃」。
- **root cause**：MUI v7.3 的 `useAutocomplete` 在 `freeSolo` 時，Enter 只會選「使用者用方向鍵／滑鼠反白過」的選項（`highlightReasonRef !== null`），程式自動反白（`autoHighlight`）的不算，打的字優先。畫面上卻有反白，看起來像會選它。
- **解法**：可以自由輸入的欄位（出演、監督、系列、發售商、品牌）關掉 `autoHighlight`，畫面和行為一致：直接 Enter 加入打的字，要選建議就用方向鍵或點選。標籤欄不能自由輸入，維持自動反白，Enter 直接選第一個選項。
- **狀態**：已修正（2026-11-04，`components/av/video_term_autocomplete.tsx`）。
