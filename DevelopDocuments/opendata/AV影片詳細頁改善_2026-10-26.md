## 現況數據（2026-10-26）

- ES `dmmvideos` 共 532,411 筆，**缺 `maker_no` 的有 454,339 筆（85%）**。
- 抽樣舊資料用 DMM 內部番號（轉小寫）查明細：2014 年以後的都查得到官方番號；2008 年的回 `null`（已下架）。
- 舊資料的 `no` 是大寫（`H_491LOVE00068`），新資料是小寫（`mdvr00448`）；查 DMM 一律轉小寫。
- ES 每個文字欄位都有 `.keyword`，精確篩選用 `term` 即可，不用改 mapping。

## 規格

### 1～3、5、9：前端版面

- 封面：照原比例顯示（`objectFit: contain`、不固定比例）。桌機左欄維持 280～420px；手機最高 `60vh`、置中。
- 番號列：`MDVR-448`｜`配信日 2026/10/26`｜`發售日 2026/10/26`｜`132 分鐘`。兩個日期都顯示（多數作品不同，例如 `1SDNM-554` 配信 10/20、發售 11/19）；沒有值的不顯示。
- 標題字級：手機 1.25rem、桌機 1.75rem。
- 資訊表：沒資料的列不顯示；手機也改成左右排（標籤欄 64px）。
- 麵包屑：`SiteBreadcrumbs` 新增共用 hook `useBreadcrumbTail(label)`（`helpers/breadcrumbTail.ts`），頁面可以補上最後一層。內容是「番號 標題」，番號優先用 `maker_no`，沒有就用大寫的 `no`；太長以省略號截斷。這個 hook 之後 VTuber 藝人頁等動態頁面也可以用。

### 4：精確篩選

- 後端 `VideoQueryRequest` 新增 `maker`、`label`、`series`、`director`，各自對 `makers.keyword` 等欄位下 `term`。
- `tag` 從 `match` 改成 `term tags.keyword`（現在的 `match` 會被斷詞，結果不精確）。
- 詳細頁 chip：發售商 → `?maker=`、品牌 → `?label=`、系列 → `?series=`、監督 → `?director=`、標籤 → `?tag=`；出演維持導到女優頁。
- 搜尋頁讀這些參數，跟現在的「關鍵字」一樣顯示可移除的 chip（例：`系列：MOODYZ 8KVR ×`）。

### 6：同步資料按鈕

- 有 `maker_no` → 顯示 MissAV 按鈕（同現在）。
- 沒有 `maker_no` → 改成顯示「同步資料」按鈕。
- API：`POST /opendata/av/video/:no/sync`，`:no` 是 ES 的 `no`（DMM 內部番號）。
  1. 檢查限流：同一個 IP 每小時 10 次；同一個 `no` 成功或失敗後冷卻 24 小時（Redis）。超過限制回 429。
  2. 用小寫的 `no` 查 DMM 明細（沿用重試邏輯）。查到後沿用 `persistVideos` 寫入 MySQL 和 ES（id 不變、覆蓋舊文件），回傳更新後的影片。
  3. DMM 回 `null` → 回 404「DMM 已查無此作品」，同樣進入冷卻。
- 前端：按下後按鈕顯示「同步中…」，**直到資料確認查得到才換頁**（2026-10-26 調整）：
  - 後端單筆同步寫 ES 用 `refresh=wait_for`，回傳前再用官方番號查一次，查不到回 502（視為暫時性失敗、解除冷卻）。
  - 前端收到成功後再以官方番號 `fetchQuery` 一次，拿到資料（同時進快取）才 `navigate(..., { replace: true })`，等同 301：上一頁不會回到舊網址。
  - SPA 無法對使用者回真正的 HTTP 301；爬蟲端由 SNS meta 處理：用內部番號進入且已有官方番號時，canonical 與轉址都指向官方番號網址。
- orphan（2026-10-26 新增）：同步**確定失敗**（DMM 已查無、沒有配信日、沒有官方番號）時，MySQL `dmm.is_orphan=1`／`orphaned_at`，ES 文件加 `is_orphan: true`；API 回傳 `is_orphan`，前端不再顯示同步按鈕，之後的批次補資料程式也可以據此跳過。暫時性錯誤（逾時、DMM 故障）不標。每日同步重新抓到這部時 upsert 會清回 0、ES 文件整份覆寫也不再有 `is_orphan`。
- 寫入走 primary（依照 DB 讀寫分流原則）。

### 7：相關作品

- 「同系列作品」：`series=<第一個系列>`；「同女優作品」：`actress=<第一位女優>`。各取 12 筆，依配信日新到舊排序，排除目前這部，沒有結果時不出現。
- 版面（2026-10-26 調整）：「基本資料／同系列作品／○○ 的其他作品」做成同一組 tab（`video_detail_tabs.tsx`），預設基本資料；相關作品在 tab 內以格狀顯示。換到別部影片時 tab 重置回基本資料。圖片預覽維持在 tab 下方。
- 卡片：直式封面＋番號＋兩行標題，點擊進入該片詳細頁。共用元件 `VideoCoverCard`；查詢邏輯在 `useRelatedVideoGroups.ts`。
- 追溯不到的影片（沒有系列也沒有女優，或兩組都查無結果）改顯示「近期隨機推薦」：搜尋 API 新增 `shuffle=true`（`function_score`＋`random_score`），搭配 `start_date` 取最近 `RELATED_RANDOM_WINDOW_MS`（預設 30 天，在 `useRelatedVideoGroups.ts` 調整）內配信的作品。`ListByPaginationRequest` 已有別的 `random` 欄位，所以參數叫 `shuffle`。
- 已知 bug（已修）：沒有系列／女優的影片出現「同系列作品」「undefined 的其他作品」tab。原因是 `{ series: undefined }` 的查詢 key 跟列表頁「全部影片」相同，即使 `enabled: false` 也拿到那份快取；改成以參數是否有值決定分組。
- 列表頁封面同步改成直式比例（`data/avVideoCover.ts` 的 `AV_COVER_ASPECT_RATIO`），欄數改為手機 2／平板 3／桌機 4。

### 8：分享預覽 meta

- `service/sns/meta.go` 新增 `^/av/video/([^/]+)$`，用番號查 ES：
  - title：`MDVR-448 【VR】最強ガチ親友…`（片名太長就截斷）
  - description：`出演：石原希望、葵いぶき｜ムーディーズ｜配信日 2026/10/26`
  - og:image：該片封面（`thumb`）
- 查不到資料時，退回現在通用的「AV 影片搜尋」。

## User stories

- 看到一部舊片沒有 MissAV 連結 → 按「同步資料」→ 幾秒後按鈕變成 MissAV。
- 想看同系列的其他作品 → 點系列 chip，或直接往下看「同系列作品」。
- 在 Discord／X 分享連結 → 預覽顯示番號和片名，而不是通用的「AV 影片搜尋」。

## 常見失敗與處理

| 情況 | 處理 |
|---|---|
| DMM 已下架（明細回 `null`） | 404「DMM 已查無此作品」，該番號冷卻 24 小時，按鈕維持顯示但會提示 |
| DMM 又改 schema／暫時故障 | 回 502，Snackbar 顯示「暫時無法同步，請稍後再試」 |
| 有人狂按或用腳本打 API | IP 每小時 10 次＋單一番號冷卻，超過回 429 |
| 同步後 `maker_no` 格式奇特（`HODV-00071`、`PSSP-01`） | 原樣存入；MissAV 網址格式不在這次範圍 |
| 相關作品查詢失敗 | 整區不顯示，不影響主要內容 |

## 實作備註

- 精確篩選的參數名與顯示名稱集中在 `static_site/src/data/avVideoFilters.ts`；詳細頁 chip 的 keyPrefix 與參數同名。
- 同步成功後 ES 的 `no` 會從大寫變成小寫（DMM 原始格式），所以 `videoNoQuery` 同時比對原樣、小寫、大寫，舊連結仍然有效；前端則換到官方番號網址。
- DMM 暫時性失敗（502）會解除作品冷卻；查無作品（404）維持冷卻。
- 限流 key：`av:video-sync:ip:{ip}`、`av:video-sync:no:{小寫 no}`。本機請求沒有 `X-Real-IP`，IP 會是空字串，所以本機所有請求共用同一個額度；正式環境由 nginx 帶入，跟 VTuber 搜尋限流一樣。
- 部署需要跑 migration `20261026150000-alter_dmm_add_orphan.sql`（MySQL 5.7 ADD COLUMN 會重建約 53 萬筆的 `dmm` 表，期間可讀寫但會花一些時間）。
- 本機測試同步時要設 `DMM_VIDEO_INDEX` 為測試 index（本機 DB 的 id 與正式環境不同，不能寫進正式 `dmmvideos`）；因此本機同步後轉址到官方番號會查不到資料，屬預期。
- `service/sns` 的 `TestBuildMetaStaticRoute`、`TestBuildMetaStripsTrackingQuery` 在這次改動前就已失敗（canonical 的 query string 處理），與本功能無關，未處理。
- **寫入保護**（2026-10-26）：本機 `go run .` 也會啟動排程，且本機與正式環境共用 ES cluster。為避免本機（例如凌晨 03:50 的每日同步）用本機 DB 的 id 覆寫正式 `dmmvideos`，DMM 影片的 ES／DB 寫入（`persistVideos`、`markVideoOrphan`）只在 `APP_ENV=production`、或 `DMM_VIDEO_INDEX` 不是 `dmmvideos` 時允許；否則回 `ErrVideoWritesDisabled`（同步 API 回 502、排程該日失敗並發 TG 告警）。**正式環境務必設定 `APP_ENV=production`。**

## 2026-10-28 調整：相關作品 tab

- tab 依「這部片有沒有該欄位」決定，不先查詢：同系列 → **每位女優各一個**（最多 5 位，多人合輯避免塞爆）→ 同監督 → 同品牌；四者都沒有才出現「近期隨機推薦」。定義在 `components/av/relatedVideoTabs.ts`（純函式）。
- **切換到該 tab 才查詢**：`RelatedVideoPanel` 只在選中時掛載；查過的結果由 react-query 快取，切回來不重查。代價是 tab 先顯示、點開才知道有沒有結果，沒有時顯示「沒有其他作品」。
- 每組最多 **16** 筆：桌機 8 欄 × 2 排、平板 4 欄 × 4 排剛好排滿；手機改成可左右滑的 carousel（scroll-snap，一次露出兩張半）。
- 影片／女優搜尋表單包成 `<form>`，在任一輸入框按 Enter 就送出。
