VTuber 搜尋 Mockup藝人搜尋框（改查 DB）＋藝人頁影片搜尋（YouTube API）・假資料
看點
  1. 藝人選擇列的「搜尋藝人」輸入框保留，外觀不變，比對改成打後端查 DB（停 300ms 才送）：名稱、@handle、期別、頻道說明。命中在說明時，選項多一行說明片段並標出命中處（試試輸入 しょこら、生放送タグ）。頻道說明週更 job 已經同步進 vtuber_channels.description。
  2. 影片搜尋放在藝人頁的「所有影片」分頁，只搜這位藝人的頻道（YouTube search.list 指定 channelId，不存 DB）。按 Enter 或「搜尋」才查，可選「相關性／最新」；搜尋時藏起「全部／直播／影片／短片」，「清除搜尋」回到原本的列表。結果卡片跟原本的影片卡片同一種樣式，點了開影片 modal。
  3. 快取：藝人＋關鍵字＋排序＋第幾頁 Redis 快取 6 小時；讀到快取的頁不算次數，所以往回翻、重查同一組都不扣。
  4. 單一 IP 每小時上限：最多 3 組不同關鍵字，每組最多 20 頁，只有真的呼叫 YouTube 才算。「一組」＝同一位藝人＋同一個關鍵字（排序不同算同一組、頁數合計）；只看關鍵字的話，同一個字在 79 位藝人頁各查 20 頁就繞過了。超過時結果區顯示 <ErrorPage compact code={429} />（ErrorPage 要補 429 的預設文案）。上方「重置查詢次數」可以重來。
  5. YouTube 額度真的用完（search.list 回 403 quotaExceeded）：後端寫 Redis key vtuber:video-search:quota-exhausted，效期一天。藝人頁本來就會抓的頻道資料 API 多回 video_search_available，旗標在時搜尋框、排序、按鈕都停用，placeholder 改成「今日影片搜尋額度已用完」（上方「模擬：額度已用完」）。
  6. 旗標在、卻還是送出了（頁面開著時才用完、或直接打 API）：後端看到旗標直接回 503（不再呼叫 YouTube），結果區顯示 <ErrorPage compact code={503} /> 並停用搜尋框（上方「模擬：送出時才用完」）。跟 IP 超過上限的 429 分開，文案不同。
    附註：YouTube 配額在美西時間午夜（台北下午 3／4 點）重置，固定一天的效期可能比實際重置晚幾小時才恢復；之後想更準可以改成「到下一個美西午夜」。
  7. 已定（2026-10-25）：先不加全站每日上限、不同步官網藝人介紹（藝人搜尋只用 DB 既有的頻道資料）。
